- **Scan-on-proxy now gates Alpine packages from Alpine Remote and Virtual repositories** (#4113, part of #4097). With `scan_on_proxy` on, a proxied `.apk` goes through the shared inline scan-and-block gate instead of streaming unscanned: a vulnerable package is refused with 403 `scan_blocked`, a clean one is served with `X-AK-Scan: clean`, the verdict is reused for the same digest, and `fail_open`, `fail_closed` and `record_only` behave as for the other enforced formats. The package's own `.PKGINFO` must name exactly the requested `{pkgname}-{pkgver}.apk` for the requested architecture (or `noarch`); it is then graded as itself, and through its `origin`, on the release the requested branch names (`v3.19`, `edge`) through a synthetic installed system (an `etc/os-release` and a one-entry `lib/apk/db/installed`). A package whose `.PKGINFO` disagrees, appears twice or names a field twice, or that is requested through a branch naming no release (`latest-stable`), is withheld under `fail_closed` (423) without being scanned. A Remote that re-fetches a package because its cached copy is unreadable now goes through the gate too. On Remote and Virtual Alpine repositories, a branch, repository, architecture or file name containing `?`, `#`, `;`, `\`, a stray `%`, a space or a control character after decoding is now refused with 400. `GET /api/v1/formats` reports Alpine as `scan_on_proxy: "enforced"`, and the generic download route refuses a scanning Alpine Remote with 403 `scan_on_proxy_route_required`.
