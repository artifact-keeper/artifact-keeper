- **CI builds the backend's test binaries once per run instead of three times: `🧪 Backend Unit Tests` is now also the coverage run and the integration run.** The unit, coverage and integration jobs each compiled the `artifact-keeper-backend` crate from scratch on the self-hosted pool, which no cache can hold, and the 17.5k-test unit suite ran twice -- 37 of the ~65 pool-minutes a pull-request push cost went to the three leaf-crate compiles. The unit job now builds once with `cargo llvm-cov` instrumentation (keeping the coverage job's memory guards: debuginfo off, 4-way compile parallelism, the single SIGKILL retry), runs the unit suite once, writes `lcov.info` from that run, and then runs the pure integration targets and the PostgreSQL integration suites from the same build, the latter on pushes and on backend-touching pull requests as before (#3124). The integration suites are serialized by a `kind(test)` entry in `.config/nextest.toml`'s `db-serial` test group instead of `cargo test --test-threads=1`. The 50% floor, the 70% new-code gate and the duplication gate move to a `coverage-gates` job on a GitHub-hosted runner that reads the uploaded report, still under the `📊 Code Coverage` name and still advisory. The `test-backend-integration` job and its `🔗 Backend Integration Tests` check are gone; that check was never a required context. When a runner exports `AK_PERSISTENT_TARGET_DIR`, the unit job builds there, so the dependency graph survives between runs; without it the job uses the ephemeral checkout `target/` as before.
