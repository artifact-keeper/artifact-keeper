section: Fixed
issues: [#4555, #4180]

- **A virtual conda channel fetches its remote members compressed and capped, and merges hosted members first** (#4555, #4180). `build_virtual_repodata` asked each remote member for the plain `repodata.json` through the uncapped buffered proxy path, parsed the whole document into a JSON tree and re-serialised it on every request: for a conda-forge subdir that is a few hundred MiB of JSON per member per request, with no ceiling at all. Remote members are now fetched as `repodata.json.zst`, then `.bz2`, then `.json` (each only if the previous one is 404), through the same budgeted path and the same 128 MiB default ceiling as a single remote channel (`CONDA_VIRTUAL_MEMBER_MAX_BYTES`); the decoded document has its own ceiling, enforced while the streaming decoder runs (`CONDA_VIRTUAL_MEMBER_MAX_DECODED_BYTES`, default 1 GiB). Members are fetched one at a time so a request never holds one budget reservation while waiting for another, and records are merged as raw JSON on a blocking thread instead of as `Value` trees. The merge order is now hosted (local and staging) members first, then remote members, each in priority order, first writer wins per filename. `channeldata.json` for a virtual channel takes the same capped, hosted-first path.
