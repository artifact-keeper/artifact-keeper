- **MCP Remote ingest: a size-cap refusal is no longer reported as a full quota, a seed keeps the "approved" context on a store error, a failing backfill no longer starves later names, and a re-pushed Git LFS object no longer orphans its old blob** (#5675). A `413` from storage during an approval's ingest answered `507 QUOTA_EXCEEDED`; it now answers `400 PAYLOAD_TOO_LARGE`. A seed-job pin whose store failed showed the bare storage error; it now reads "approved, but not ingested yet (storage: ...); the next sync retries it", as a deferred ingest does. The sync's backfill of approved-but-not-ingested names retried every failing name on every sync in name order, so once failing names filled its batch of 50 later names were never reached (possible with `STORAGE_KEY_SCHEME=flat` on cloud storage); it now picks the least recently attempted first and retries a name that failed 5 times once a day. Re-pushing a Git LFS object whose soft-deleted row was stored under the legacy flat key dropped that row and left the old object unreferenced; the old key is now handed to the storage GC as a candidate, which deletes it once nothing references it.
