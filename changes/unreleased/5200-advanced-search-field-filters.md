- **`GET /api/v1/search/advanced` now applies `repository_key`, `path`, `version`, `min_size`, `max_size`, `created_after` and `created_before`** (#5200). The endpoint documented and parsed all seven, but built its query from `query`, `format`, `name` and the sort fields only, so `?repository_key=sa` (and `ak artifact search --repo`) still returned artifacts from every repository the caller could read, and the size and date filters narrowed nothing. Each now narrows both the items and `pagination.total`, including the `per_page=0` count-only form, on top of the caller's existing repository visibility: naming a repository the caller cannot read returns nothing. `repository_key` and `version` match exactly; `path` is a literal prefix of the stored path (a leading `/` is ignored); `min_size` and `max_size` are inclusive byte bounds; `created_after` and `created_before` are exclusive and take an RFC 3339 timestamp or a `YYYY-MM-DD` date (midnight UTC). An unparseable date is now a 400 instead of being ignored. The facet counts are unchanged: as before, they describe everything the caller can see rather than the filtered result.
