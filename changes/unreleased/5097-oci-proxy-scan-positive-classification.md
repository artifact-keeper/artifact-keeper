- **OCI scan-on-proxy withholds a manifest it cannot classify under `fail_closed` instead of serving it unscanned** (#5097). The inline scan gate on a Remote OCI repository skipped every manifest it did not recognise as a runnable image, including ones it could not parse or classify. Container clients decode manifests more leniently than the server (case-insensitive keys, last duplicate key wins), so such a manifest could still run on the client. The gate now classifies positively: only a pure index or a known non-image artifact (Helm chart, cosign signature, SBOM or attestation, WASM module) skips the scan. A manifest that does not parse, uses case-variant or duplicate field names, or pairs an unknown config media type with a rootfs layer is handled as an inconclusive scan: `423` under `fail_closed`, served with `X-AK-Scan: pending` under `fail_open` and record-only. This also applies to a Remote member served through a Virtual repository. The scanner applicability check likewise keeps such manifests scannable. An OCI artifact that pairs its own config media type with a tar layer (a Flux artifact, for example) is in that last group, so a `fail_closed` scanning Remote now withholds it; proxy such artifacts through a Remote without scan-on-proxy, or with `fail_open`.
