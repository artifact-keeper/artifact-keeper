- **Content imported by the Artifactory / Nexus migration tooling before origin tracking existed is now recorded as `migration`, not `hosted`** (#4153). The origin backfill (migration 228) derived every older row from its repository, so imported artifacts were frozen as hosted uploads by the immutability trigger. Migration 270 re-stamps a row as `{"kind":"migration","upstream_url":<source system URL>}` only when a completed, non-dry-run migration item for the same target repository (resolved through the job's `repo_mappings`) carries the row's SHA-256, the row already existed when the item completed, the path is one the importer writes for that item, and only one source system claims it; anything ambiguous stays `hosted`. The immutability trigger now admits exactly this rewrite (and an `upstream_url`-only rewrite, used by #4463) on a connection that sets the transaction-local `ak.origin_rewrite` GUC; it no longer has to be disabled, and no table lock is taken on `artifacts`. The re-stamp runs in 5000-row batches with a 5-second `lock_timeout` per batch and retries, and logs how many rows it planned, re-stamped and left ambiguous. The online-migration gate now also requires `lock_timeout` and `statement_timeout` in any new migration that backfills or adds a trigger to a large table.

  Operator note: the migration needs no action. To see what it changed, count `SELECT count(*) FROM artifacts WHERE origin->>'kind' = 'migration'` before and after the upgrade, or read the `migration 270` NOTICE lines in the backend log.
