- **MCP capability snapshots now lint resources, prompts and `instructions`, refuse hidden characters in names and URIs, and flag lookalike names** (#5388). A stored capability snapshot (`ci_reported`, `gateway_reported`, `remote_probe`, `sandbox_run`) was linted on its tools only, and `CapabilitySet::from_doc` applied no Unicode filtering, so resource URIs, names and descriptions, prompt names, descriptions and arguments, and server `instructions` were stored and shown with bidi overrides, zero-width characters or tool-poisoning phrases unflagged, and a tool named `rеad_file` (Cyrillic `е`) passed as `read_file`. The `hidden_text`, `injection_phrase` and `secret_literal` rules now cover every string of resources, prompts and `instructions` (also in a publisher-declared block and MCPB manifest prompts); a capability document whose tool or prompt name, resource URI or name, or prompt argument name carries a control, bidirectional, zero-width or tag character is refused with `400`, as the publish path already refused them; and a new `confusable_name` rule (`review`) flags tool, prompt and resource names that mix scripts with ASCII lookalikes or read as ASCII through UTS #39 confusables. The lint version is now `ak-mcp-lint/2`. There was no XSS: the web UI renders these strings as text.
