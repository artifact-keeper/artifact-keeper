- **A conda component discovered through more than one path now reports as ONE component and ONE finding per vulnerability, with every discovery path preserved as evidence** (#4044). Once a conda artifact carries both a conda and a PyPI identity (#4042) and its payload is cataloged (#4041), the same underlying component surfaced repeatedly: as the conda component itself, as the `.dist-info` inside its payload, and as the advisory finding reached through the alias — the same CVE counted two or three times, which destroys confidence in the number faster than a miss does. Dedup now happens at the component-identity layer (`component_dedup`, scoped strictly to conda artifacts at the scan persistence boundary), keyed on `(normalized name, version)` across ecosystems linked by the alias graph — same name+version via alias is the same component. The inventory merge (`merge_artifact_packages`) collapses the artifact's own rows into one: the survivor keeps the richest identity (the qualified conda purl), is renamed to the conda package the reader holds, and records EVERY discovery path in a sorted, deduplicated seen-via `source_target` — the paths are diagnostic information and are never silently dropped. Within one scan, artifact-self findings sharing a vulnerability identity merge (`merge_artifact_self_findings`), retaining maximum severity with the survivor's `source` and description carrying every path (`Also discovered via: …`). Across scans, a cataloging scanner's artifact-self finding is suppressed ONLY when the latest completed `dependency` scan of the same artifact already recorded a finding with the same `(vulnerability, component, version)` identity (`partition_covered_findings` against `latest_dependency_scan_finding_identities`), which keeps finding counts stable when a rescan catalogs MORE than the last one did; a finding the advisory path never recorded is always kept, so suppression cannot hide unique coverage, and a lookup failure fails open (a false duplicate stays). False merge is treated as strictly worse than false dup throughout: versionless rows never merge, unnormalizable names never merge, a same-named row at a different version stays (a vendored native library inside a DIFFERENT artifact is never touched, because the scope is the artifact's own identity), and cross-scan suppression only fires when the alias graph positively owns the component (`Mapped` or `NotPythonPackage`) — an `Unmapped` package is an unasked question (#4042) whose payload catalog is its only coverage. The #3442 pin-path `dedupe_findings` behavior is untouched (its tests, including the measured 21→7 lodash collapse, still pass). Vendored native components discovered by BOTH package analysis and the payload catalog, and the inline-proxy scan path, are documented in the module as deliberate follow-ups, not defects.
