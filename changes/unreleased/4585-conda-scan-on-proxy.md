- **Scan-on-proxy is enforced on conda remote and virtual channels** (closes #4585, part of #4097). A `conda` or `conda_native` Remote repository with `scan_on_proxy` on now runs `.conda` and `.tar.bz2` downloads through the same inline gate as npm, PyPI, Cargo, Maven, NuGet, OCI and VS Code: digest-keyed verdicts reused across pulls, `fail_open` (served with `X-AK-Scan: pending` and scanned in the background), `fail_closed` (scanned inline; inconclusive is `423`), `record_only` (served with `X-AK-Scan: recorded`), and the severity threshold. A blocked package answers `403 {"error": "scan_blocked", "file": ..., "reason": ...}`, so the client fails the download. A Virtual channel scans each Remote member under the stricter of the virtual's and the member's policy. The `/t/<token>/` URL forms are covered, and a `.sigs` attestation sidecar is refused when its package's stored verdict blocks. Repodata, channeldata and shards are not gated. `GET /api/v1/formats` now reports `conda` and `conda_native` as `scan_on_proxy: "enforced"`, so the web UI offers the toggle for them. The identity check pins the package's `name@version` from the file name when its `info/index.json` agrees; a package the scanner catalogs nothing for (some compiled libraries) is inconclusive, so a `fail_closed` channel withholds it.

  Behaviour change: on a conda repository that scans on proxy, the generic download route (`/api/v1/repositories/{key}/download/...`) now refuses proxied files with `403 scan_on_proxy_route_required` (#4442), and a package-route path segment containing `?`, `#`, `;`, `\`, a control character, a stray `%` or a space is a `400` on Remote and Virtual conda repositories.
