- **One switch pauses every scheduled job that contacts an upstream** (#5288). Set `UPSTREAM_JOBS_PAUSED=true`, or send `PATCH /api/v1/admin/settings/system` with `{"upstream_jobs_paused": true}` (no restart, audited as `SETTING_CHANGED`). While it is on, the curation upstream sync and its popularity lookups, the environment advisory re-evaluation (OSV), the npm replication-feed consumer, peer replication transfers and the Remote MCP registry sync skip each tick before any network work. The backend logs the paused jobs once at startup, and each job logs when it pauses or resumes. Turning the switch off resumes each job on its next tick from where it stopped. The env var pins the switch on, and an unreadable setting counts as paused. `GET /api/v1/admin/settings/system` and the npm feed status report the state. Local jobs (GC, lifecycle, retention, metrics) and request-time proxy fetches are unaffected. The default is off. `CURATION_POPULARITY_PYPI_URL` and `CURATION_POPULARITY_NPM_URL` point the popularity lookups at an internal mirror, or turn them `off` so each lookup answers unknown at once instead of waiting out a connect timeout. See `docs/operations/disconnected-operation.md`.
