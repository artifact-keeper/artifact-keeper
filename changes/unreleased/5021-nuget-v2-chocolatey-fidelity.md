- **A hosted NuGet V2 feed now renders the `NuGet.Server` property set and honours the OData query a client sends, so a Chocolatey meta package installs its dependencies and `choco search` returns matches instead of the whole repository** (#5021). `Dependencies` was never emitted — the EDMX declared seven properties and the push stored only identity — so every Chocolatey spec package (`7zip`, `git`, `vlc`, ...), which is nothing but a `<dependency>` list, installed nothing and reported success; and the hosted branch of `v2_odata` ignored `Search()`, `$filter`, `$orderby`, `$top` and `$skip`, answering `Search()` with the first 500 rows of the repository. The `.nuspec` is now parsed by `NugetHandler::parse_nuspec` (namespaces, `<group targetFramework>`), its dependency list and descriptive fields are stored in the artifact metadata document, and entries render `Dependencies` in the protocol's `id:range:framework` form, `IsLatestVersion`/`IsAbsoluteLatestVersion` per id, `IsPrerelease`, `Listed`, `NormalizedVersion`, `Created`/`Published`/`LastUpdated` and the download counters, against an EDMX that declares them all. `PackageHash` is now the SHA-512 the V2 protocol specifies (added to the shared staging digest pass, with base64 SHA-256 kept for artifacts that carry no nuspec), and an unrecognised OData predicate is logged and ignored rather than 400'd — the client's next request after a failed query is usually an install.
