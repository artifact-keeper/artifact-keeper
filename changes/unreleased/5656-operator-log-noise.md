---
section: Changed
issues: [#5656]
---
- **Uploads no longer log two quality-check lines or read the artifact back from storage, unscanned generic files are unrated instead of graded F, and a fresh install no longer logs about 50 Postgres notices** (#5656). Operator log and metrics cleanups:

  - **Quality check on upload.** Every upload logged `Quality check completed` and `Artifact health score recalculated` at INFO. Both are DEBUG now. The check also staged the whole artifact from storage (up to 10 GiB) on every upload, but only the Helm lint reads content. Other formats now skip that read, so a non-Helm upload costs one storage read fewer. An artifact over the quality input limit no longer logs `Auto quality check failed` either.
  - **Generic artifacts are not scored on metadata, and an artifact with nothing to score is unrated.** The metadata-completeness check looks for a description, license, author and documentation link, which a generic upload never carries, so every generic file scored 0-20 and was graded F. Generic artifacts no longer run that check, and a metadata score recorded for one before the upgrade is ignored when its health is recalculated. An artifact with no security, license, quality or metadata score is now **unrated**: `health_score` and `health_grade` are `null` in `GET /api/v1/quality/health/artifacts/{id}` and in gate evaluations, instead of a default of 100 / A (migration 420 makes the two columns nullable, catalog-only). An unscanned generic file is unrated; a scanned one is scored on its repository's security score. **Gate:** an unrated artifact fails a quality gate's or promotion rule's `min_health_score` (violation `actual: "unrated"`), as it did when it scored F, so a gate on a generic repository blocks exactly what it blocked before. API clients that read `health_score` / `health_grade` must accept `null`. Repository health averages rated artifacts only; a repository with none rated still shows 100.
  - **Fresh install.** The migrations' `DROP ... IF EXISTS` statements logged about 40 `... does not exist, skipping` notices, and the data repairs about 10 `0 row(s)` notices, all at INFO. On an empty database the migration session now sets `client_min_messages = warning`, so a fresh install logs none of them. Upgrades keep their notices, which report what a repair changed.
  - **`Background schedulers started`** was logged twice at startup. It is logged once.
  - **Storage GC** logged only `Running scheduled storage garbage collection` when a pass found nothing. Every live pass now logs `Storage GC complete` with the keys deleted, artifacts removed, bytes freed, error count and duration.
  - **`ak_build_info{version, git}`**, always `1`, is a new metric naming the running build, with `# HELP` text.
