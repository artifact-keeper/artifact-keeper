- **CI OIDC exchanges mint a token that lives the provider's configured TTL instead of dying with the CI platform's ID token** (#5054). `POST /api/v1/auth/ci/token` capped the minted access token at the presented assertion's own `exp` (#3820). GitHub Actions ID tokens live about five minutes, so every token exchanged from GitHub Actions stopped working after about five minutes, whatever TTL was configured, and longer build steps failed with 401. The assertion now only has to be valid when it is exchanged, as with AWS STS, GCP Workload Identity Federation, Azure, PyPI trusted publishing and Vault. The minted token lives the provider's new `token_ttl_secs` (default 900, between 60 and 3600, set with `POST`/`PUT /api/v1/admin/ci-oidc`; migration 307). An expired assertion is still refused, the mapping's repository ceiling and group binding still apply, a CI service account still cannot mint API tokens, and its session cannot be refreshed (the exchange returns no refresh token, and `/api/v1/auth/refresh` and the registry refresh grant now refuse CI accounts). `kubernetes` providers are unchanged: their pull-only credential still expires with the ServiceAccount token. Jobs that run longer than the TTL exchange a fresh ID token again; see `docs/ci-oidc.md`.
