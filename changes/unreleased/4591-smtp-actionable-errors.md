- **A failed SMTP test now tells the administrator what the server offered and what to change, and a mail server that never answers no longer hangs a send** (#4591). `POST /api/v1/admin/smtp/test` answered every delivery failure with a bare `500 Internal server error`, so the reason (`535 5.7.3 Authentication unsuccessful`, `STARTTLS is not supported on this server`, `No compatible authentication mechanism was found`) was only in the backend log, and it never said why. The endpoint now returns `502` with lettre's error, what the server advertised in EHLO before and after STARTTLS (from a separate probe that sends no credentials, so mechanisms lettre ignores, such as NTLM and GSSAPI, are listed), and a one-line hint. For example, a server offering only NTLM/GSSAPI in plaintext and LOGIN/PLAIN after STARTTLS (the Exchange default) gets "set SMTP_TLS_MODE=starttls"; a 535 gets a note about SMTP AUTH being disabled on the mailbox or connector and the `DOMAIN\user` / UPN username forms; a missing STARTTLS names the port and the `tls` and `starttls-opportunistic` alternatives; an untrusted certificate points to `SMTP_TLS_CA_CERT`. Mail sent by notifications carries the same hint in its log line, without the probe. Separately, lettre's tokio transport bounds only the TCP connect, so a plaintext client on an implicit-TLS port (or any server that accepts and stays silent) waited indefinitely, and the test endpoint gave up with `503 Server overloaded, please retry: request timed out`. Each delivery is now limited to 60 seconds and fails with "no SMTP reply within 60s" and a hint about matching `SMTP_TLS_MODE` to the port. An invalid recipient address on the test endpoint is now a `400` instead of a `500`.
