- **Every artifact now carries an immutable record of where its bytes came from, exposed on the API and usable as a policy predicate** (#4050). Origin was the security-relevant fact most easily lost in transit: a caching proxy re-serves content under its own identity, and a lower-trust source shadowing a higher-trust one (channel/repository priority misconfiguration) was invisible once the bytes landed. `artifacts` gains an `origin` JSONB column (migration 227) holding `{v, kind, repository_key, upstream_url?}` — `hosted` for uploads into a local repo, `proxy` for fetches through a remote repo naming the normalized upstream URL that supplied the bytes, `migration` for worker imports naming the source system (Artifactory/Nexus base URL) the bytes came from. A `BEFORE INSERT` trigger derives the value from the owning repository row, so all ~40 ingest paths (every format handler, the proxy cache, OCI manifest upserts) are covered with one enforcement point, including paths written after this change; the migration worker supplies its origin explicitly because only it knows the source system. Immutability is enforced at the database layer: a `BEFORE UPDATE` trigger rejects any change to a recorded origin — a proxy re-serve or re-migration may refresh size/checksum/storage columns via upsert but can never rewrite or clear origin (the sole NULL exception exists for the one-time backfill). Rows predating the column are backfilled in batches (migration 228) from the best available fact — the owning repository's type and current `upstream_url`, the same derivation the trigger applies — and a validated CHECK (migration 229) plus a concurrent expression index on `origin->>'upstream_url'` (migration 230) make "which artifacts did this upstream supply?" an indexed query. The artifact detail endpoints (`GET /api/v1/artifacts/{id}` and `GET /api/v1/repositories/{key}/artifacts/{path}`) now return the origin document. Scan policies gain a cross-format `origin` block in `scan_policies.predicates`, following the #4058 pattern but placed at the top level (origin is a fact every artifact carries, not a format's fact): `allowed_upstreams` / `denied_upstreams` over the normalized upstream URL, `allowed_repositories` / `denied_repositories` over the recording repository key, and `allowed_kinds` over the ingest kind. Allowlists fail closed when the facet is unknown — the predicate exists to prove origin, and an unknown origin proves nothing — and every violation records the fired predicate's stable token (`[origin.upstream]`, `[origin.repository]`, `[origin.kind]`). The fact load is one PK lookup and only runs when an applicable policy configures origin predicates. Surfacing origin in the web console is a follow-up in the artifact-keeper-web repository.
