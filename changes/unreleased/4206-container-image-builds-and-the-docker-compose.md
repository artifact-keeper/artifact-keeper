- **Container image builds and the docker-compose E2E suites run on the self-hosted `rocky` pools instead of GitHub-hosted runners.** (#4206) The amd64 legs of the three `Docker Publish` image builds and CI's `🐳 Build Backend Image` / `🐳 Build OpenSCAP Image` now run on `ak-docker-runners`; `🔥 Smoke E2E Tests`, the `E2E Tests` native-client / stress / failure suites, the nightly E2E, the cache-correctness suite, the single-flight race and the weekly container scan run on `ak-e2e-runners`. Both are scale sets separate from `ak-ci-runners`, so none of these jobs takes a slot from the four Rust jobs. The arm64 legs stay on GitHub-hosted arm runners, and the release, signing, manifest, scan and small gate jobs stay GitHub-hosted. The "free disk space" steps that existed only for the hosted runner's ~14 GB root disk are removed: on the pools the build runs in the pod's DinD daemon, whose storage is a hostPath on the runner host. `docker/Dockerfile.backend` gains a `CARGO_BUILD_JOBS` build argument (default 8) in its two compiling stages, because cargo inside DinD sees all of the host's CPUs rather than the pod's share; the workflows pass 8 on the pools and 4 on the hosted arm64 leg, and CI's image build can use the pool's per-slot local buildx cache (`AK_BUILDKIT_CACHE_DIR`) in front of the read-only registry cache. The published image's contents do not change.
