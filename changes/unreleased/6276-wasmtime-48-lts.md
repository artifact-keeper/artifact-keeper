section: Security
issues: [#6276]

- **The WASM plugin runtime moves from wasmtime 36 to the 48 LTS line (48.0.10)** (#6276). 48.0.9 and later fix RUSTSEC-2026-0567 and RUSTSEC-2026-0573, and `.cargo/audit.toml` no longer ignores any wasmtime advisory. The plugin sandbox is unchanged or stricter. Fuel metering, the per-plugin memory and table caps, the WASI context (stdio only) and the stack limits are as before. Wasmtime 48 turns on the GC, function-references, exceptions and component-model-async proposals by default, and the host turns all four off again, so a plugin can use exactly the proposals it could on 36. Bulk memory and table instructions (`memory.copy`, `memory.fill`, `table.copy` and the like) now cost fuel per byte or element instead of a flat 1. That is stricter, and in practice it is invisible at the default 100M fuel per second of timeout. It also lets plugins built with a current Rust toolchain load. A wasm32-wasip2 component from Rust 1.100 imports WASI 0.2.12 (`wasi:cli/exit@0.2.12` and the like), which wasmtime-wasi 36 does not provide, so on 1.12.x such a plugin installed but failed every call with "component imports instance ... but a matching implementation was not found in the linker", and every upload to its repository answered 500. Existing plugins load and run unchanged: the WIT interface did not change.
