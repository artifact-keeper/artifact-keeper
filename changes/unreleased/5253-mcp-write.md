- **MCP registries resolve packages through Remote repositories, keep deleted versions reserved, validate, edit and soft-delete versions, and host MCPB bundles** (#5253). A server whose npm, PyPI, NuGet or Cargo package was pulled through a Remote backing repository now publishes against the Remote's proxy cache (pinned by sha256 and gated by the cache entry's hold, stored scan verdict and age gate); a package not pulled yet is filled through the Remote's own proxy path by a background resolver while the version is held as `resolving` (`202`), then pinned, or failed on a definitive refusal. Every `name@version` a registry ever stored stays reserved after a delete and a trash purge (`409 mcp_version_exists`). `POST /validate` runs the publish checks without writing (no credential needed; package resolution only for callers who can read the backing repositories). Repository administrators can replace a version's document (`PUT`), and `DELETE` soft-deletes a version. MCPB bundles are uploaded beside a version, their manifest is recorded and their `mcpb sign` signature verified (`mcp_require_bundle_signature` refuses unsigned ones), and they resolve as `mcpb` packages served with ticketed download URLs. A by-digest delete of an OCI manifest a server version pins is refused, a Local OCI backing repository refuses images named on another host (`mcp_external_registry`), package names and versions match each backing format's equivalences (npm percent-encoding, NuGet `1.0` and `1.0.0`, Cargo `-` and `_`), and the age-gate `451` now carries `Cache-Control: no-store`.
