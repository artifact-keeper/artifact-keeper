- **A verified CEP-27 attestation on a hosted conda package now satisfies `min_attestation_state` and the promotion `require_signature` gate, and promotion responses report every gate rule** (#4556). The policy predicate read the attestation state only from `curation_packages`, which is written for packages curated from a remote, so a package published to a local or staging channel with a verified attestation stayed `absent` and `min_attestation_state: verified` could never pass for it; and `require_signature` (both the scan-policy gate and the per-pair promotion rule) only recognised the repository signing key's audit entries. The predicate now also reads the verdict stored on the artifact by the attestation upload (`artifact_metadata.attestation_verification`), folded with any curation record to the weaker of the two, and `require_signature` passes for an artifact whose stored verdict is `verified`. `POST /api/v1/promotion/repositories/{key}/artifacts/{id}/promote` adds `gate_results: [{"rule", "passed", "reason"}]` listing every rule the promotion was evaluated against, passed or failed, beside the existing `policy_violations`; failed per-pair promotion rules appear there too (bulk promotion items carry them for rule failures).
