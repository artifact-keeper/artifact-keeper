- **A Composer Remote can forward `search.json` to its upstream, opt-in per Remote** (#6332). With `composer_upstream_search: true` on a Composer Remote (repository create or update API), a search of that Remote, or of a Virtual it is a member of, also asks the upstream with the same term, type and page, and merges its hits after the hosted ones: one hit per name, the first source wins, each `url` re-pointed at the repository asked, totals summed and `next` set while any source has more. Upstream hits pass the Remote's and the Virtual's curation rules. Each upstream read is capped at 1 MiB under a metadata-budget permit, bounded by `AK_COMPOSER_UPSTREAM_SEARCH_TIMEOUT_SECS` (default 5 s), limited to four Remote members per Virtual search, and shared between identical searches for 60 seconds through a cache keyed by repository, upstream URL, upstream-credential fingerprint and search parameters. An upstream that is down or slow fails soft: the local hits are served with the Remote named in `X-AK-Partial-Members`; a Virtual that found nothing while a forwarded member was down answers `503`. New counter `ak_composer_upstream_search_fetches_total{outcome}`. Off by default, so no search term leaves the instance unless an administrator turns it on, and a search with it off is unchanged. See `docs/composer-upstream-search.md`.
