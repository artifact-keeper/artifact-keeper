- **An MCP Remote can be seeded with named server versions without a full catalog sync** (#5408). A Remote learned a name only from its sync, which pages the upstream registry in name order: the official registry is over 2,000 pages, so a name late in the alphabet took several passes (hours) to reach the catalog, and `POST .../mcp/catalog/pins` answered `404` for it until then. `POST /api/v1/repositories/{key}/mcp/seed` takes a list of up to 500 `{name, version}`, answers `202` with a `statusUrl`, and seeds them in the background. For each name it fetches the upstream's version list (`/v0.1/servers/{name}/versions`) through the sync's outbound path (SSRF guard, credentials, egress proxy, upstream gate, `UPSTREAM_FETCHED`). It records the name in the catalog as a sync page would (deny list, lookalike check, auto-approval), then pins and ingests the version as `catalog/pins` does. `GET .../mcp/seed/{jobId}` reports each item as `pinned`, `already_pinned`, `refused` (denied, blocked or review-flagged name, unlisted version) or `failed`. The request is refused with `409` while scheduled upstream jobs are paused or the Remote is cache-only. This is the air-gap workflow "seed exactly these servers"; see `docs/mcp-registry.md` and `docs/air-gapped.md`.
