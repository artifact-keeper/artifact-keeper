- **Remote and virtual conda channels fall back to an upstream plain `repodata.json` when the `.zst`/`.bz2` probes answer 401/403, evict an undecodable cached member document, and keep a proxied `repodata.json.sig` verifiable** (#4929). S3 buckets without list permission answer 403 for a missing key, so a channel that only publishes the plain index used to fail the compressed probe instead of serving it; 401/403 now mean "this encoding is absent" for the compressed candidates on both the single-remote and virtual-member paths, while a refusal on the plain document is still reported. The same rule applies to a remote's upstream CEP-16 shard index and to the documents its shards are synthesised from, so such a channel serves a shard index instead of a 502. A virtual member that reads an undecodable, empty or truncated cached `.zst` now evicts it and answers 502 so the next request refetches, matching the single-remote path. A remote channel that publishes `repodata.json.sig` serves upstream's plain `.json` for a plain request, because the signature covers those bytes rather than the decoded `.zst`/`.bz2`; unsigned channels such as conda-forge keep the compressed transcode.
