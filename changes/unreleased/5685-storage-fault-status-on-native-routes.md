- **The remaining native package routes answer a storage outage with `503` and full storage with `507` instead of `500`** ([#5685]). After the 1.12.0 storage-fault change, the native upload and download routes of Alpine, Chef, CocoaPods, Composer, Conda, Debian, Git LFS, Go, Incus, JetBrains, NuGet, Protobuf, RPM, sbt, Swift, VS Code and the agent-plugin marketplace still answered an unreachable or full object store with a fixed `500`, so clients treated a retryable outage as a server bug and a full store did not show on `/health`. They now answer `503` with `Retry-After` when the store cannot be reached and `507` when it refuses a write for lack of space, with a fixed message in each route's own error format (Protobuf: Connect `unavailable` / `resource_exhausted`). An Incus upload whose background finalize failed on storage recorded the raw storage error, which named the storage key and could quote the object store's error document, in the `finalize_error` that `GET /incus/{repo}/uploads/{id}` returns; it now records a fixed message, as does the Debian metadata backfill for a stored package it cannot read. See `docs/operations/health-probes.md`.
