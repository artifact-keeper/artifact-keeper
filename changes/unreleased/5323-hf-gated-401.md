- **A gated model on a Hugging Face Remote without access now raises `GatedRepoError` instead of being retried as a server error** (#5323). When the Hub refused the Remote with `401`/`403` and `X-Error-Code: GatedRepo`, the client got a `502` (or a `400` when the Hub's `WWW-Authenticate: Bearer realm="Authentication required"` was mistaken for an OCI token challenge), so `huggingface_hub` retried five times with backoff. Resolve, model info and tree now answer with the Hub's status and an `X-Error-Code` `huggingface_hub` recognises: `GatedRepo` for a gated model, and `RepoNotFound` for a `401` on a missing or private model (`RepositoryNotFoundError`). `X-Error-Message` names the Remote and `PUT /api/v1/repositories/{key}/upstream-auth`. The Hub's message and the Remote's upstream token are never passed on, the refusal is not cached, and a Remote with an upstream credential that has access downloads as before. An Artifact Keeper user who cannot read the Remote still gets `404`. `docs/huggingface.md` describes the three cases.
