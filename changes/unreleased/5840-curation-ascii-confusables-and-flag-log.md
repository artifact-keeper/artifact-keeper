section: Changed
issues: [#5840]

- **New `popularity` rules flag, rather than refuse, an all-ASCII lookalike of a popular package on npm and PyPI Remote and Virtual downloads (`ascii_lookalikes`, default `"flag"`), existing rules keep blocking, and a flagged download is logged once an hour instead of on every pull** (#5840). With `block_typosquat: true` and `download_name_checks: true` (#5274), a rule refused every name whose UTS #39 confusable skeleton matched a popular one. Those skeletons also fold ASCII into ASCII (`1` and `I` become `l`, `0` becomes `o`, `rn` becomes `m`), so `c1ick` was refused as a lookalike of `click`. That is a one- or two-character lexical difference, the same class as an edit-distance match, which only flags on downloads because there is no review step and real packages have such names. The new rule setting `ascii_lookalikes` (`"block"` or `"flag"`, anything else is a `400`) decides what happens to such names; a rule without it flags them, with the reason "ASCII lookalike". A lookalike that holds any non-ASCII character (Cyrillic `о` in `lodash`, a fullwidth or Greek letter, a mixed-script name) is refused exactly as before, whatever the setting. The staging sync is unchanged. See `docs/security/curation-download-checks.md`.

  The flag line "curation flagged a proxy download; serving it" is now written at `warn` the first time a (repository, package, rule) is flagged in an hour, per process, and at `debug` after that, still with the rule and the reason. Before, a busy Remote logged it on every pull, twice per PyPI install and once per Virtual member checked. Every flag is counted in the new `ak_curation_proxy_flags_total{repository, rule_id}`.

  **Upgrade note:** migration 421 sets `"ascii_lookalikes": "block"` on every existing `popularity` rule with `block_typosquat: true`, so an upgraded install refuses exactly what it refused in 1.12. Only rules written after the upgrade default to `"flag"`; set `"ascii_lookalikes": "flag"` on an existing rule to adopt the new behaviour, or `"block"` on a new one to keep refusing (on PyPI, where names are ASCII-only, `"flag"` means the download path refuses no lookalike).
