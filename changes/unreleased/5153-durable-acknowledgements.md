- **An acknowledged finding stays acknowledged across rescans, dedup copies and promotions** (#5153). An acknowledgement was a flag on one finding row, so every path that wrote new rows brought the finding back, and the download gate also counted rows from every scan the artifact ever had. It is now a decision about an advisory, component and version on specific bytes in one repository, with a reason, an actor and an optional `expires_at`, applied by every reader. One decision covers every engine reporting the same component, so six CVEs reported by two scanners take six acknowledgements rather than twelve. A new CVE, the same CVE on another component or version, a new build under the same version, and a re-grade above the accepted severity all stay open.

  The download gate now grades the artifact's current scans (per scan type, the latest complete scan and anything after it), so a finding only an older scan reported no longer blocks; a later crashed or incomplete scan does not clear it. A promotion copies the source's verdict into the target repository when the target would grade exactly what the source grades, and its live decisions when the promoter could acknowledge in the target, so a promoted copy with a current, complete verdict is no longer treated as unscanned. Anything less copies no verdict, and a `promote:artifacts` token carries no decision. A clean verdict keeps dedup's 1-day limit, so one older than that does not travel; the promotion response and audit row say so. Promotion thresholds and `max_cve_severity` rules now count the findings open for the target, so a decision opens those gates only if it applies there or the promoter could acknowledge there and the promotion carries it. An approval now re-reads the policy and is refused where a promotion would be, unless the reviewer sets `skip_policy_check`. Deleting an artifact or repository whose scan had been copied no longer fails on the copy's `source_scan_id`, which is now cleared instead. A revoke reaches every copy a promotion made. The same bytes in another repository are not covered unless the request says `"scope": "all_repositories"`: this is narrower than copying decisions on every dedup, on purpose, so acknowledging in one repository cannot open the gate of another. When a finding's scan has copies in other repositories an acknowledge or revoke must name its repository, and a caller who can see only a copy of a scan now gets that copy instead of a 404. External scanner submissions never supersede each other. New: `expires_at`, `scope` and `repository_id` on `POST /api/v1/security/findings/{id}/acknowledge`, `GET /api/v1/security/acknowledgements`, `DELETE /api/v1/security/acknowledgements/{id}`, and the audit actions `FINDING_ACKNOWLEDGED`, `FINDING_ACKNOWLEDGEMENT_REVOKED`, `FINDING_ACKNOWLEDGEMENT_CARRIED`, `FINDING_ACKNOWLEDGEMENT_NOT_CARRIED` and `FINDING_ACKNOWLEDGEMENT_EXPIRED`.

  On upgrade, an acknowledged row becomes a decision only when every row of that finding in the artifact's current scans is acknowledged. A finding acknowledged only in an older scan, or by one engine while another engine's row is open, stays open and needs acknowledging again.
