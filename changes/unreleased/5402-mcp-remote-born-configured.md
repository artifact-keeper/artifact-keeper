- **A Remote can be created with its upstream mode and egress proxy, and an MCP Remote no longer starts its first sync before its settings are stored** (#5402). An MCP Remote is synced by the scheduler as soon as it is due, and a Remote never synced was due at once, so its first pages of the upstream registry could go out before a following `PUT .../egress-proxy` or `PUT .../upstream-mode` applied; the only safe order was to pause every scheduled upstream job instance-wide around the create. `POST /api/v1/repositories` now takes `upstream_mode` (`online` or `cache_only`) and `egress_proxy` (`mode`, `proxy_url`, `no_proxy`, the body of the `PUT` route) for Remote repositories, validates them before the repository exists (400 on any other repository type) and stores them before anything else; a `cache_only` creation is recorded in the creation audit row. MCP Remotes gain `mcp_remote_sync_paused` (create and `PATCH`), which keeps the scheduled sync off one Remote until it is cleared, and a Remote that was never synced is not due until it is one minute old, so a scheduler tick that lands during the create cannot start a pass without its create-time settings. A Remote created `cache_only` makes no upstream request at all; while scheduled upstream jobs are paused no Remote syncs on its own, as before. `docs/mcp-registry.md` and `docs/air-gapped.md` describe creating a Remote in its final state.
