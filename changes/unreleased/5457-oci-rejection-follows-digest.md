- **A quarantined or rejected OCI image can no longer be made pullable again by moving its tag** (#5457). Quarantine and rejection state is stored on a manifest's `artifacts` rows, and one image can have several of them: the row for each tag (`v2/<name>/manifests/<tag>`, rewritten in place when the tag moves) and a digest row (`v2/<name>/manifests/<digest>`, written by an MCP pin, a push by digest or a Remote pull). The native manifest gate checked a single row picked arbitrarily, and a tag push kept the old hold on the rewritten row. So after an administrator quarantined, or the scanner rejected, the tag's row, an ordinary writer could push another image to the same tag. The original bytes were then served again by digest through hosted and Virtual repositories, and any MCP server version pinned to them was served again too, while the new image wrongly inherited the hold.
  Every read of a manifest now makes the same decision: native pulls and HEADs (hosted, Remote and Virtual, by tag and by digest), the MCP backing gate (hosted and Virtual registries, detail and listings), the generic `/download` route and the tree content read. Each checks every live row of the digest in the repository, and any held row refuses it. When a push moves a tag that is still held (rejected, permanently quarantined, or under a timed hold that has not expired), the hold moves to the old digest's row. That row is created if it does not exist, revived if it was deleted, and keeps the stronger of its own hold and the moved one. A moved scan-policy hold becomes an administrator's hold, so acknowledging findings cannot release it. The rewritten tag row starts clean for the new image, which still gets its own upload hold.
  What operators should know: releasing acts on one row, so a held image stays refused until every held row of its digest is released. There is no single "release this digest everywhere" action yet. A rejected image whose tag moved away keeps a live digest row and is retained until an administrator deletes it. Layers and other blobs are still not gated, as before. See `docs/security/download-holds.md`.
