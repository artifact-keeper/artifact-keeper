- **A conda artifact's emitted and stored purl now names the build — channel, subdir and build string — instead of the whole name/version set** (#4041). `format_to_purl_type` mapped `"conda" => "conda"` and that was the entire conda identity strategy: a bare `pkg:conda/name@version` matches every build of that version on every subdir at once, even though the `linux-64` and `osx-arm64` builds are different binaries with different vendored libraries and different CVE surfaces, and grype/syft catalog the conda component with `purl: None` (#4039), so the artifact's own inventory row reached the SBOM with no identity at all. The qualified identity `CondaPurl` (introduced with #4042 for the advisory path) is now wired into the scan/SBOM pipeline: when a hosted scan of a conda artifact persists its package inventory, the scanner-reported row that names the artifact itself — matched on normalized name and exact version, never on scanner-supplied purl strings — is stamped from the artifact's own metadata (`conda_identity::artifact_purl_from_metadata`, which prefers the identity document written at ingest and falls back to the flat `name`/`version`/`build`/`subdir`/`noarch`/`package_format` keys for artifacts stored before that block existed), so `scan_packages.purl` carries `pkg:conda/name@version?build=…&channel=…&subdir=…&type=…`. The SBOM read path (`extract_dependencies_for_artifact`) restates the same identity onto purl-less rows from scans that predate the persisted value and the findings-only fallback, and both generators carry it: CycloneDX `components[].purl`, SPDX `packages[].externalRefs[referenceType=purl].referenceLocator` — the convention every other ecosystem already rides on. Two builds of one name/version on different subdirs therefore produce distinct purls, a `noarch` package produces exactly one identity (`subdir=noarch`) regardless of the subdir it was seen under — enforced by `CondaPurl::with_noarch`, the single place that invariant lives — and every qualifier value is percent-encoded, so an attacker-controlled build string carrying `?`, `&` or `@` cannot forge a qualifier. Non-conda formats, scanner-supplied purls, and rows naming anything but the artifact itself are byte-for-byte untouched; the bare `conda` type remains the documented last-resort mapping only when an artifact's own coordinates genuinely were never recorded.
