- **Guest (anonymous) access can be turned on or off at runtime by an administrator, without a restart** (#867). New admin endpoints `GET` / `PATCH /api/v1/admin/settings/system` (body `{"guest_access_enabled": false}`) store the setting in `system_settings` (`security.guest_access_enabled`). The replica that serves the `PATCH` enforces the new value on its next request and other replicas within 5 seconds (in-process cache). The guest-access guard, `/api/v1/system/config`, the public-repository refusal and the anonymous `/v2/token` mint all read the same runtime value. Every write is audited as `SETTING_CHANGED` with the old and new effective value and its source.
  **Precedence: `AK_GUEST_ACCESS_ENABLED` still wins when set explicitly** to `true`, `1`, `false` or `0`. It stays the offline break-glass, the same model as `TOTP_POLICY`. While it pins the value, the `GET` response reports `guest_access_source: "environment"` and `guest_access_editable: false`. A `PATCH` is still stored and reported as `guest_access_stored`, and takes over once the variable is unset. To move an instance that runs with `AK_GUEST_ACCESS_ENABLED=false` to UI management without reopening anonymous access, first `PATCH` `false`, then remove the variable. Unset, empty or other values do not pin, and behave as before (guests enabled) until an administrator stores a value. The web UI toggle is a follow-up in artifact-keeper-web.
