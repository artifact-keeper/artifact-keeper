- **LDAP group memberships and admin status are now re-synced against the directory on a schedule, and users removed from the directory can be deactivated automatically** (#3830). A federated LDAP user's standing used to be re-evaluated only when they logged in, so removing someone from an Active Directory group, or deleting them, left their API tokens and sessions working indefinitely, and the documented `LDAP_SYNC_INTERVAL` was never read. A background job now runs every `LDAP_SYNC_INTERVAL` seconds (default 3600, `0` disables, minimum 60) on one replica at a time. It re-reads each active LDAP user with the service account of the provider they last logged in through, re-syncs their LDAP group memberships, and recomputes admin from the provider's admin group exactly as login does, for users whose login provider is recorded. A user removed from the admin group loses admin and their tokens are revoked. Demotions are capped like deactivations, and a pass never leaves the instance without an active admin, counting deactivations too. Membership removals are capped the same way. Local accounts are never touched.
  **Upgrade note:** deactivation is opt-in. With `LDAP_SYNC_DEACTIVATE=true`, a user whose entry is gone, or no longer matches the provider's user filter, is deactivated and their API tokens, access tokens and refresh tokens are revoked; without it such users are only logged. An entry missing from its DN is not treated as gone if a username search finds the username elsewhere. Nothing is re-synced from that other entry, because it may be a different person who reused the username. A user who has not logged in since the upgrade is treated as gone only when every enabled provider covering their DN agrees. A directory error, timeout or referral never deactivates anyone, and a pass that would deactivate more than `LDAP_SYNC_MAX_DEACTIVATE` (default 25) users of a provider, or more than one user and more than `LDAP_SYNC_MAX_DEACTIVATE_PERCENT` (default 10) percent of them, deactivates nobody of that provider and logs an error. Package-manager clients still authenticate with a personal API token; LDAP username/password Basic auth on format endpoints is not implemented.
