section: Security
issues: [#4021, #3980]
---
- **The legacy V2 feed of a virtual NuGet repository now answers from every member, not just the hosted ones** (#4021). `v2_odata` resolved the virtual's member list and then discarded it (`let (repo_ids, _members)`), and `v2_download` had no remote-member arm at all, so a Chocolatey or `nuget.exe` client behind a virtual repository saw only what hosted members published — a remote member's packages were neither listed nor downloadable, whichever protocol that member speaks. The feed now merges each authorized remote member's entries in configured priority order, deduped case-insensitively by `(id, version)` with earlier members winning, so a hosted member's copy of a coordinate beats a remote member's — the same "local wins" rule the V3 registration merge applies (#3980) — and bounded at the 500 rows the hosted half already caps at. An unreachable member is logged and skipped rather than emptying the whole feed. Downloads go through the same member walk the V3 flat-container route uses, now shared by both routes, so the legacy route inherits its configured priority order, its caller-authorized member set (a member the caller cannot read directly stays invisible) and its rule that a member refusing a package it holds is terminal rather than a reason to fall through to the next member.
