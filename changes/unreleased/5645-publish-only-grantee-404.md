- **Repository routes answer a grantee who cannot read the repository like an unknown key** ([#5645]). A caller holding a grant on a private repository that does not include `read` (a publish-only `write` grant, or a `delete`-only one) passed the tenant write gate and then got the admin or action `403` from the check after it, where an unknown key answers `404 Repository not found`. These routes now return exactly what an unknown key returns, as the write gate itself has since [#5458]: `GET` and `PUT /api/v1/repositories/{key}/age-gate` (and the repository-scoped age-gate review queue), `PUT .../on-upstream-not-found`, `PUT .../upstream-mode`, `PUT .../stale-if-error-grace`, `PUT .../cache-ttl`, `PUT .../npm-scope-policy`, `POST .../cache/invalidate`, `POST .../cache/seed`, `PUT` and `DELETE .../pypi-tracks/{project}`, `POST` and `DELETE .../routing-rules`, the `.../email-subscriptions` routes, `PUT .../security`, `POST .../security/proxy-scans/rescan`, the `.../labels` writes, `PUT` and `DELETE .../artifacts/{path}`, the image build routes, and `POST .../rpm/repodata/rebuild`. A caller who can read the repository still gets the `403`.
