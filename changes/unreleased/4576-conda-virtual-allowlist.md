- **Package allowlist on virtual conda channels** (closes #4576). `GET`/`PUT`/`DELETE /api/v1/repositories/{key}/allowlist` on a virtual conda repository (repository admin; every change is audited as `REPOSITORY_ALLOWLIST_CHANGED`) restricts what the virtual's remote members contribute to a list of `{ "name", "version", "subdirs" }` entries: `name` is an exact package name or a `*`/`?` glob, `version` an optional conda version spec evaluated with conda ordering (`2.2.3`, `2.2.*`, `>=2,<3`, `1.0|1.1`; a version that does not parse is not admitted), `subdirs` an optional platform restriction. When `enabled`, a remote record the list does not admit is left out of the virtual's `repodata.json`, `.zst` and `.bz2` and its name out of `channeldata.json`, and a download of it through the virtual answers 404 without contacting the upstream, so a client reports the package as not found instead of resolving it and failing at download. Hosted (local and staging) members are not filtered. `enabled` is required; an enabled empty list admits nothing from remotes, and `enabled: false` restores the unfiltered merge. Merged documents report the number of records the list left out in an `X-AK-Allowlist-Dropped` header.
