issues: [#4155, #4048]

- **`CONDA_ATTESTATION_REQUIRE_VERIFIED` now actually gates CEP-27 conda attestations: the upload path cryptographically verifies Sigstore bundles and fails closed** (#4155, #4048). The flag was parsed fail-closed by default and printed in the startup configuration dump, but it was read at no decision point, and the live attestation endpoint still ran the pre-#4048 shape check — which required a top-level `_type` a Sigstore bundle does not carry, so it rejected every genuine CEP-27 bundle and accepted only the unsigned in-toto Statement, the exact inversion of the advertised posture. The endpoint now runs `verify_conda_bundle` — DSSE signature, Fulcio certificate chain, Rekor inclusion proof and Signed Entry Timestamp, OIDC issuer allowlist, then the CEP-27 statement policy on the signed payload — against a SHA-256 the server streams out of storage and computes itself, persists the verdict next to the stored attestation under the `attestation_verification` metadata key, and when the flag is on (the default) refuses any attestation that does not verify, storing nothing. Only an explicit operator opt-out (`CONDA_ATTESTATION_REQUIRE_VERIFIED=false`) accepts an unverified attestation, and then the failed verification record is stored with it so the gap stays auditable.
