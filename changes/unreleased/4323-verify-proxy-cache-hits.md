- **A proxy-cache hit is now checked against the SHA-256 its cache entry records as it streams, and a corrupted cached object is evicted and fetched again instead of being served** (#4323). Hosted and virtual-member serves have verified stored bytes since 1.12.0 (#4983, #4989), and the buffered proxy-cache read already treated a digest mismatch as a miss. The streaming hit path, which serves every cached package file of a Remote on its own route and through a virtual, still sent the cached object unchecked, so an object corrupted in storage (bit rot, a truncated rewrite, a bucket edit) went out whole under a `200` until its entry expired. The body is now hashed while it streams, in one chunk of memory and without reading ahead, so a `HEAD` reads nothing. A body that does not match is never delivered complete: its last chunk is withheld and the transfer is aborted. The entry is evicted, and the client's retry fetches the object again from upstream under every gate.

  Behaviour on a mismatch, by kind of object: a Remote's cached object is evicted and refetched, as above. A hosted object keeps the `502 STORED_OBJECT_INTEGRITY` it has answered since 1.12.0 (aborted mid-transfer above 4 MiB), and a virtual walk still treats it as final rather than serving another member's bytes; run the storage scrub (`POST /api/v1/admin/storage-scrub`) to find and repair the affected rows. Two new counters report both cases: `ak_stored_object_integrity_failures_total{phase}` counts every mismatch the serve-time verifier finds (`before_headers` or `streaming`; the buffered proxy-cache read keeps reporting its own as `ak_proxy_cache_lookups_total{result="miss_checksum_mismatch"}`), and `ak_proxy_cache_integrity_evictions_total{repository}` counts the evicted cache entries. `DOWNLOAD_VERIFY_CHECKSUMS=false` turns the check off, as for the other serve paths. An entry whose cache record holds no digest is served unverified, as before. Measured in the `s3-presign-and-scrub-1120` tier: 30 warm streamed hits of a 47 KB npm tarball took 982 ms before and 1,019 ms after (about 1.2 ms per hit for the hash); with one byte of a cached tarball flipped in MinIO, the download used to return all 47,577 corrupted bytes under a `200` on every retry, and now stops after 17,993 bytes while the retry serves the upstream bytes.
