- **CI skips the four Rust jobs when nothing they read changed, and on a push whose tree a merged pull request already proved green.** (#4207) A pull request that touches only CI-only files (`.github/release-notes/`, `scripts/release/`, `docs/`, and the `scripts/ci/*.sh` gates no Rust job executes) now runs Shell Tests and Security Audit but skips Check Rust, Backend Unit Tests, Code Coverage and Backend Integration Tests, about 65 pool-minutes per run. Other workflow files, `ci.yml`, the toolchain pin and every script a Rust job runs still run them: the backend's own tests read every file under `.github/workflows/`. On a push, `scripts/ci/resolve-verified-tree.sh` skips the Rust jobs when the pushed commit's tree is identical to the head of the merged pull request, that head contained the pushed commit's parent, and its CI Complete, Check Rust and Backend Unit Tests all passed; integration is skipped only if it also passed there. Pushes that change `Cargo.toml`, `Cargo.lock` or the toolchain still run, so `main` keeps saving the Rust cache, and any lookup error runs the jobs. CI Complete accepts those skips the way it already accepts the version-bump-only skip. `test-ci-change-classification.sh` and `test-resolve-verified-tree.sh` pin both decisions in Shell Tests. CI-only; nothing shipped changes.
