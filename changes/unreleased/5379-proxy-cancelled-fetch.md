section: Fixed
issues: [#5379, #5220]
---
- **A buffered proxy fetch that its client gives up on now still fills the cache, and the cancelled request is logged** (#5379, #5220). A cold upstream fetch used to run inside the request of the client that started it: when that client timed out and disconnected (yarn after 60 seconds, for example) the fetch was cancelled, nothing was cached, and every retry started the same fetch from scratch. No line was logged for the abandoned request, so the only trace was `Fetching artifact from upstream`. The single-flight leader's fetch and cache write now run on their own task, a first step of the #4533 design: a client that disconnects no longer cancels them, and a retry joins the running fill or reads the cache it wrote. A fill with a caller-supplied identity check (#4829) stays in its request. At most `PROXY_UPSTREAM_MAX_DETACHED_FILLS` (default 16) fills run detached per replica; past that a fill runs in its request as before. A detached fill is abandoned 60 seconds after its fetch deadline, so a stalled cache write releases the single-flight slot and the cross-replica lock. A request that outwaits another request's fill now gets a 502, or the stale cached copy when there is one, instead of a 500. A request whose future is dropped before the handler answers now logs `Request cancelled` (WARN) with the `method`, `uri`, `correlation_id`, `user`, `ip` and `latency_ms` fields of `Request completed` (a panic unwinding through the middleware logs `Request panicked` at ERROR instead).
  The upstream timeouts are now settings: `PROXY_UPSTREAM_CONNECT_TIMEOUT_SECS` (default 10, was a fixed 60), `PROXY_UPSTREAM_READ_TIMEOUT_SECS` (default 60, unchanged: the longest wait for the response headers or the next body chunk) and `PROXY_UPSTREAM_FETCH_DEADLINE_SECS` (default 600), a new deadline on a whole buffered upstream fetch, so an upstream that trickles bytes cannot hold a fill for as long as it keeps the socket open. A buffered object that cannot be fetched within it (128 MiB at under about 220 KB/s) is no longer cached; raise it for slow upstreams. Streamed downloads are not bounded by the deadline. The upstream client, and each Remote's egress-proxy client, which until now had no timeouts at all, also send HTTP/2 keep-alive PINGs every 30 seconds, idle connections included, and close a connection that leaves a PING unanswered for 10 seconds. Idle pooled connections are closed after 90 seconds. A stalled multiplexed connection is therefore replaced, not reused for every new fetch.
