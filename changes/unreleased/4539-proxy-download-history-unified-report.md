- **Proxy download history now survives cache eviction, and the admin download report covers proxy serves** (#4539, #3844). Proxy download rows were deleted together with their cache entry (`proxy_download_statistics.proxy_cache_id` cascaded from `proxy_cache_artifacts`), so every lifecycle eviction or cache purge erased the download history of what it removed, and per-path counts restarted from zero after a re-cache. Rows are now also keyed on the Remote repository and path they were served from; evicting an entry only detaches its rows (`ON DELETE SET NULL`), deleting the repository still deletes them, and the per-path and per-repository proxy counts read the new key. Migrations 277-283 add and backfill the key online (batched, no table rewrite) and build its index, and an IP index for the by-IP listing, concurrently.

  The admin download listing (`GET /api/v1/admin/downloads`, `/downloads/by-ip/{ip}`, `/downloads/by-user/{user_id}`) now returns proxy pull-through serves alongside hosted downloads. Each row carries `source` (`hosted` or `proxy`), `repository_id` and `path`; `artifact_id` is `null` for a proxy serve, which has no artifact row. New `source` and `repository_id` query filters select between them. `GET /api/v1/admin/stats` `total_downloads` now includes proxy serves, with the new `proxy_download_count` as its breakdown, so an all-proxy deployment no longer reports zero downloads.

  **Upgrade note: deliberate API behaviour change.** Two admin responses change meaning for existing clients. (1) `/api/v1/admin/downloads` and its `by-ip` / `by-user` variants now include proxy serves by default, and `DownloadRecord.artifact_id` is nullable (`null` on a proxy row); a client generated from the 1.10 spec that types `artifact_id` as required will fail to read a page containing a proxy row. Pass `source=hosted` to get the previous hosted-only listing. (2) `/api/v1/admin/stats` `total_downloads` now counts hosted and proxy downloads; the previous hosted-only figure is `total_downloads - proxy_download_count`. The `/api/v1/analytics` snapshots are unchanged: their `total_downloads` stays hosted-only, with `proxy_download_count` reported separately. The web UI and SDK updates are tracked in artifact-keeper/artifact-keeper-web#960 and artifact-keeper/artifact-keeper-api#42.
