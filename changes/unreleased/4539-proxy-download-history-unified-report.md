- **Proxy download history now survives cache eviction, and the admin download report covers proxy serves** (#4539, #3844). Proxy download rows were deleted together with their cache entry (`proxy_download_statistics.proxy_cache_id` cascaded from `proxy_cache_artifacts`), so every lifecycle eviction or cache purge erased the download history of what it removed, and per-path counts restarted from zero after a re-cache. Rows are now also keyed on the Remote repository and path they were served from; evicting an entry only detaches its rows (`ON DELETE SET NULL`), deleting the repository still deletes them, and the per-path and per-repository proxy counts read the new key. Migrations 277-281 add and backfill the key online (batched, no table rewrite) and build its index concurrently.

  The admin download listing (`GET /api/v1/admin/downloads`, `/downloads/by-ip/{ip}`, `/downloads/by-user/{user_id}`) now returns proxy pull-through serves alongside hosted downloads. Each row carries `source` (`hosted` or `proxy`), `repository_id` and `path`; `artifact_id` is `null` for a proxy serve, which has no artifact row. New `source` and `repository_id` query filters select between them. `GET /api/v1/admin/stats` `total_downloads` now includes proxy serves, with the new `proxy_download_count` as its breakdown, so an all-proxy deployment no longer reports zero downloads.
