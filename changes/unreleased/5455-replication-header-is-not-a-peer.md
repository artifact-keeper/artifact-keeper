- **The `x-artifact-keeper-replication: true` header no longer gets peer-replication exemptions on the generic upload and delete routes unless it comes with an instance administrator's token** (#5455). The header is set by the client. A service account sending it was treated as a peer by the chunked upload session, the raw and multipart generic `PUT`/`POST` and the generic artifact `DELETE`. Such a caller could skip the storage quota, refresh a replicated row in place and soft-delete a released (immutable) artifact: an npm release's `DELETE` answered `200` instead of `409`. Any writer sending the header, not only a service account, could also attach its own artifact and package metadata to a chunked upload in place of the server-derived metadata, and delete other sessions' in-flight replication uploads for the same path. All of these paths, and the MCP refusal, now take the decision from one helper. The header counts only alongside an administrator's token with the `admin` (or `*`) scope, which is how a peer link is set up. A session's stored metadata is used only when the principal completing it passes the same check, so a session opened by a peer and completed by a narrower token commits server-derived metadata. Fan-out suppression still follows the bare header: a writer can only stop its own write from being pushed on to peers.

  **Upgrade note: a peer link whose `api_key` on the receiving instance is a service-account token, or an administrator token without the `admin` scope, now replicates as an ordinary writer.** Its mirrored deletes of released artifacts get `409`, and writes over a quota get `413`/`507`. The sending side fails those tasks without backing off the peer, so its other deliveries continue. The receiver logs `replication header from non-admin principal ignored` at most once a minute. Re-issue the key on the receiving side as an administrator's token, and restrict it to the replicated repositories (`repository_ids`). That key is an administrator's credential on every receiver, so anyone who can read the sending instance's database (`peer_instances.api_key`) holds administrator access on every instance it pushes to (`docs/air-gapped.md`).

  The generic `DELETE`, npm unpublish and the pacman delete now record their caller as the `ARTIFACT_DELETED` actor instead of a null actor. A server.json that a peer replicates through the generic routes now writes the `MCP_SERVER_PUBLISHED` audit row.
