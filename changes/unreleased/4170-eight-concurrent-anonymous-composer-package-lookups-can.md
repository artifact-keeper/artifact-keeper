- **Eight concurrent anonymous Composer package lookups can no longer deadlock the buffered-metadata proxy path for every format** (#4162). This is the Composer instance of the #4145 hazard: `resolve_v1_provider_metadata` — the v1 provider fallback a proxied Composer repository runs whenever the direct `p2/...` metadata fetch 404s — reserved 128 MiB (`LARGE_METADATA_MAX_BYTES`) of the process-wide buffered-metadata byte budget for the upstream's root `packages.json` and then, while still holding it, took a SECOND untimed reservation from the SAME budget for each `provider-includes` index and again for the final per-package document. The shipped default budget is 1 GiB — exactly eight worst-case buffers — so eight concurrent requests reserved all of it and then each waited for bytes only the others could release, until the 120 s global request timeout or a client disconnect dropped them. The fallback is anonymously reachable on any public remote Composer repository and needs no credentials or setup, and the stall is of the *shared* buffered-metadata path (RPM repodata, npm packuments, the PyPI simple index, Debian `dists`), not just Composer; a lowered `AK_PROXY_METADATA_BUDGET_BYTES` makes it cheaper still. The reservation is taken before the proxy cache lookup, so neither a cache hit nor a negative-cached 404 avoided it. Each fetch is now scoped so its permit is released before the next reservation is requested — a request holds at most one slice of the budget at a time and its peak reservation falls from 256 MiB to 128 MiB — while the discovery walk, the documents it fetches and everything Composer serves are unchanged. A source pin keeps every fetch in the fallback scoped that way.
