- **Soft-deleted artifacts can now be kept in a trash for a configurable number of days and restored by an admin** (#2072). Storage GC used to hard-delete a soft-deleted artifact on its next pass, so a developer who noticed an artifact had been removed (by hand or by a lifecycle policy) had no recourse short of a backup restore. A new `GC_TRASH_RETENTION_DAYS` setting holds soft-deleted artifacts back from GC for that many days; it defaults to `0`, which keeps the previous behaviour exactly, so an upgrade does not change how much storage GC reclaims. Migration 261 adds `artifacts.deleted_at`, stamped by a trigger whenever an artifact is soft-deleted and cleared when it comes back, so every delete path records it. Two admin endpoints expose the trash: `GET /api/v1/admin/trash` lists trashed artifacts (optionally for one repository) with the time each becomes eligible for GC, and `POST /api/v1/admin/trash/{id}/restore` restores one. Restore returns 409 for OCI manifests and blobs (their tags were already removed and their layers are reclaimed by blob GC, so re-push the image instead), when another live artifact holds the path, or when the stored object is already gone.
