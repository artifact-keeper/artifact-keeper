- **Maven: an empty repository no longer publishes a prefix file that blocks SNAPSHOT metadata, the native route honours `Range`, and an unreachable upstream answers `502`** ([#5668]). A hosted repository with no artifacts yet (and a virtual whose members publish no groupIds) served a header-only `.meta/prefixes.txt`, which Maven Resolver reads as "deny every path" and keeps for a day: `mvn deploy` then could not read the SNAPSHOT `maven-metadata.xml` it had just written ("the prefixes file appears stale") and the timestamped build number stayed at 1. That file (and its checksum) is now `404` with `Cache-Control: no-store` until the repository has a groupId, and the first publish makes the next request serve the real file. The native `/maven/{repo}/...` route now answers a `Range` request with `206` and the requested bytes (`416` past the end, `Accept-Ranges: bytes` on every serve), as the generic route does, so segmented downloads are no longer corrupted. An uncached request through a Remote whose upstream cannot be reached (DNS failure, refused or reset connection, timeout) now answers `502` instead of `500 STORAGE_ERROR`, on every format.
