section: Security
issues: [#4452, #4463]
---
- **The API no longer returns a Remote's upstream credentials when they are embedded in `upstream_url`** (#4452). A Remote created with `https://user:password@host/...` had the URL echoed back verbatim, password included, by the create response, `GET /api/v1/repositories`, `GET /api/v1/repositories/{key}` and the update response, so any caller with read access to repository metadata could read a live upstream secret. These responses now render the URL with the userinfo removed and report a new boolean `upstream_url_has_credentials` (additive field) so a client can still tell that credentials are configured. The same redaction now applies to the `POST /api/v1/repositories/{key}/test-upstream` response, to `origin.upstream_url` on the artifact detail responses (the origin record of a proxied artifact is derived from the repository's upstream URL), to origin-policy violation messages returned by promotion and approval and saved in their `policy_result`, to `upstream_url` / `index_upstream_url` values in audit-entry details, and to the proxy, PyPI, npm, OCI and curation-sync log lines and error messages that printed the raw upstream URL. Writes are unchanged: a URL with userinfo is still accepted on create, still stored as given, and the credentials are still sent upstream as HTTP Basic auth, so existing Remotes keep authenticating.

  **Upgrade note:** this release stops *returning* the credentials but does not remove the copies already stored. Besides `repositories.upstream_url`, they remain at rest (lowercased) in the `origin` record of every artifact already proxied through such a Remote (`artifacts.origin` and its migration-230 index), and in promotion / approval `policy_result` records saved before this release whose origin-policy violations quoted the URL. Cleaning those copies is tracked in #4463. If a Remote embeds credentials in its URL, rotate the secret at the upstream and put the new one in the dedicated upstream-auth fields (`upstream_auth_type` / `upstream_username` / `upstream_password` on create, or `PUT /api/v1/repositories/{key}/upstream-auth`), which are stored encrypted and never returned. Because `upstream_url` cannot be changed through the update API, removing the old credentials from the URL itself means recreating the Remote with a credential-free URL.
