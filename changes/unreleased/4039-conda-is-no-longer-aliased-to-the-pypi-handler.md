section: Fixed
issues: [#4039]
---
- **Conda is no longer aliased to the PyPI handler, so a hosted conda artifact whose bytes do not back its registry coordinate is now graded `partial` instead of `complete`** (#4039). `RepositoryFormat::handler_key()` mapped `Poetry | Conda | Jupyter => "pypi"`, and the security subsystem believed it: the hosted-upload pin selector (`pinned_ecosystem`) resolves conda to `"pypi"`, whose PyPI-sdist gate (`.tar.gz`/`.zip`) never matches a conda package, so `format_expects_pin` was always false for conda and the #3604 `pin_downgraded` completeness escape hatch could never fire — a text file named `numpy-1.26.0-py311_0.tar.bz2` scanned "0 findings, complete". Conda now has its own handler key, routed to the conda-native handler in both dispatch tables (`get_core_handler` / `get_handler_for_format`) and listed in the compiled-in handler registry (which also gives conda its own enablement row in `format_handlers` — previously a `conda` repository was gated on the *pypi* row, so disabling PyPI silently disabled conda repository creation). A new `ComponentEcosystem::Conda` pins `.conda`/`.tar.bz2` artifacts under both `conda` and `conda_native`, cross-checked against the package's own `info/index.json` (read through the shared bounded-archive helpers for both containers) before it is trusted. The pin is deliberately **not materialized** into the scan workspace: measured on the bundled engines, grype 0.113.0 catalogs a `conda-meta/*.json` record but has no conda matcher or conda-keyed advisory data (a pinned `urllib3@1.25.9` matches zero vulnerabilities) and trivy 0.69.3 does not read the layout at all, so a written record would fill the catalog while grading nothing and suppress #4036's `not_cataloged` fail-closed signal. The two predicates therefore stack: an untrustworthy conda coordinate is `partial` (pin), a cataloged-nothing scan stays `not_cataloged` (#4036, which keeps precedence). The same wrong-alias class in the migration worker's filename parser (`artifact_metadata.rs` routed `conda` through the PyPI sdist grammar) is fixed with a conda arm using the native handler's `<name>-<version>-<build>` parser, so migrated conda artifacts get the coordinates a natively published one has. Poetry and Jupyter were audited and stay on the pypi key: both genuinely speak the PyPI protocol (PEP 503 simple index, sdist/wheel uploads), which `age_gate_spec` and the on-demand curation family already model independently of `handler_key()`.
