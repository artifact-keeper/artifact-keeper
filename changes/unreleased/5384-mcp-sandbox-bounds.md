- **MCP sandbox: the introspector now enforces the sandbox's time, memory, disk and failure bounds** (#5384, #5253). When a sandboxed run ends, whatever the outcome, `ak-mcp-introspector` stops the engine client (`SIGTERM`, then `SIGKILL`) and removes the container through the engine (`rm -f`): before, only the Podman/Docker client was killed and the guest kept running past the 120 s wall clock. Each attempt gets a fresh container name (a retry no longer fails with "name already in use"), guests carry an owner label and the worker removes its leftovers at startup, and Podman guests get `--timeout` (and `--http-proxy=false`). A stdio line is read only up to the 1 MiB budget, so one endless line no longer grows the worker by gigabytes. Guests run with `--log-driver=none`, so Docker no longer copies their output into an uncapped JSON log. An engine exit of 125-127 (runtime, network or image missing, pull failed, name in use) is reported `start_failed` with the engine's message, and `start_failed` is now retried, instead of being stored as the server's `needs_config`. The worker applies the backend's limits (256-byte names, 64 KiB `instructions`, 1 MiB body) and posts `refused` with the reason instead of a result the backend rejects, which used to hang until the claim lease expired. `AK_MCP_SANDBOX_RUNTIME=runc`, `crun` or any runtime that is not gVisor or Kata is refused without `AK_MCP_SANDBOX_ALLOW_DEFAULT_RUNTIME=true`. The default runner images are pinned by digest, an OCI package's image is removed after its run, and the worker warns about unpinned runner images. The engine client or launcher starts with a cleared environment (an allowlist plus `AK_MCP_SANDBOX_*` and `AK_MCP_SANDBOX_PASS_ENV`), so it never sees the worker's token. The Kubernetes launcher names each pod afresh, deletes it on `SIGTERM`, deletes pods an earlier attempt left behind, and with `AK_MCP_SANDBOX_AK_IP`/`AK_MCP_SANDBOX_AK_HOST` gives guests a `hostAliases` entry and no DNS server. See `docs/mcp-registry.md`, "The `ak-mcp-introspector` worker".
