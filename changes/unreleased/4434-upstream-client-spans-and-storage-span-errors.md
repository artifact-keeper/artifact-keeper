- **Proxy-service upstream registry requests now appear in traces as CLIENT spans that carry the trace onward, and failed storage operations mark their spans as errors** (#4434, #3954). Every upstream request the proxy service makes (artifact and metadata fetches including `fetch_upstream_direct`, conditional revalidations, and the OCI bearer-token exchange and its retry) runs in an `otel.kind = client` span named after the HTTP method, with `http.request.method`, `url.full` (credentials, query and fragment removed), `server.address`, `server.port`, `http.response.status_code` and, on failure, `error.type`. The span covers connect, TLS, redirects and the wait for response headers, so upstream latency is now attributable in a trace instead of being an untraced gap. The span's W3C `traceparent`/`tracestate` is injected into the outbound request, so an instrumented upstream continues the same trace. A 4xx or 5xx or a transport failure sets the span status to error. The exception is a `401` to a request sent without credentials, which is the bearer challenge an OCI registry sends before the token exchange. A `401` to a request that carried credentials means they were rejected, and is an error. Upstream requests made outside the proxy service (PyPI JSON metadata, the npm change feed, and the npm and goproxy handlers' own fetches) are not covered yet.

  Injection happens only when OpenTelemetry export is configured (`OTEL_EXPORTER_OTLP_ENDPOINT`). The trace context sent upstream continues whatever inbound trace the request joined. With `RATE_LIMIT_TRUSTED_PROXY_CIDRS` set, only a listed proxy's `traceparent` is adopted. With the list empty (the default), any client's `traceparent` and `tracestate` are adopted and therefore forwarded to third-party upstreams such as Docker Hub or PyPI. Set the trusted-proxy list if you do not want caller-chosen trace context relayed upstream.

  The filesystem, S3, GCS and Azure storage spans now record the error of a failed operation, which sets the span status to error. The error is recorded as an INFO-level event on the span, so a routine miss (a proxy-cache lookup of an absent key) is visible in the trace without becoming an ERROR log line. Because that text now reaches INFO logs and exported span status, the filesystem backend's directory-sync errors name the storage key instead of the absolute path, and S3 errors go through the S3 error classifier with request URLs (endpoint and bucket) replaced by `<url>`. Errors from presigned S3 requests no longer include the presigned URL.
