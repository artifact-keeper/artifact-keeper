- **A Remote repository's proxy cache can be seeded from a list of paths** (#5284). `POST /api/v1/repositories/{key}/cache/seed` with `{"kind": "paths", "content": [...]}` (a JSON array or newline-separated text, at most 10,000 paths) starts a background job and answers `202`; `GET /api/v1/repositories/{key}/cache/seed/{job_id}` returns its inventory, one row per path in request order: `cached`, `already_cached` (a fresh entry existed and the upstream was not contacted), `refused` (with the reason) or `failed` (with the status a client would have seen), with size and SHA-256 where known. Each path is fetched through the same proxy entry as a client download, so the upstream filter, origin policy, Package Age Policy, quota and proxy-cache cap, and the scan-on-proxy refusal of the generic route apply to a seed too. Concurrency (default 4, at most 16) and an optional `max_total_bytes` bound the job. Jobs are stored and resumed by any replica after a restart; each completed job writes one `CACHE_SEEDED` audit row. Requires `write:repositories` and repository `admin`. The typed manifests (`pypi-requirements`, `npm-lockfile`, `oci-images`, `hf-models`) and seeding a Virtual repository answer `400` for now. See `docs/cache-seed.md`.
