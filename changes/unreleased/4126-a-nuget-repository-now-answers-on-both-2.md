section: Security
issues: [#4122]

- **A NuGet repository now answers on both protocol surfaces whatever its upstream speaks, so a Chocolatey feed is reachable from `dotnet` and nuget.org is reachable from `choco`** (#4122). Each surface required the upstream to match it. Every V3 leg resolved through the service index and failed on anything that was not one, so a remote repository with a `/api/v2` upstream answered `502` on registration, flat container and search — and the same repository as a **member of a virtual** was skipped silently, because the member loops read the discovery error as "this member does not have it". In the other direction the V2 OData verbs were proxied verbatim to an upstream that serves no OData, so every `FindPackagesById()`, `Search()` and `Packages(...)` against a V3-backed remote repository 404'd. The protocol is now probed once per upstream (memoized through the proxy-cache entry discovery already uses) and translated both ways: a V2 feed answers the V3 version list and registration index from `FindPackagesById()` and the search page from `Search()`; a V3 feed answers the V2 verbs from the flat container and the search service. Downloads resolve through one protocol-aware target, so a V2 and a V3 client share a single cached body instead of storing it twice, and every synthesized URL points back at AK.

  **A transient upstream failure is never read as "this feed is V2".** Only a definitive signal downgrades the protocol — a 404 on the service index, a body that is not JSON, or one advertising neither `RegistrationsBaseUrl` nor `PackageBaseAddress`; a 5xx or a timeout propagates as an error, because guessing V2 during a brief outage would 404 every package on a working V3 feed. The V2 surface translates only on a positive V3 answer: when the probe errors — a Chocolatey-style server that answers `index.json` with 400, 401, 403 or 5xx — the V2 verbs and `package/{id}/{version}` downloads keep the verbatim pass-through and cache keys they have always used, so a V2 client on a V2 upstream never depends on the probe. A translated V2 entry carries no package size or hash, because the V3 documents do not publish them and the client reads the bytes through the `src` URL. Known limit: V2 feed paging (`<link rel="next">`) is not followed, so a version list or registration synthesized from a V2 upstream holds only the first page the feed returns and can be truncated for a package with many versions.
