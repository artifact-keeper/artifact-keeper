- **Admins can register "ghost" artifacts left in storage without a database row** (#1570). `POST /api/v1/admin/repositories/{key}/reindex-storage` (admin-only, body `{"dry_run": <bool>}` required, optional `limit`) lists the objects in a Maven or Gradle repository's own storage namespace. It covers the filesystem repository root and the repo-scoped `maven/{repository_id}/` prefix on S3 and GCS (#2624). For every artifact object with no row, it records a row with the object's real SHA-256 and size. It also reports live rows whose object is missing. The response is `{scanned, registered, skipped, skipped_recent, skipped_unknown_age, missing_objects, truncated, …}`. Objects modified in the last 5 minutes are left for their in-flight upload (`skipped_recent`), and so are objects whose listing reports no modification time (`skipped_unknown_age`). The S3 REST listing fallback used for endpoints such as Alibaba OSS now reads `<LastModified>`. Registered rows record SHA-256, SHA-1, and MD5, as a Maven upload does. It is safe on a live repository and idempotent. Paths that already have a row, live or soft-deleted, are never touched. Checksum sidecars and `maven-metadata.xml` are skipped. Legacy flat cloud keys, which every repository shares, are not attributed. Backends that cannot list objects (Azure) answer 422. Runs are audit-logged (`STORAGE_REINDEX_RUN`), including refused and failed ones.
