- **A remote repository's upstream credentials are now sent only to its configured upstream's origin, not to hosts named by index metadata** (#0000, GHSA-24rf-2gv2-j47c). Package index metadata can name download locations by absolute URL: a PyPI simple-index `href`, a Helm `index.yaml` `urls` entry, the Cargo `config.json` `dl` template, a Composer `dist.url`, a Terraform `download_url`. The shared upstream fetchers attached the remote's configured Basic or Bearer credentials to whatever URL they were given. An upstream index that is compromised, or that serves content an attacker controls, could therefore point a download at a host of its choosing and receive the credentials, over plain HTTP if it named an `http://` URL. Any client that could trigger the download could cause this, including an anonymous one on a public remote. The buffered, streaming, conditional-revalidation and ETag-probe fetchers and the JSON POST path now attach credentials only when the request URL has the same scheme, host and port as the remote's `upstream_url` or its `index_upstream_url` override. Any other URL is still fetched, but without credentials, and a sampled `security` warning is logged. OCI bearer-realm handling (GHSA-78h6-3wp8-2542, `oci_trusted_bearer_realms`) is unchanged. **A credentialed remote whose upstream serves files from a different host than its index, and needs the same credentials there, will now get 401/403 from that host.** For a Cargo registry with split index and download hosts, set `index_upstream_url` to the index and `upstream_url` to the download host, so that both are configured origins.
