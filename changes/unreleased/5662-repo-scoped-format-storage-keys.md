- **Go, Swift, Pub, Ansible, Chef, CocoaPods, CRAN, Puppet, Protobuf, Composer, JetBrains, Helm, Hugging Face, Bazel, Terraform, RubyGems, VS Code and Hex packages are stored under repository-scoped keys on cloud storage, so two repositories can hold the same package version** ([#5662]). On S3, GCS or Azure these formats wrote hosted packages to flat keys such as `chef/<name>/<version>/<file>` (Protobuf: `modules/<module>/commits/<digest>`), which every repository shares. Publishing a version that another repository of the same format already held therefore failed with `409 CONFLICT` "refusing cross-repository overwrite". New objects now go to `<prefix>/<repository-id>/...`. Objects stored before keep serving from the key their row records and no longer block other repositories from publishing that version. Nothing is migrated, and filesystem storage and `STORAGE_KEY_SCHEME=flat` keep the flat keys. A CocoaPods podspec that is read from storage is found next to the archive its row records, under either layout. Hugging Face file paths are now limited to 1999 characters (was 2036) so the scoped key fits the storage-key column.
