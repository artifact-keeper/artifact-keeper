section: Security
issues: [#5460]

- **A repository-restricted `mcp:introspect` worker token can no longer claim or complete another repository's introspection job** (#5460). The worker API checked only that the token carried the `mcp:introspect` scope, so a worker token restricted to private repository A could claim a private repository B job and store a capability snapshot for it with the returned claim token. A claim now hands out only jobs of repositories the token is scoped to (another repository's job is left untouched), and a completion re-checks the token's repository scope, and that the job belongs to the repository of the server version it introspects, inside the same transaction that locks and ends the claim, for results and retries alike. A completion by a token that does not cover the job's repository answers `403 mcp_forbidden` and stores no snapshot, changes no current view and leaves the job as it was. A change to a token's repository restriction is honoured at completion once the API-token validation cache (up to 5 minutes) has expired. Tokens without a repository restriction are unaffected.
