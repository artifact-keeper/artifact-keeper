- **Incus images and Debian packages uploaded through the chunked upload API now get the same metadata and index entries as the native upload routes** (#4403, #1846). `PUT /api/v1/uploads/{id}/complete` wrote a bare artifact row with no format processing, so an Incus image pushed that way was named after its file (its `images.json` download URL pointed at a product that does not exist) and had no arch/os/release, and a `.deb` was named after its file, versioned by its pool directory, and listed in `Packages` with "No description available" and no `Depends`. Completion now dispatches to the native finalize for incus/lxc repositories (`<product>/<version>/<file>` image paths) and Debian repositories (`pool/<component>/.../*.deb`): the row takes the product/package name and version, the `artifact_metadata` row (image `metadata.yaml`, or the control file) and the catalog row are written, and Debian maintainer scripts are analysed. A `.deb` whose control file disagrees with its file name is refused with 400 before anything is stored, as the native route refuses it. Other formats are unchanged, and the completion stays synchronous for Incus.
