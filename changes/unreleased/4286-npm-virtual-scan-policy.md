- **npm and Maven virtual repositories no longer serve hosted-member artifacts that the member's scan policy blocks** (#4286). The npm virtual tarball path (`npm_local_fetch`) discarded every error from the gated exact-path lookup, including the scan-policy 403 and the quarantine 409. It then served whatever its `{package}/%/{filename}` pattern lookup found after checking quarantine only. Hosted npm tarballs are stored at `{package}/{version}/{filename}`, which only the pattern lookup finds, so a tarball a `block_unscanned`, `block_on_fail` or `max_severity` policy refused on the direct hosted route was served through any virtual repository that listed that hosted repository as a member. Only a genuine miss (404) now falls through to the pattern lookup. The row it finds is served through the same gated helper, so quarantine and the scan policy both apply.

  The same review found three related Maven gaps, fixed here too. The virtual member closure discarded the gated lookup's refusal in the same way. It then fell through to the storage-direct fallback, which checked only quarantine on the requested primary's own row and applied the scan policy to the Gate-2 anchor. When a newer primary in the same GAV passed the policy, the blocked jar's bytes were served. That fallback now applies the full gate to the primary's own row. Finally, a `-SNAPSHOT` alias resolved to its timestamped artifact with no download gate at all, on the direct hosted route and through a virtual repository. It now passes the same quarantine and scan-policy gate as an exact-path hit.
