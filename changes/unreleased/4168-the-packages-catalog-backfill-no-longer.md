section: Fixed
issues: [#4168, #4169]
---
- **The Packages catalog backfill no longer advertises artifacts the registry refuses to serve, and can now reconstruct Maven and Gradle coordinates** (#4168, #4169). `POST /api/v1/admin/packages/backfill` walked every live artifact regardless of `quarantine_status`, so one run listed a `quarantined` or `rejected` artifact on the Packages page as an available package while every download of it stayed refused — and because nothing rewrites a catalog row when a verdict changes, it stayed listed. The walk now applies the same listability test the download paths use (`quarantine_status NOT IN ('quarantined', 'rejected')`, including the escape hatch for a timed quarantine whose `quarantine_until` has elapsed). Separately, `maven` and `gradle` were absent from `BACKFILL_FORMATS`, which made the endpoint a no-op for them: unlike the formats already listed, Maven's `artifacts.name` holds the bare `artifactId` and the `groupId` lives only in the path, so the default coordinate arm would have registered a group-less row beside the handler's `groupId:artifactId` (#2723) for every module — the duplicate-row shape #3978 fixed for NuGet. Both formats are now backfilled through `MavenHandler::parse_coordinates`, which yields the same `groupId:artifactId` at the same directory version (#3064) that the handler registers, collapses every asset of one release (jar, pom, classified jars) onto that single version, and rejects non-package paths such as `maven-metadata.xml` instead of inventing a row. `docker`/`oci`, `npm`, `pypi`, `nuget` and `generic` stay out of the walk, with the reasons recorded on the constant.
