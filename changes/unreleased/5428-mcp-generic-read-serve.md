- **MCP registries: the remaining generic read routes no longer reveal server versions a reader is not served** (#5428, #5253). A caller who does not hold an MCP registry (an administrator, or `read` through a grant) could still tell a held, refused, resolving, unresolvable or soft-deleted server version from a missing one on several generic routes. The security scan listings (`GET /api/v1/repositories/{key}/security/scans`, `GET /api/v1/security/scans`, `/security/artifacts/{id}/scans`, `/security/scans/{id}` and its findings) now leave out such a version's scans, and their `total` counts only the rest. `GET /api/v1/packages` decides its MCP rows before paging, so `total` and every page count only the rows the caller is shown, and a row that shows a newer servable version in place of a held one carries that version's size, downloads and times. `POST /api/v1/repositories/{key}/artifacts-missing` reports such a path as `not_found`. The by-id sub-resources (`/artifacts/{id}/labels`, `/artifacts/{id}/package-analysis`, `/quarantine/{id}`, `/quality/health/artifacts/{id}`, `/quality/checks`, `/sbom/by-artifact/{id}`, `/sbom/cve/history/by-artifact/{id}` and `/sbom?artifact_id=`) answer it as a missing artifact. `GET /api/v1/repositories/{key}/storage` and `storage_used_bytes` of `GET /api/v1/repositories/{key}` count only the versions the caller is served. A package version list whose lookup fails is now empty instead of complete. Holders keep full access.
