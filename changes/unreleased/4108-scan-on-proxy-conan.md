- **Scan-on-proxy now gates Conan recipe and package archives from Conan Remote and Virtual repositories** (#4108, part of #4097). With `scan_on_proxy` on, every proxied recipe or package file except `conanfile.py`, `conanmanifest.txt` and `conaninfo.txt` (the `conan_export.tgz`, `conan_sources.tgz` and `conan_package.tgz` archives, and any other file name, so an archive under another name is never streamed unscanned) goes through the shared inline scan-and-block gate instead of streaming unscanned: a vulnerable archive is refused with 403 `scan_blocked`, a clean one is served with `X-AK-Scan: clean`, the verdict is reused for the same digest, and `fail_open`, `fail_closed` and `record_only` behave as they do for the other enforced formats. A Conan archive carries no identity of its own, so it is graded as the requested reference's `name/version` (through a synthetic `conan.lock` pin, #4952) and on its contents (a bundled `conanfile.txt` or `conan.lock`, binaries the engine recognises); bytes that are not a readable gzipped tar are withheld under `fail_closed` (423) without being scanned. On Remote and Virtual Conan repositories, a recipe or package file path containing `?`, `#`, `;`, `\`, a stray `%`, a space or a control character after decoding is now refused with `400`. `conanfile.py`, `conanmanifest.txt`, `conaninfo.txt`, revision lists and search are unchanged, and `GET /api/v1/formats` now reports Conan as `scan_on_proxy: "enforced"`.
