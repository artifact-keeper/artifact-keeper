- **5-field cron schedules run on the weekday they name** (#5487). Backup schedules and lifecycle policies take standard 5-field cron, but the weekday field went to the `cron` crate unchanged, and it numbers weekdays 1-7 from Sunday where standard cron numbers them 0-7 with 0 and 7 both Sunday. So `0 3 * * 1` ran on Sunday instead of Monday, every numeric weekday ran one day early, and `0 3 * * 0` was refused as invalid. Numeric weekdays, ranges, lists and steps in a 5-field expression are now translated to day names before parsing; `N/step` runs from N through Sunday as in standard cron, and long day names (`monday`, `tues`, `thurs`) are read in the same field. Day names were already read correctly, and 6- and 7-field expressions keep the crate's own numbering. Upgrading: a schedule written with numeric weekdays moves to the day it names, one day later than it has been running.

  This affects backup schedules, lifecycle policies and lifecycle policy assignments, and a 5-field `GC_SCHEDULE` or `STORAGE_STATS_SCHEDULE`; `*/n` steps and day-name schedules run on the same days as before. If you compensated for the bug (for example wrote `2` to get Monday), change the schedule back to the standard number, or it will now run a day later than you intend. A backup schedule runs once more at its stored `next_run_at`, on the old day, and moves to the new day from then on.
