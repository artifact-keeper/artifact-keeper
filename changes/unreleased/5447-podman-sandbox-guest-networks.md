- **Rootless Podman sandbox guests can no longer connect to other guests** (#5447). The reference Podman deployment put every npm and PyPI guest on one shared internal network, `ak-mcp-sandbox`, and containers on one bridge reach each other, so an install script or MCP server in one guest could connect to a second, concurrent guest. The OCI runner now creates an internal network of its own for every npm or PyPI guest, attaches the AK forwarder to it under AK's host name (from the job's `akBaseUrl`, the backend's public base URL), gives the guest the forwarder's address on that network as a hosts entry (`--add-host`, so it does not depend on the engine's DNS, which a gVisor guest on an internal Docker network cannot reach), starts the guest on it and removes it after the run; leftovers are reaped at startup and every 10 minutes while idle. If the network cannot be created or the forwarder cannot join it, the guest is not started (`start_failed`, retried). OCI guests keep `--network=none`. The reference forwarder now runs with IP forwarding off.

  Upgrading: `AK_MCP_SANDBOX_NETWORK` is retired. A worker started with `--sandbox` while it is set (or with an empty `AK_MCP_SANDBOX_GATEWAY`) exits with an error before claiming anything, so skipping this step stops the worker rather than losing jobs. Unset it, set `AK_MCP_SANDBOX_GATEWAY` if the forwarder's container is not `ak-gateway`, recreate the forwarder from the updated `deploy/mcp-introspector/compose.sandbox-network.yaml` and remove the old `ak-mcp-sandbox` network. Give every worker on a shared host its own `AK_MCP_INTROSPECTOR_ID`. The backend's public base URL must use a host name for npm and PyPI sandbox jobs (an IP address is `start_failed`). `deploy/mcp-introspector/sandbox-check/guest-isolation-check.sh` checks a host's guest isolation, with a shared-network control that must fail, and the `mcp-sandbox` workflow runs it under gVisor.
