- **A virtual conda channel's package allowlist now applies to its hosted members too, so the channel no longer serves packages outside its list** (#5055). The allowlist (#4576) filtered only what remote members contributed: hosted (local and staging) members passed through unfiltered in the merged index and on downloads, so anyone who could publish to a hosted member could put a package on every channel containing it, list or not. The list is now the channel's boundary for every member, in every index form a virtual serves (`repodata.json` plain, `.zst` and `.bz2`, the CEP-16 shard index and its shards, `current_repodata.json`, `run_exports.json`, `channeldata.json`) and on package and attestation-sidecar downloads through the virtual, with the same matching rules as before (name glob, version spec, subdirs; filename and record identity must agree). A hosted package the list does not admit is dropped and still owns its name, so the upstream's packages of that name stay excluded. Reads of the hosted repository itself are unchanged. A new `scope` field on `PUT /api/v1/repositories/{key}/allowlist` restores the old behaviour per channel: `"scope": "remote_only"` (the default is `all_members`); a request that omits `scope` keeps the stored scope.

  **Upgrade impact:** on a channel with an enabled allowlist, hosted packages that are not on the list disappear from that channel (its index and downloads through it) until they are added to the list, or until the channel is set to `"scope": "remote_only"`. Check each virtual conda channel with an allowlist before upgrading. The hosted repositories themselves keep serving those packages directly.
