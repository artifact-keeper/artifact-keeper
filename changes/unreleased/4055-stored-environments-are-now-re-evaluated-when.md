- **Stored environments are now re-evaluated when advisory data changes: a newly published advisory against an already-installed component marks the affected environments — with no artifact, lockfile, or environment row changing — and the registry reports TRANSITIONS, not steady state** (#4055). An environment scanned clean in March is not clean in June, and #4054's stored component set is exactly what makes closing that gap cheap: a re-evaluation is a match against stored rows, never a rescan of bytes. The trigger hooks the advisory DELTA rather than a timer over everything: the `AdvisoryClient`'s answer cache is where new advisory data enters this system, and a refresh whose advisory-id set differs from the previously cached answer reports an `AdvisoryDelta` for the `(ecosystem, name)` to a persisted queue (`advisory_deltas`, one upserted row per package — persisted, not an in-memory channel, so a delta detected on a replica that does not hold the scheduler lease is still processed by the one that does); a cluster-leased scheduler tick (`environment_reeval`, reusing the existing `scheduler_service` + `cluster_work` singleton-lease machinery) drains it. Processing one delta costs one index scan over the new `idx_environment_packages_identity((ecosystem, name))` — the delta package's stored versions across every environment — plus one batched feed query of that size, so cost scales with the advisory delta and a package in NO environment touches no rows (fenced by an EXPLAIN test and a touches-no-rows test). Version-range matching is the feed's, not ours: each stored version is queried through the same OSV path a scan uses, so no third semver/range evaluator exists, and a withdrawal or a fixed-version shift past the stored version renders identically — the feed stops naming the advisory for that version. The feed's answer is diffed against the new `environment_advisory_state` table (row present == affected); only the diff is recorded, in `environment_advisory_transitions` (`new-affected` / `no-longer-affected`, denormalised with the advisory's summary/severity/fixed version so the event stands alone), and published on the existing `EventBus` as repo-scoped `environment.advisory_affected` / `environment.advisory_cleared` events — two types rather than one with a payload, because the DIRECTION is the fact a subscriber pages on. A degraded feed answer records NOTHING (absence of an answer is not absence of affectedness): the delta stays pending and is retried with a bounded attempt budget, and every state/transition insert is guarded against an environment being deleted mid-evaluation. Served at `GET /api/v1/environments/advisory-transitions?advisory=…&kind=…&since=…&until=…` (visibility rendered by the same `require_visible` predicate the reverse-index lookup uses) and `GET /api/v1/repositories/{key}/environments/{id}/advisories` for one environment's current state. Conda-keyed and unscoped (`*`) deltas are skipped by design: no feed serves the conda ecosystem (the scan path resolves conda through the PyPI alias graph before querying, #4042), and an unscoped vendored-library query has no ecosystem to key a reverse lookup on.
