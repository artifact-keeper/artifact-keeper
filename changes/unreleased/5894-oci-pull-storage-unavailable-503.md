- **An OCI pull of a stored blob or manifest answers `503` while object storage or the database cannot answer, not `404`** (#5894). With the storage backend unreachable, a blob `GET` and a manifest `GET` or `HEAD` for content the repository holds answered `404 BLOB_UNKNOWN` / `MANIFEST_UNKNOWN`, which docker and containerd read as "this image does not exist" and do not retry. A database error on the blob or manifest lookup itself (a dropped connection, a pool or statement timeout) did the same on blob `GET`/`HEAD`, and answered a `500` carrying the raw database error on manifest `GET`/`HEAD`; a virtual repository read a failed member lookup as "no member has it". All of these now answer `503 UNAVAILABLE` with `Retry-After` and a fixed message, like every other route since #5649 and #4765, on hosted repositories and through virtual ones, and a failed virtual walk is no longer negative-cached. A blob or manifest whose object is really missing still answers `404`, and a remote repository still refetches it from upstream.
