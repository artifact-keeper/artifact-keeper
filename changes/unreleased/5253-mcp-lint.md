- **MCP registries lint every server version and roll up its health** (#5253). Each publish and status change of an `mcp` repository is linted offline for secrets pasted into defaults, headers and URLs, credential-named inputs not marked `isSecret`, prompt-injection phrases and hidden characters in descriptions and declared tools, launcher arguments that re-route installs or escape the container (`--registry`, `--index-url`, `--privileged`, `-v /:/host`), suspicious remote URLs, OCI tag/digest and server-name label mismatches, MCPB bundles without a hash, and destructive or shell-like tool names. A `block` finding refuses the publish with `422 mcp_lint_blocked`; every other finding is stored as an ordinary scan finding (scan type `mcp_lint`) at a severity the scan policy reads (`review` = high, `warn` = low), so the findings UI, acknowledgements and the scan-policy gate apply unchanged. `mcp_require_oci_label: true` refuses an image whose stored config lacks a matching `io.modelcontextprotocol.server.name` label (`422 mcp_oci_label_mismatch`). `GET /api/v1/repositories/{key}/mcp/servers/{name}/versions/{version}/health` rolls the pinned packages' scan results, backing gates and lint verdict up to `ok`, `warning`, `critical` or `unknown`. See "Lint and health" in `docs/mcp-registry.md`.
