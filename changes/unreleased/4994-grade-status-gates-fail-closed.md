---
section: Changed
issues: [#4994, #4336]
---
- **New quality gates and promotion rules fail closed on a repository that is not fully assessed; existing ones keep the 1.11 behaviour until you opt in** (#4994, #4336). A gate's `min_security_score` or `min_health_score`, and a promotion rule's `min_health_score`, read a repository security score that stays 100 when the repository's scans failed or cataloged nothing, so they passed it. They can now also check the repository's `grade_status` through the new `accepted_grade_status` field on gates and rules: `rated` passes only a `rated` repository, `incomplete` also passes an `incomplete` one, and `any` is the score-only check. A gate or rule created on 1.12 defaults to `rated`. A gate reports the refusal as a `grade_status` violation (blocking or warning by the gate's `action`); a rule reports it in its violations. Neither checks an artifact that has no health score yet (#4156).

  **Upgrade.** Existing gates and rules are unchanged: migration 361 sets `accepted_grade_status: any` on every gate and rule that exists at upgrade, so they still decide on the score alone. To enforce on the grade status with one of them, set it to `rated` or `incomplete`. 1.11 reports no grade status, so check what that would refuse after the upgrade, once the repositories have been rescanned: `GET /api/v1/security/scores` gives each repository's `grade_status`, `GET /api/v1/repositories/{key}/security/coverage/artifacts` lists the artifacts that keep it from `rated`, and `POST /api/v1/quality/gates/evaluate/{artifact_id}` or `POST /api/v1/promotion-rules/{id}/evaluate` tries a gate or rule (set to `rated` first) without promoting anything. Fix the scans, or set the repository's `uncataloged_policy` to `warn` where the uncataloged artifacts are plain archives, before tightening a gate or rule that promotions depend on. A new gate with no `repository_id` covers every repository that has no enabled gate of its own. A repository whose format no scanner covers stays `unrated` for good, and `warn` does not change that, so keep `any` on the gates and rules that cover it, and set `any` on any new gate or rule that does. Downloads are not affected: gates and rules run only on promotion and on the evaluate endpoints. `accepted_grade_status` is set through the API only until the web UI supports it. During a rolling upgrade, a gate or rule a 1.11 replica creates gets `rated`, and a 1.11 replica decides promotions without the check. See docs/security/grade-status.md.
