- **Artifact label writes now need the repository `write` action; visibility alone no longer authorizes them** (#4193). `PUT /api/v1/artifacts/{id}/labels`, `POST /api/v1/artifacts/{id}/labels/{key}` and `DELETE /api/v1/artifacts/{id}/labels/{key}` checked the `write:artifacts` token scope, which every interactive session passes, and the artifact visibility gate, which answers read visibility only: it let every signed-in user through on a public repository and asked a member of a private one for `read`. Any signed-in user with no grant on a public repository, and any read-only member of a private one, could therefore rewrite or delete the labels on its artifacts, and every label change re-evaluates the sync policies that decide what replicates to peers. The three routes now also pass the deny-by-default `require_repo_action(.., "write", ..)` gate the SBOM mutations adopted for GHSA-ww52-pmcg-f53c, and answer 403 to a caller without the action. Removing a label asks for `write`, not `delete`, matching the token scope label operations already carry (#2989) and the `PUT`, which can replace the whole set. Global admins, `developer` and `repository-owner` members and fine-grained `write` grants are unaffected, and so are reads: a public repository's labels stay listable by any signed-in user, and a missing artifact is still a 404.
