- **Hosted Maven, npm, PyPI, Cargo, NuGet and Helm downloads verify the stored bytes** ([#4989], [#4323]). These download routes read the stored object through their own code and served it as a `200` under the checksum it was uploaded with, even when the object had been corrupted in storage. They now check it against the artifact's recorded SHA-256, as the generic download route and every virtual-repository member serve already do: an object of at most 4 MiB that does not match is answered `502 STORED_OBJECT_INTEGRITY` with none of its bytes, and a larger one is cut short before its last bytes. This covers Maven (including a `-SNAPSHOT` alias, also as a virtual member), npm tarballs, PyPI files, Cargo crates, NuGet packages (V3 flat container and V2), and Helm charts with the other formats that serve through the shared hosted tail. A `HEAD` on the streaming routes reads nothing and is not checked. The artifact route `GET /api/v1/repositories/{key}/artifacts/{path}` of a virtual repository now answers a corrupt member with the same `502` instead of `404`, and skips the check for a `HEAD`. See `docs/operations/download-integrity.md`.
