- **Opt-in routing of OCI pulls through a containerd registry mirror (`/v2/<image>/...?ns=<registry>`) to the Remote for that registry, behind `AK_OCI_NS_MIRROR_ROUTING` (off by default)** (#6247). containerd's `hosts.toml` mirrors (and so Talos, k3s, RKE2 and kind nodes) send a mirror pull without a repository key and name the upstream registry in the `ns` query parameter. With `AK_OCI_NS_MIRROR_ROUTING=true`, a read whose path names no repository is routed by `ns` to the one OCI Remote whose upstream URL is that registry, so one Artifact Keeper host can mirror several registries without a per-registry `override_path`; with `AK_DEFAULT_DOCKER_MIRROR_REPO` set, docker.io reads keep going to that repository, and a registry that no Remote proxies, or several do, is answered as an unknown repository. Like Docker-mirror mode, it lets an anonymous caller tell a missing repository from a private one (#3730), so it is off by default; see `docs/repository-visibility.md`. Independently of the setting, with `AK_DEFAULT_DOCKER_MIRROR_REPO` set a pull whose `ns` names a registry other than docker.io is now answered as an unknown repository instead of being served the Docker Hub mirror's image. Requests without `ns`, paths that name a repository, and writes are unchanged.
