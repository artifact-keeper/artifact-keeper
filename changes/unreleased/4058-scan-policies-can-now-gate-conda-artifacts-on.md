- **Scan policies can now gate conda artifacts on the facts the content epic persists — channel of origin, license, install scripts, and attestation state** (#4058). `scan_policies` gains a `predicates` JSONB column (migration 224; empty object = no predicates, so every existing policy evaluates byte-for-byte as before) holding a `conda` block with seven optional predicates: `allowed_channels` / `denied_channels` over the channel recorded in the artifact's identity purl at ingest (a remote repo's upstream URL, or the owning repo's key for hosted uploads — defence against channel-priority misconfiguration and typosquatted channels, failing closed when origin is unknown), `denied_licenses` / `denied_license_families` over the `license` / `license_family` `about.json` keys `build_conda_metadata` persists (an undeclared license is not a denied license), `block_install_scripts` and `max_install_script_severity` over the `package_install_scripts` rows and their analysis findings (scripts the rule engine could not examine are covered by the presence predicate, never graded "clean" by the severity one), and `min_attestation_state` (`present` / `verified`) over the CEP-27 verification record on `curation_packages.attestation_state`, folded weakest-first across a name/version's builds. Predicates compose with the existing CVE/severity conditions in the same policy — a violation from either blocks — and every violation is recorded with the fired predicate's stable token (`[conda.channel]`, `[conda.license]`, `[conda.license_family]`, `[conda.install_scripts]`, `[conda.attestation]`) in `PolicyResult.violations`, which is what the download gate, quarantine reason and audit trail persist. The allow/deny lists are the organisation's own: the product ships the mechanism and seeds no list. Evaluation loads the fact set only when an applicable policy configures conda predicates, so predicate-free repos pay zero extra queries on the download path. A staleness predicate against the last-observed upstream version is deliberately NOT included: nothing in-tree records an upstream version observation (the npm replication feed is a cache-invalidation mechanism, not a version record), and building that pipeline is out of scope here.
