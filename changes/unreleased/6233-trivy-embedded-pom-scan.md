- **The Trivy filesystem scan of a Maven JAR no longer grades the dependencies declared in its embedded build POM as shipped components** (#6233). #5262 kept `META-INF/maven/<groupId>/<artifactId>/pom.xml` out of the grype directory scan, but the Trivy filesystem scan of the same staged workspace still read it, so a JAR that bundles none of the code it declares (including `provided` and `test` scope) could be blocked or quarantined on those dependencies' CVEs. The scan workspace now drops an embedded build POM whose `pom.properties` sits beside it before Trivy runs, on both the local CLI and scanner-adapter paths. Bundled and shaded components are still graded at the versions they ship, from their `pom.properties`. A build POM with no `pom.properties`, and every build POM of an archive that bundles JVM archives (a `.war` or `.ear`, a `WEB-INF/lib` or `BOOT-INF/lib` directory, or a nested `.jar`, `.war`, `.ear`, `.aar`, `.hpi` or `.jpi` anywhere in it), is kept, because Trivy does not open nested JARs and the POM may be the only thing that names a bundled library. Known gap: a Maven-shaded jar whose relocated classes come from Gradle-built libraries (no `pom.properties`) is no longer flagged from its embedded POM. Grype has ignored embedded POM declarations since #5340, so neither engine flags that case now. Set `TRIVY_IGNORE_EMBEDDED_POM_DECLARATIONS=false` (new, default `true`) to grade those declarations again (and accept the false positives from #6233).
