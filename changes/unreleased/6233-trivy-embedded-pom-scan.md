- **The Trivy filesystem scan can now ignore the dependencies a JAR's embedded build POM only declares (opt-in; the default is unchanged)** (#6233). Set `TRIVY_IGNORE_EMBEDDED_POM_DECLARATIONS=true` to stop the Trivy filesystem scan grading dependencies that are only *declared* in a JAR's embedded build POM (`META-INF/maven/<groupId>/<artifactId>/pom.xml`; the grype behaviour since #5340). This removes false positives such as #6233's, where a JAR that bundles none of the code it declares (including `provided` and `test` scope) was blocked or quarantined on those dependencies' CVEs. It applies on both the local CLI and scanner-adapter paths. Bundled and shaded components are still graded at the versions they ship, from their `pom.properties`. Even when enabled, a build POM with no `pom.properties`, and every build POM of an archive that bundles JVM archives (a `.war` or `.ear`, a `WEB-INF/lib` or `BOOT-INF/lib` directory, or a nested `.jar`, `.war`, `.ear`, `.aar`, `.hpi` or `.jpi` anywhere in it), is kept, because Trivy does not open nested JARs. Known gap when enabled: any shaded library whose own `META-INF/maven/**` wasn't carried into the jar is then not flagged by either engine (maven-shade embeds the original build POM, e.g. jackson-core's shaded fastdoubleparser). With the setting unset or `false`, the Trivy filesystem scan grades embedded POM declarations exactly as before.
