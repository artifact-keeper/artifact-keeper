- **The Trivy filesystem scan of a Maven JAR no longer grades the dependencies declared in its embedded build POM as shipped components** (#6233). #5262 kept `META-INF/maven/<groupId>/<artifactId>/pom.xml` out of the grype directory scan, but the Trivy filesystem scan of the same staged workspace still read it, so a JAR that bundles none of the code it declares (including `provided` and `test` scope) could be blocked or quarantined on those dependencies' CVEs. The scan workspace now drops an embedded build POM whose `pom.properties` sits beside it before Trivy runs, on both the local CLI and scanner-adapter paths. Bundled and shaded components are still graded at the versions they ship, from their `pom.properties`. A `.war` or `.ear`, an archive that bundles libraries under `WEB-INF/lib`, `BOOT-INF/lib` or `lib/`, and a build POM with no `pom.properties` keep their build POMs, because Trivy does not open nested JARs and the POM may be the only thing that names a bundled library.
