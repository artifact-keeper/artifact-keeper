---
section: Changed
issues: [#4240, #3951]
---
- **An npm virtual repository with a private member now serves its packument from the computed-packument cache, and consults its members concurrently instead of one after another** (#4240, #3951). Every virtual packument request walked its members serially — `collect_virtual_packument` awaited each member inside a `for` loop — so a virtual over N remote members cost roughly the *sum* of N upstream round trips on a cold path, and a member that did not have the package still cost a full one. On top of that, #3323 had to make every virtual with a non-public member ineligible for the #2166 cache: the merge is narrowed to the members the caller may read, the cache key carried nothing about the caller, and a shared entry would have served one caller's view to another. A virtual that aggregates anything internal has a private member by construction, so in practice those virtuals recomputed the full merge on every request, and no cache tier — including a shared `NPM_PACKUMENT_CACHE_REDIS_URL` backend — could reach them.

  **Members are now consulted concurrently, with byte-identical output.** The merge resolves contributions in priority-order batches with `join_all` — the shape #2069 already gave the other formats' aggregating walk — and folds them in priority order, so `merge_packument_into`, which lets the higher-priority member win a version or dist-tag, sees exactly the sequence it did before. The first member in priority order whose contribution errors still fails the merge, and a member miss still never does. Memory stays bounded by the #2665 metadata budget whatever the walk shape: each remote fetch reserves its cap from a process-wide budget that waits rather than failing, so concurrency cannot raise the ceiling or silently drop a member, and each member holds exactly one reservation and reserves nothing further while holding it, so the walk cannot form the hold-and-wait #4145/#4170 removed. The batch width is bounded so one request holds at most half the budget's slices — 4 concurrent member fetches on the default 1 GiB `AK_PROXY_METADATA_BUDGET_BYTES` — and a budget shrunk below two slices falls back to the serial walk, so a wide virtual cannot monopolise the budget other requests share.

  **A virtual's cache entry is keyed by the caller's authorized member list.** The merged document depends on the caller only through `authorized_virtual_members`, so it is a pure function of that ordered list: the list is resolved once per request, a digest of its ordered member ids becomes the third key segment (`{repo}:{package}:m{digest}:{variant}:{encoding}:{base}`), and the entry is computed from exactly that list rather than from a caller — which is what lets the background stale-while-revalidate refresh, which has no caller, recompute precisely the document its key names. Callers with identical visibility share one entry; callers with different visibility get different entries and cannot read each other's. Remote keys are unchanged; existing virtual entries move to the new layout once, so each all-public virtual recomputes its packuments once after upgrade and its old shared-cache entries expire with the stale window. Age-gated virtuals still bypass the cache entirely.

  **A definitive 404 now evicts only the member list that produced it.** The cache evicted the whole package whenever a compute returned 404/410, so that upstream unpublishes and takedowns propagate. With one entry per member list that was wrong — a 404 for one list says nothing about a larger list that includes a member still carrying the package — and it would have let any caller flush every other caller's entries on demand. A virtual's 404 now evicts that list's entries only, and every list still evicts on its own next refresh, so a takedown still reaches all of them. A caller who may read no member is answered with the existing not-found body before the cache is touched. To make list-scoped eviction work on the shared backend, the Redis `invalidate_prefix` now honours the contract the backend trait already documented — drop every entry whose key starts with the prefix — by filtering the package's key index; previously any prefix narrower than a whole package was silently a no-op there. Eviction for every existing caller, all of which pass whole-package prefixes, is unchanged.
