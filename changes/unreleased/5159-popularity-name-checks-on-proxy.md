- **`popularity` curation rules now check package names on npm and PyPI Remote and Virtual downloads** (#5159). Before, a proxy download consulted only `pattern` rules, so the typo-squat, homoglyph and affix detection of a `popularity` rule ran only in the staging-repository sync and never refused a package pulled through a Remote. The proxy curation gate now also runs each `popularity` rule's name checks against its popular list. They are local string comparisons, so a download makes no call to pypistats or the npm downloads API. With `block_typosquat: true`, a homoglyph or mixed-script lookalike of a popular name is refused with the usual `403 curation_blocked`. Every other match is a flag: since the proxy path has no review queue, the download is served and the flag is logged. Edit-distance and affix matches only ever flag on downloads, because both reach real packages that a block would refuse with no review step. Edit distance 2 from the short seed names matches npm `preact`, `vite`, `chai` and `vuex`, and PyPI `numba`, `httpie`, `attr` and `pipx`. Sparing popular affixed names such as `eslint-plugin-react` needs the download count. A flag never overrides a lower-priority `block` rule. On a Virtual repository the rules resolve exactly as `pattern` rules do there. The download-count threshold (`min_downloads`, `block_unknown`) and `publisher_trust` rules still run only in the staging sync.
