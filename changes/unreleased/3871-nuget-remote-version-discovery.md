- **A remote NuGet repository now lets a client discover package versions it has not restored yet** (#3870). Restoring through a remote repository worked, but `dotnet list package --outdated` failed with `Object reference not set to an instance of an object` and the Visual Studio and Rider version pickers stayed empty. For a package with a long history, such as `Serilog`, the upstream registration index splits its versions into pages, and the index handed to the client pointed at `/v3/registration/{id}/page/{lower}/{upper}.json` URLs that AK answered with `404`. Those pages are now proxied and rewritten onto AK the same way the index is, through the remote repository or each remote member of a virtual repository in priority order. The package id and every path segment are validated before any upstream fetch, and the upstream URL is built from encoded path segments, so a client cannot add a query, a fragment or a `..` hop. A V2 upstream links no pages and answers `404`. The service index also advertises `RegistrationsBaseUrl/3.6.0` and a `SearchAutocompleteService`. Autocomplete answers package ids and versions from a hosted repository's rows, from a remote repository's upstream, or from both merged for a virtual repository, and honours `skip`/`take`. An upstream that advertises no autocomplete service, which includes every V2 feed, gets an empty answer instead of a `502`. A remote repository that still holds cached `artifacts` rows for a package now merges the upstream version list into them, deduplicated case-insensitively, instead of listing only the cached versions. If the upstream fails, the cached versions are returned.
