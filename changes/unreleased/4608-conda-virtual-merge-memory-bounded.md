section: Fixed

- **Concurrent solves against a virtual conda channel no longer drive the backend out of memory** (closes #4608). Every request for a virtual channel's `repodata.json` (any encoding), `channeldata.json` or CEP-16 shard index ran its own merge: it decoded each remote member's document (about 455 MB of JSON for conda-forge `linux-64`), merged it with the hosted records and encoded the result, and none of that was counted against the buffered-metadata budget. Memory grew with the number of concurrent solves: 20 concurrent `repodata.json.zst` requests took the backend to 20.8 GB, and at a 12 GiB limit it was OOM-killed. Requests for the same merged document now share one merge, and its encoded result is kept for `CONDA_VIRTUAL_MERGE_CACHE_TTL_SECS` (default 300, `0` disables) under one `ETag`, so revalidation answers 304; it is reused only while the caller-visible member set, the hosted records, the names hosted members own, the allowlist and each remote member's proxy-cache entry (by checksum, and only while fresh) are unchanged, a merge with a failed member is never kept, and the member-failure policy still applies to each response. Shard requests through a virtual are routed from the kept shard index merge instead of re-reading every member's index. At most `CONDA_VIRTUAL_MAX_CONCURRENT_MERGES` merges run at once (default: the buffered-metadata budget divided by the member fetch and decoded ceilings, at least 2); a merge that cannot start within `CONDA_VIRTUAL_MERGE_QUEUE_SECS` (default 60) answers 503 with `Retry-After`. Each merge reserves its fetch buffer, decoded member documents, working set and output from `AK_PROXY_METADATA_BUDGET_BYTES` before it starts (sized from the previous merge of the same document, or the whole budget the first time) and never waits for budget while holding some. The compressed encodings are serialized straight into the compressor. With the change, 20 concurrent requests peak at 0.7 GB, and a 40-way cold-cache `pixi install` stampede completes under an 8 GiB limit with the backend below 1 GB. New metrics: `ak_conda_virtual_merge_inflight`, `ak_conda_virtual_merge_cache_hits_total`, `ak_conda_virtual_merge_cache_misses_total`, `ak_conda_virtual_merge_rejected_total` and `ak_conda_virtual_merge_bytes_reserved`; sizing and restart alerting are in `docs/operations/conda-virtual-merge-memory.md`.
