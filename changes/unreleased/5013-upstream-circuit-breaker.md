- **A Remote stops contacting an upstream that keeps failing, and answers at once from its stale copy, the next virtual member or a retryable `503`** (#5013). Every upstream request of a Remote repository now goes through a circuit breaker for that repository and upstream host. After `AK_UPSTREAM_CIRCUIT_FAILURES` (default `5`) failures in a row, each within `AK_UPSTREAM_CIRCUIT_WINDOW_SECS` (default `120`) of the previous one, the circuit opens: requests skip the upstream for `AK_UPSTREAM_CIRCUIT_OPEN_SECS` (default `10`), then one request probes it. A failed probe doubles the period, up to `AK_UPSTREAM_CIRCUIT_MAX_OPEN_SECS` (default `300`), with ±20 % jitter; an answer closes the circuit. A failure is a connect error, a timeout, another transport error, an upstream `502`/`503`/`504`, or a request one of this server's own deadlines gave up on after waiting `AK_UPSTREAM_CIRCUIT_SLOW_CALL_SECS` (default `10`) for headers (a client disconnect never counts). The circuit is per host of the requested URL, so redirects share it and repeated `502`/`503`/`504` on one path open it for the whole host. A `404`, `410`, `401`, `403` or other answer never trips it, and an open circuit is never reported as a miss: a Remote serves its stale copy within the stale-if-error grace without waiting out the upstream timeout, a virtual repository moves to the next member or answers `503` with `Retry-After`, and the scan and serve gates are unchanged. Before, a black-holed upstream cost every request the 10 s connect timeout and a hung one the 60 s read timeout.

  **Default change:** the breaker is on. Set `AK_UPSTREAM_CIRCUIT_OPEN_SECS=0` to keep the 1.12 behaviour of contacting the upstream on every request. The state is in memory per replica. `ak_upstream_circuit_state`, `ak_upstream_circuit_opens_total` and `ak_upstream_circuit_short_circuited_total` (labels `repository_id`, `host`) report it, and opening and closing are logged. See `docs/operations/upstream-circuit-breaker.md`.
