- **The backend image's bundled `grype` and `buildctl` are rebuilt on go1.27.2 with `golang.org/x/net` v0.60.0, clearing the Go October security release from Docker Publish's gate** (#3698). From 2026-10-10 the `Security Scan` job failed on every `main` build, so no `:main` image was published and 1.11.0 could not be cut. Trivy reported CVE-2026-78669 (HIGH; HTTP/2 denial of service via excessive SETTINGS frames, fixed in `x/net` v0.60.0) against `usr/local/bin/grype` and `usr/local/bin/buildctl`, both at `x/net` v0.58.0, and three HIGH standard-library advisories (CVE-2026-78667 in `net/http`, CVE-2026-78669 in the bundled HTTP/2 stack, CVE-2026-97031 in `crypto/tls`; fixed in go1.26.9 / go1.27.2) against `buildctl`, which was copied out of `moby/buildkit:v0.33.0` and compiled by Docker on go1.26.8. No grype or BuildKit release carries `x/net` v0.60.0 yet (grype v0.120.1, BuildKit v0.34.0 and both projects' `main` pin v0.59.0), so a version bump could not fix either. `buildctl` is now built from source at the same v0.33.0 tag (commit `dddd5621`), the way grype has been since #3352, so its compiler is ours too; both stages raise the `GO_MIN_PATCH` floor to 1.27.2 and apply an `x/net` v0.60.0 override with the same three build-time guards as grype's gRPC override: the pinned source still requires v0.58.0, `go get` moves exactly the declared set of seven `golang.org/x` modules, and the compiled binary's Go build info records v0.60.0. Every module the override drags along lands on the version grype v0.120.1 already ships, and the `x/crypto` v0.57.0 it brings also clears the two `x/crypto/ssh` advisories #3698 was waiting on. Nothing is added to `.trivyignore`: each finding had a fixed version to build against. `grype --version` still prints `0.118.0` and `buildctl --version` still reports v0.33.0, so nothing operator-facing changes. The scanner-adapter image fails the same gate on its bundled trivy; that half is fixed in `artifact-keeper/trivy` and repointed here separately.
