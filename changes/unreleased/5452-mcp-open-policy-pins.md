- **MCP registries under the `open` package policy no longer serve runnable packages without an Artifact Keeper pin and gate** (#5452). `open` stored and served `packages[]` verbatim, so a hosted, Remote or Virtual MCP repository could hand an agent an npm, PyPI or OCI coordinate on a registry the publisher controls, and the client fetched those bytes directly, past every age, quarantine and scan gate. `open` now only accepts foreign coordinates: a `registryBaseUrl` or OCI image host naming another registry is not refused, but the package must still resolve by name and version in the repository `mcp_package_repos` maps, and is pinned, served at its Artifact Keeper coordinates and gated exactly as under `own-repos`. Through a Remote backing repository (or a Virtual's Remote member) foreign coordinates resolve only when they name that Remote's upstream, so a same-named public package cannot stand in for a private one and nothing is filled on the publisher's behalf from another registry. The served package's `_meta["com.artifactkeeper/resolved"]` and the version's health show what was replaced (`foreign_coordinates_replaced`). A package that does not resolve is refused at publish, filled through a Remote backing repository (`202 resolving`), or, for a Remote MCP repository's sync, stored `unresolvable` (hidden). The generic download, artifact metadata and tree content routes now serve the same pinned server.json as the registry, not the stored submission. An `open` publisher now needs `read` on the backing repository, as under `own-repos`.

  Upgrade note: versions published under `open` before this release carry no pins and are held `unresolvable` (`404 mcp_unresolvable` for a repository holder; health `critical`) until they are pinned. A Remote MCP repository's sync re-resolves them on every pass and serves each once its packages are in a backing repository (a package naming a registry other than a Remote backing repository's upstream stays hidden). A hosted version is re-resolved in place by an administrator's `PUT .../versions/{version}` of the same document once its packages are in a backing repository, or republished as a new version.
