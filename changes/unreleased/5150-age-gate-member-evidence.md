- **An age-gated Remote that does not host a package no longer refuses it through an npm or PyPI virtual** (#5150, #5151). The member used to answer 451 and write a pending review with no publish time, which stopped the member that does host the package from being asked. A member now steps aside when its upstream answers 404 or 410, or its package document does not list the version; that answer is read from the upstream, not the proxy cache, and is reused for at most 3 seconds. For PyPI only an index that is about the requested project can give it, so a login page or other 200 from the upstream still blocks. It writes no review and serves no bytes for that request, so if no member hosts the version the virtual answers 404. A member that hosts the version and finds it too young still blocks the virtual, as does an unreadable upstream, an upstream that lists the version with no time, a rejected review, and a `first_seen` observation still inside the window. A direct Remote answers as before.

  PyPI upstreams without the Warehouse JSON API can now be dated: the gate and the HTML listing read `data-upload-time` from the simple index, and the gate also reads PEP 700 `upload-time` from a PEP 691 response, using the Remote's configured credentials. `first_seen` mode can now start its clock from the simple index on these upstreams. `min_age_days = 0` no longer blocks on an unknown publish time for any format, and on npm, PyPI and Maven it no longer depends on upstream metadata being readable; the sweep also releases pending reviews with no time at 0. A rejected review still blocks at 0. Above 0, a version with no time from any source stays blocked until approved, which is the documented rule for every format: use `first_seen` for an upstream that publishes no times.
