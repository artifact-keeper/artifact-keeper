section: Fixed
issues: [#4580]
---
- **Conda repodata and CEP-16 shard indexes resolve packages against the URL that served them, so mirror-configured clients, clients behind a proxy and token channels download from the right place** (closes #4580). Hosted and virtual `repodata.json` (and its `.zst`/`.bz2`, `current_repodata.json` and JLAP forms) carried `info.base_url = "/conda/<repo>/<subdir>/"`, and every shard index (hosted, remote and virtual) carried the same host-relative path. rattler resolves `base_url` against the channel's canonical URL before applying a `[mirrors]` rewrite, so with the standard enterprise mirror `"https://conda.anaconda.org/conda-forge" = ["https://ak.internal/conda/conda-forge"]` every `pixi exec` and `rattler-build -c conda-forge` environment creation requested `https://conda.anaconda.org/conda/conda-forge/<subdir>/<pkg>` and failed with 404, with no client-side escape (rattler-build ignores `disable-sharded`). A proxy in front of the registry (Nexus) passed the path through, so a client using the proxy's channel URL resolved packages against the proxy host at the registry's path, and a `.condarc` token channel (`/conda/t/<token>/<repo>`) lost its token on every package URL. `repodata.json` now omits `base_url`, so CEP-15's default (the document's own directory) applies, and shard indexes carry `base_url: "./"` and `shards_base_url: "./shards/"`, the values rattler's own indexer writes. The documents no longer depend on the request at all: an absolute URL built from `Host`/`X-Forwarded-*` would have pointed past a proxy that sets no forwarded headers, written token-channel tokens into the body, and made the cached bytes and `ETag` depend on a client-supplied header. The red-team workarounds (`disable-sharded` for the forge mirror, `-c https://ak.internal/conda/conda-forge` in place of `-c conda-forge` for rattler-build) are no longer needed.
