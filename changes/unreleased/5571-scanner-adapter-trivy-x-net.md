- **The scanner adapter's bundled `trivy` is rebuilt with `golang.org/x/net` v0.62.0, clearing the last HIGH finding that kept Docker Publish red on main** (#5571). Since 2026-11-07 the publish gate reported CVE-2026-78661 (GO-2026-6860, HIGH, denial of service in `golang.org/x/net/html`, fixed in v0.62.0) against the three Go binaries the images ship: `grype` and `buildctl` in the backend image, and `trivy` in the scanner adapter. #5567 cleared the first two. For the third, upstream Trivy v0.76.2 does pin `x/net` v0.62.0, but the adapter has to run the same Trivy release as its server sidecar, so instead of moving the server for a client-only dependency fix, `artifact-keeper/trivy` gained a guarded `x/net` override on top of the unchanged v0.76.0 source (trivy#21) and was published as `0.76.0-r4`. The adapter's `FROM` moves from `ghcr.io/artifact-keeper/trivy:0.76.0-r3` to `0.76.0-r4` by manifest-list digest. The binary still reports Trivy 0.76.0 on go1.27.3, so a self-run Trivy server stays on 0.76.0 and nothing in the adapter's version probing changes. With this, every image published from main scans at zero HIGH and zero CRITICAL findings.
