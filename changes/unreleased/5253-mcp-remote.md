- **Remote MCP registries: an approval-gated allowlist populated from an upstream MCP registry** (#5253). A Remote `mcp` repository syncs the upstream's `/v0.1/servers` listing hourly (and on demand, `POST /api/v1/repositories/{key}/mcp/sync`) into a catalog the web UI browses, and serves on `/v0.1` only the names an administrator approved (`mcp_remote_posture: approval_required`, the default and instance-lockable; `allow_with_gates` is the opt-in relaxation). Names can be approved one by one, in bulk by full-name glob (`POST .../mcp/catalog/bulk-approve`, `io.github.acme/*`; a bare namespace is refused with `422`) or by id (`POST .../mcp/catalog/bulk-decide`, which also blocks), blocked in bulk by glob (`POST .../mcp/catalog/bulk-block`), with a `dryRun` preview of either glob decision, automatically on sync (`mcp_auto_approve_namespaces`), or as single `name@version` pins; `mcp_server_deny` always wins, on every repository type, and a hosted publish of a denied name is refused with `403 mcp_server_denied`. Approved versions are stored write-once with every package pinned at sync through the Remote's own `mcp_package_repos` (an upstream `latest` or tagless image is pinned to its digest with a warning, or hidden with `mcp_oci_floating_tag_policy: hide`). An upstream edit of an ingested version keeps the stored document, revokes that version's approval and re-queues it (`MCP_SERVER_CONTENT_DRIFT`); lookalike names are flagged for review at ingest; the Remote's age gate holds new server versions by first sighting; and any gate that cannot be evaluated answers `503 mcp_gate_unavailable` (fail closed, audited `MCP_GATE_UNAVAILABLE`). `mcp_remote_mode: mirror` ingests and indexes every upstream name for offline search while serving stays curated. The first sync asks upstream for deleted versions too, so a version already deleted upstream is recorded as `deleted`. Catalog items carry a cached risk `summary` (transports, package registry types, secret, package and remote counts, and the latest ingested version's lint counts), and `GET /api/v1/mcp/pending-summary` counts the approval queue across every Remote MCP repository the caller can read. See "Remote repositories" in `docs/mcp-registry.md`.
