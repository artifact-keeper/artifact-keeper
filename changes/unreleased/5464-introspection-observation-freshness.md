- **A stale MCP capability observation can no longer replace a newer current one** (#5464). The current capability view, the drift baseline, snapshot deduplication, the history order (`snapshots[]`, and with it the diff's default `from`) and retention ranked snapshots by arrival, so an introspection result or CI/gateway report completed later with an earlier `observedAt` became current over a fresher observation. They now rank by the latest time the content was validly seen (`lastSeenAt`, else `observedAt`), then arrival, with deterministic ties. A stale observation is kept as history: it raises no `tool_drift` finding and is not linted, so tool text in such a history row carries no lint finding in the diff view. A completion's response now carries `current`, whether the stored snapshot is the version's current view after the commit. An introspection result's `observedAt` must lie between the job's claim and its arrival (five minutes of clock skew either side), else it is refused with `400` and the claim is left as it was; a result or report dated up to five minutes ahead is stored as of its arrival, so clock skew never ranks it above genuine observations. CI and gateway reports keep no lower bound on `observedAt`: a pipeline that reports a build or commit time older than the current snapshot of its source now stores history (`current` stays on the fresher snapshot, no drift) instead of updating the current view. This is intended, but existing reporters that send such timestamps will see it.
