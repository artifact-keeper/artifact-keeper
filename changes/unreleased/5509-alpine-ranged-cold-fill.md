section: Fixed
issues: [#5509, #5554]
---
- **A ranged download from a cold Remote cache now fills the cache** (#5509, #5554). The proxy's write into its cache is driven by the client reading the body, and the HTTP server stops reading a body once its `Content-Length` bytes are out. A ranged `GET` answered `206` from a cold fetch with a window ending before the end of the file (the signature and control spans of an `.apk` that rules_apko fetches as three ranged `GET`s, or any mid-file range on the generic and Hugging Face routes) therefore cut the cache write short: it was rejected as truncated, the upstream fetch was aborted, and requests sharing that fetch started over, so every repeat went upstream again and only a range ending at the end of the file was ever cached. A streaming fill whose client stops reading after the first bytes now reads the rest of the object on its own task and commits it, so the next request is a cache hit. These fills share the `PROXY_UPSTREAM_MAX_DETACHED_FILLS` limit with the buffered fills that already outlive their request (#5220), and with no slot free a fill ends with its client as before. The Alpine package route now ranges its proxy-cache, cold-fetch and Virtual serves with the same helper as the generic and Hugging Face routes, so it also honours `If-Range` (a stale validator gets `200` with the whole file) and answers a `HEAD` with `Range` with `200` and no body, as those routes do. `Range` is still never sent upstream.
