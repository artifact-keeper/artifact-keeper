- **Lifecycle policies assigned to a Remote repository now reclaim its proxy cache** (#3734). Until now the lifecycle executors only looked at `artifacts`, while a Remote repository records what it proxies in `proxy_cache_artifacts`. Storage GC leaves `proxy-cache/*` objects alone, so a long-lived Remote repository's cache grew without bound. When a `max_age_days` or `no_downloads_days` policy is explicitly assigned to a Remote repository, `max_age_days` evicts cache entries whose `cached_at` is older than the window, and `no_downloads_days` evicts entries that were cached before the window and have not been served or downloaded inside it. Each eviction deletes the `__content__` body and the `__cache_meta__.json` sidecar, then removes the catalogue row. If a storage delete fails, or the row records a key outside the repository's cache (for example after a repository rename), the row stays and the entry is reported in `errors`. `match.path_prefix` applies to the cached path. Preview and execute report cache entries in a new `proxy_cache` object on the result (`entries_matched`, `entries_removed`, `bytes_matched`, `bytes_freed`, `skipped_reason`), separate from the artifact counters. `last_run_items_removed` counts both.

  **Global (`applies_to_all`) policies do not reach Remote caches.** This keeps upgrades safe: a global policy written for hosted cleanup does not start evicting every Remote cache, which may hold the only copy of content that is gone upstream. Such a run names the reason in `proxy_cache.skipped_reason`. To reclaim a Remote cache, assign the policy to the repository explicitly, and run a preview first: `max_age_days` evicts by cache age regardless of how often an entry is used.
