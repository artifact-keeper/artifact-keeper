- **A proxied file the scan gate cannot vouch for is no longer committed to the proxy cache** (#4514). On a Remote that scans on proxy, the format route now fetches a package into memory, runs the scan gate, and only then writes it to the proxy cache. A body that is inconclusive under `fail_closed` (answered `423`: no scanner, a failed or over-budget scan, an identity that cannot be established) is no longer cached, so no reader can serve it from the cache; it is fetched from the upstream again on its next pull, and concurrent pulls of one file on one replica wait for the first pull's decision (up to 35 seconds) instead. A body that fails the format's own check before the gate (a Cargo index `cksum`, a Maven `.sha1`) is not cached either. Served bodies are cached as before, and so are blocked (`403`) ones, which every reader of the scanning Remote refuses from the stored verdict and which stay listed, counted and rescannable. A fill refused by a Package Age Policy hold is still committed with its hold. No migration and no change to the cache sidecar format. See "The proxy cache and the gate" in `docs/security/scan-on-proxy.md` and the design note `docs/security/proxy-cache-commit-after-gate.md`, now marked shipped.
