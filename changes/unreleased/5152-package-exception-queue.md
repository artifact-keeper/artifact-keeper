- **A proxied package refused by the age, scan or curation gate can be let through on its own, without loosening the repository** (#5152). Only the age gate had a per-package review. For the other two the only lever was the repository's posture (`severity_threshold`, `block_on_policy_violation`, a curation `allow` rule), which turns the gate off for everything. The age-gate review queue is now the queue for all three (`gate` discriminates, migration 381). A refusal files a row, so the queue shows real demand, and `POST /api/v1/exceptions/requests` lets any authenticated user attach a justification to one. `GET /api/v1/exceptions/requests` and `GET /api/v1/exceptions/requests/{id}` show a requester the status of the requests they hold, without the reviewer capability. Every REST refusal carries a link in `exception_request_url` and an `X-AK-Exception-Request` header, templated from the new `security.exception_request_url` setting, and the OCI error message carries it too.

  A scan or curation grant serves those bytes until `expires_at` (90 days by default, `never_expires` is a separate explicit choice), needs a reason and is audited with the actor. A scan exception is bound to the content digest that was refused, so republished bytes under the same version block again, and expiry is applied on every read with no sweep. An approval on one gate never satisfies another, and a lookup error denies. A 423 `scan_pending` is exceptable only when it can never clear (no scanner, or the scan failed). A scan that ran out of budget keeps the plain 423. This is not a finding acknowledgement (#5153): an acknowledgement accepts one advisory on a hosted artifact and keeps every other finding open, an exception releases a proxied package version from a gate as a whole.

  Deciding is a new global capability, `security_review`, seeded on a `security-reviewer` role, so a reviewer can accept risk per package without being able to change repository scan or age settings. The reviewer routes are mounted at `/api/v1/exceptions` and check the capability in the handler. A scoped or repository-restricted API token never carries it. `GET /api/v1/auth/me` reports it in a new `capabilities` list. The repository-scoped age-gate queue (#4238) stays age-only, and a reviewer who is not an instance admin cannot overturn an instance admin's locked decision. An age-gate approval keeps its contract (reason optional, no expiry unless `expires_in_days` is sent). A scan or curation approval needs a reason (400 without one). Whoever filed the request on a scan or curation row cannot grant it (403), like promotion approvals, and a repository-restricted token cannot reach the queue even when an admin owns it. A user may have at most 50 undecided requests open (409 past that), and `security.exception_request_url` must be an absolute `http` or `https` URL. A gate auto-files at most 1000 undecided rows per repository, so anonymous pulls of made-up names on a remote that blocks by default cannot flood the queue: past that a new name is still refused but files nothing.
