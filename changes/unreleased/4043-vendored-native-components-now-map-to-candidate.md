- **Vendored native components now map to candidate CPEs — with confidence and provenance — so NVD-keyed matching has something to key on** (#4043). The native libraries content analysis recovers (recipe sources, wheel auditwheel layouts) are C/C++ projects whose advisories live in NVD, which is keyed on CPE, not package names; a vendored `libwebp` was discovered and then matched against nothing. A new `cpe_candidates` module restates each component's identity as **candidate CPEs, plural**, produced by three explicit rules — `cpe-known-table-v1` (a small vendored table of well-known libraries and the vendor/product pair NVD uses, e.g. `libwebp` → `webmproject:libwebp`; **high** confidence), `cpe-source-url-vendor-v1` (the forge owner of the component's own `source_url`/`git_url`, when the repo name matches the component; **medium**), and `cpe-name-as-product-v1` (the name itself and the `<name>_project` vendor spelling, both **low** — two vendors publish the same product name often enough that offering one would be a coin flip). Every candidate carries the `rule_id` that produced it, so a wrong candidate is traceable to its rule; the name-guessing rule has a confidence floor, and a name too short or malformed to be a real upstream product (`ab`, `{{ name }}`) produces no candidate at all rather than an invented one. Ambiguity is **surfaced, never resolved**: the package-analysis API serves the full candidate set per component with confidences, rule ids and a `cpe_ambiguous` flag, while the Dependency-Track submission and the stored/on-demand SBOM stamp a component's CycloneDX `cpe` field (and SPDX `cpe23Type` SECURITY external ref, persisted to the long-dormant `sbom_components.cpe` column) **only when the top-confidence tier holds exactly one candidate** — an ambiguous identity is submitted CPE-less rather than arbitrarily picked, because DT treats `cpe` as authoritative for NVD correlation. Matching semantics are pinned offline by `match_advisories`, an evaluator for NVD-shaped `cpeMatch` criteria (version ranges included, boundary-checked both directions) tested against a fixture advisory set modelled on CVE-2023-4863; in production the NVD matching itself happens inside Dependency-Track against the submitted `cpe`, and an in-tree NVD feed sync remains future work with its evaluator ready.
