- **A remote repository now applies the upstream outbound address policy to IP-literal destinations in every egress routing mode** (#5095). URLs a Remote reads from upstream content, such as the chart URLs in a Helm `index.yaml`, were checked against the policy only when the repository routed through an explicit egress proxy; with direct or inherited routing the connect-time resolver check was relied on, and an IP-literal host never reaches the resolver. Every upstream fetch now checks an IP-literal destination (including numeric, octal and hex IPv4 spellings, IPv6, IPv4-mapped IPv6 and NAT64 `64:ff9b::/96` addresses) against the same policy that validates a saved upstream URL before any request is sent, and a refused destination answers `502` with code `UPSTREAM_DESTINATION_REFUSED`. The configured private-address exceptions (the private-CIDR allowlist, also accepted as `UPSTREAM_PRIVATE_IP_ALLOWLIST`, and `UPSTREAM_ALLOW_PRIVATE_IPS`) apply as they do when an upstream URL is saved; loopback, link-local and cloud metadata addresses stay refused. Host names keep the connect-time check, and explicit egress proxies are unchanged. The VS Code gallery query (a JSON POST) now also goes through the repository's egress routing, and the CI OIDC token exchange checks the JWKS URL the issuer's discovery document names.

  **Upgrade note:** a Remote whose stored upstream URL is a private IP literal saved before upstream URLs were validated stops fetching until that address is admitted by the private-CIDR allowlist or `UPSTREAM_ALLOW_PRIVATE_IPS`. A stored loopback or link-local upstream (for example a sidecar mirror on `127.0.0.1`) cannot be admitted; point it at a non-loopback address. When the CIDR allowlist is set, it takes precedence over `UPSTREAM_ALLOW_PRIVATE_IPS` for upstream fetches, as it already did when saving an upstream URL.
