- **Scan-on-proxy now gates Composer dist archives from Composer Remote and Virtual repositories** (#4105, part of #4097). With `scan_on_proxy` on, a proxied `dist/` download goes through the shared inline scan-and-block gate instead of streaming unscanned: a vulnerable archive is refused with 403 `scan_blocked`, a clean one is served with `X-AK-Scan: clean`, the verdict is reused for the same digest, and `fail_open`, `fail_closed` and `record_only` behave as they do for the other enforced formats. The archive's own `composer.json` must name the requested package (and any `version` it declares must match); one that does not is withheld under `fail_closed` (423) without being scanned. A dist that agrees is graded as the requested package version (through a synthetic `composer.lock` pin, #4952) and on its contents (a bundled `composer.lock`, vendored packages). A Virtual repository applies the stricter of its own and each Remote member's policy; a scanning Remote member now fetches the dist from the URL its own upstream metadata names, so a Virtual over a Packagist-style Remote serves through the gate. On Remote and Virtual Composer repositories, a `dist/` vendor, package, version or reference containing `?`, `#`, `;`, `\`, a stray `%`, a space or a control character after decoding is now refused with `400`. Package metadata is unchanged, and `GET /api/v1/formats` now reports Composer as `scan_on_proxy: "enforced"`.
