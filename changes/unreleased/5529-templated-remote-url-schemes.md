- **MCP publish checks what a templated remote or package transport URL expands to** (#5529). A literal `javascript:` remote URL was refused, but `{base}/sse` was accepted with a `base` variable whose `default` or `choices` were `javascript:`, `data:` or `vbscript:` URLs, so a client that filled in the publisher's value obtained an active-scheme URL. Every `remotes[].url` and `packages[].transport.url` template is now expanded against each variable's `value`, `default`, `placeholder` and `choices` (for a package, those of every argument and environment variable the variable names), and the version is refused with `400 mcp_invalid_server_json` unless every expansion is an absolute `http`/`https` URL; more than 256 expansions are refused rather than checked. Upstream versions ingested into a Remote repository follow the same rule and are not admitted. A template whose scheme-position variable has no value is also refused, declared or not: `{base}/sse` with no `default` or `choices` for `base` was accepted, including when `base` was not declared at all; whatever the client fills in picks the scheme, so declare the variable with an `http(s)` `default` or `choices`. The `remote_url_shape` lint rule (`review`) flags such templates in versions stored before this change when the version is next linted (publish, edit, status change, pin or ingest); there is no backfill. The lint version is now `ak-mcp-lint/3`. There was no XSS: the web UI renders these URLs as text.
