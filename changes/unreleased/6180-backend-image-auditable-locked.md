- **The backend image's binary carries its own dependency list, and every shipped build uses the committed Cargo.lock** (#6180). `docker/Dockerfile.backend` now builds `/usr/local/bin/artifact-keeper` with `cargo auditable` (pinned 0.7.7, as the release tarballs are). So `cargo audit bin`, Trivy and Syft can list the binary's Rust crates from the image itself. Before this they saw none, and the image's SBOM covered only the RPMs and the bundled Go tools. Docker Publish fails if the published image's binary has no embedded dependency graph. For this release Trivy reports findings in those crates to the Security tab without blocking publication, while a `.trivyignore` policy for crates is agreed. Rust advisories still block merges through `cargo audit`. The image build, the release tarballs and the CI builds run with `--locked`, and cargo-chef, cargo-audit and cargo-auditable are pinned to exact versions. Check Rust fails a PR whose Cargo.lock is out of date. CI also runs `osv-scanner` on Cargo.lock beside `cargo audit`, under the same blocking rule: it reads GitHub advisories that RustSec may lack. Its ignores are in `osv-scanner.toml`, each with a reason and an expiry. block-buffer (0.12.1), event-listener (5.4.2) and rustix (1.1.6) move to their patched releases. Image and tarball builds no longer rewrite the version in Cargo.toml from the git tag, so a binary reports the version committed by the release-prep PR. A prerelease tag `vX.Y.Z-rc.N` now builds and reports `X.Y.Z`, and a tag that does not match Cargo.toml fails the release build.
