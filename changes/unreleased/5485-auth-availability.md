- **Password verification now has a login budget everywhere, and a cancelled request no longer frees its bcrypt slot early** ([#5485]). The auth-concurrency permit (`AUTH_MAX_CONCURRENCY`) is now held by the bcrypt job itself, so a client that disconnects, resets the HTTP/2 stream or times out mid-verify can no longer release its slot while bcrypt keeps running, and the cap again bounds the bcrypt work in flight. The LDAP login `POST /api/v1/auth/sso/ldap/{id}/login` now sits behind the same per-(username, IP) login limiter, global backstop and per-IP failed-login budget as `POST /api/v1/auth/login` (`429` once spent). HTTP Basic `username:password` on the package routes, on `/v2` and on the management API now has a login budget too: failed verifications are counted per (username, source IP) in a bucket sized like `RATE_LIMIT_TOKEN_EXCHANGE_PER_WINDOW`, and past it that pair answers `429` with `Retry-After` before any bcrypt, for a real account and an unknown username alike. Correct passwords are never counted. The timing pad that makes an unknown or federated username cost the same bcrypt as a local account now follows the per-IP failed-login budget the login endpoint uses (`RATE_LIMIT_LOGIN_FAILED_PER_IP_PER_WINDOW`), on Basic and on `/v2/token`, which previously answered an unknown username without bcrypt. Refusals are counted in `ak_rate_limit_rejections_total{limiter="basic_password"}`. The SSO/OIDC HTTP client now has a 10 s connect timeout and a 30 s request timeout, so a stalled identity provider no longer holds a login open until the global request timeout.
