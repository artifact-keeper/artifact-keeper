- **Remote repositories can be declared cache-only, serving what is cached and never contacting upstream** (#5282). An operator who seeded a Remote and then disconnected the instance had no way to say so: a miss still tried the upstream (a 60-second stall when a firewall drops packets) and an expired index entry still revalidated. The closest workaround, an upstream filter excluding everything, hid seeded index files once their TTL passed and answered with the filter's reason. `PUT /api/v1/repositories/{key}/upstream-mode` with `{"upstream_mode":"cache_only"}` (Remote-only, repository admin) now makes the Remote serve every cached entry, fresh or stale, with no revalidation; stale serves carry `Warning: 110` and `X-AK-Stale-Since`. A miss answers `404 not in cache; repository '<key>' is cache-only` at once, without upstream contact, and is counted as `ak_proxy_cache_lookups_total{result="cache_only_miss"}`. The mode is enforced at the shared upstream gate, so the npm `/-/` passthroughs and `npm audit`, the curation upstream sync and the `test-upstream` probe honour it too, and a virtual repository skips a cache-only member that lacks the path. Each change is recorded as `REPOSITORY_UPDATED` with `upstream_mode_change`. `PROXY_UPSTREAM_MODE=cache_only` puts every Remote in cache-only mode at once. See `docs/proxy-cache-freshness.md`.
