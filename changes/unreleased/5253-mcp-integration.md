- **MCP registry: one set of gates on every write path, provenance in served entries, and generic API fields** (#5253). The admin edit (`PUT .../versions/{v}`) now runs the publish's `mcp_server_deny`, namespace-grant and lint gates and refreshes the version's lint, declared capabilities and catalog row; soft delete and MCPB bundle upload run the namespace write gate (and the deny list, for uploads). Remote ingest lints every stored version and records its declared capabilities, and every reported or observed capability snapshot has its tools linted onto the server version. `POST /validate` (`/v0` and `/v0.1`) works without a credential on a public registry, as `mcp-publisher validate` expects, and never resolves packages for a caller who cannot read every backing repository. A NuGet package pulled through a Remote whose upstream is a V2 feed now pins. `_meta["com.artifactkeeper.registry/source"]` gains `origin` (`hosted`, `remote`, `mirror`) and `upstreamVerified` (the upstream URL moves to `upstreamUrl`); `mcp_auto_approve_namespaces` entries are globs over the full server name (`io.github.modelcontextprotocol/*`); `/api/v1/packages` rows of MCP servers carry a server.json summary in `metadata`; `/api/v1/formats` advertises `repository_types`; MCP repository responses carry `mcp_caller_can_lock`. See `docs/mcp-registry.md`.
