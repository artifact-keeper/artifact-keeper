- **Configurable trust policy for CEP-27 conda attestations, including key-based Sigstore bundles for on-premises CI** (#4556). Upload verification accepted only keyless bundles whose Fulcio certificate named the GitHub Actions issuer, which a regulated organization's own CI cannot produce. Three settings now define the policy: `CONDA_ATTESTATION_ISSUERS` (comma list of OIDC issuers accepted on keyless bundles; default the GitHub Actions issuer, so existing deployments are unchanged), `CONDA_ATTESTATION_IDENTITIES` (optional comma list of certificate identity patterns, `*` wildcard; empty accepts any identity the issuer vouches for), and `CONDA_ATTESTATION_PUBLIC_KEYS` (comma list of PEM file paths or inline PEM public keys, each optionally `name=`-prefixed). A bundle produced by `cosign attest-blob --key ... --tlog-upload=false --bundle ...` with predicate type `https://schemas.conda.org/attestations-publish-1.schema.json` verifies when its DSSE signature verifies under a configured key (ECDSA P-256/P-384/P-521, Ed25519 or RSA), its in-toto subject names the package and matches the SHA-256 the server computes from the stored bytes, and its statement passes the CEP-27 policy; no Fulcio certificate or transparency log is consulted (a bundle with no tlog entry is expected), so the configured key is the trust anchor. The in-toto Statement may be v1, as CEP-27 specifies, or the v0.1 that `cosign attest-blob` still emits; the version that verified is recorded as `statement_type`. The stored `attestation_verification` record now says how it verified: `method` is `sigstore-keyless` or `sigstore-key`, with `identity`, `issuer`, `statement_type` and, for keys, `key_fingerprint`. `GET /api/v1/attestations/policy` returns `{"require_verified", "issuers", "identities", "keys": [{"id", "name", "fingerprint", "algorithm"}]}` to any authenticated caller; it carries public material only (no key bytes or file paths).
