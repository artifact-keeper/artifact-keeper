- **Instance-wide storage and monthly download transfer quotas, for deployments on metered storage or egress** (#5912). `STORAGE_QUOTA_BYTES` caps the instance's total stored bytes (the `total_storage_bytes` figure). At the quota every write that would store new bytes is refused with `403 STORAGE_QUOTA_EXCEEDED`. That covers every format's publish, OCI blob and manifest pushes (session start, every chunk and completion), the artifact and chunked upload APIs, and replication into the instance. A request that declares a `Content-Length` is refused before its body is read, and a body without a length is refused once its size is known. A remote repository keeps serving upstream content at the quota but stops caching it. Downloads, deletes, listing, sign-in and settings are never refused, and a delete frees its bytes at once. `TRANSFER_QUOTA_BYTES` caps the artifact download bytes per calendar month (UTC). Every replica adds its count to a shared Postgres counter (migration 380). Downloads keep working through `TRANSFER_QUOTA_GRACE_PERCENT` above the quota, and at the hard limit artifact downloads answer `429 TRANSFER_QUOTA_EXCEEDED` with `Retry-After` until the next month; uploads, metadata, the API and the UI keep working. `MAX_UPLOAD_SIZE` is now checked on `Content-Length` before the body is read, and its refusal is a JSON `413 PAYLOAD_TOO_LARGE` with `limit_bytes`. Refusals use the OCI error envelope on `/v2` (`DENIED`, `TOOMANYREQUESTS`, `SIZE_INVALID`), carry npm's `error` field on npm routes, set a short HTTP/1.1 reason phrase, and link `QUOTA_HELP_URL` when it is set. `GET /api/v1/system/quota` (any authenticated user) and `GET /api/v1/admin/stats` report `storage_quota`, `transfer_quota`, `max_upload_bytes` and `quota_help_url`. The metrics are `ak_storage_quota_bytes`, `ak_storage_used_bytes`, `ak_transfer_quota_bytes`, `ak_transfer_used_bytes` and `ak_quota_refusals_total{kind}`. See `docs/operations/instance-quotas.md`.
