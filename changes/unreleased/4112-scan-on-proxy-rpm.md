- **Scan-on-proxy now gates RPM packages from RPM Remote and Virtual repositories** (#4112, part of #4097). With `scan_on_proxy` on, a proxied file on the `/packages/` route or the catch-all (the yum layout dnf fetches) goes through the shared inline scan-and-block gate instead of streaming unscanned, except repository metadata and signing material (`repodata/`, `repomd.xml` and its signature and key, `.treeinfo`, `media.repo`, `RPM-GPG-KEY*`, `.asc`/`.sig`/`.gpg`/`.key`): a vulnerable package is refused with 403 `scan_blocked`, a clean one is served with `X-AK-Scan: clean`, and `fail_open`, `fail_closed` and `record_only` behave as for the other enforced formats. The package's own header must name the name, version, release and architecture of the requested file name, and the package is then graded as itself on the release its dist tag names (`el9` as RHEL 9, `fc40` as Fedora 40, `amzn2023` as Amazon Linux 2023) through a synthetic `etc/os-release`. A package whose header disagrees, lists an identity tag twice, or carries no such dist tag, and any other file that is not an RPM (a `.drpm`, an installer image), is withheld under `fail_closed` (423) without being scanned. On Remote and Virtual RPM repositories, a request path containing `?`, `#`, `;`, `\`, a stray `%`, a space or a control character after decoding is now refused with 400. `GET /api/v1/formats` reports RPM as `scan_on_proxy: "enforced"`, and the generic download route refuses a scanning RPM Remote with 403 `scan_on_proxy_route_required`.
