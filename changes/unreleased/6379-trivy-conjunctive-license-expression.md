section: Fixed
issues: [#6379, #5629]
---
- **A Trivy license list that joins a compound expression with other licenses keeps the expression in the SBOM** (#6379, #5629). The Trivy and Grype license sanitiser (#1152) wrapped every list element it could not read as a single SPDX id as one `LicenseRef-<sanitised>`, so a package whose Trivy `Licenses` were `["MIT AND PSF-2.0", "ISC"]` was stored as `LicenseRef-MIT-AND-PSF-2.0 AND ISC` and exported as a CycloneDX expression with an opaque operand. The #5629 swap only repairs a value that is one wrapped term. An element that is already a valid conjunctive SPDX expression (`AND` or `WITH`, no `OR`, at most 256 characters) is now kept as an expression, so the same package keeps its conjunction. Each operand is canonicalised as a lone term would be, so the exported CycloneDX `expression` names only listed SPDX ids: a known id takes its canonical case (`mit` becomes `MIT`), and an unlisted id is wrapped on its own (`MIT AND Acme-EULA` becomes `MIT AND LicenseRef-Acme-EULA`). `PSF-2.0` is not on that list, so the example is stored as `MIT AND LicenseRef-PSF-2.0 AND ISC`, as a lone `PSF-2.0` already is. When the other scanner stored the same text unwrapped, the SBOM keeps that text, as the #5629 swap already does for a fully wrapped term. This also covers elements with `+`, with parentheses, or longer than the 64-character `LicenseRef-` body. Every license in a conjunction applies, so a policy cannot pass the package on one of them. An element with `OR` is still wrapped, as are prose and oversized fields. Packages that Trivy or Grype list with a single conjunctive element (`MIT AND PSF-2.0`) are now stored as that expression with unlisted ids wrapped alone (`MIT AND LicenseRef-PSF-2.0`), not as `LicenseRef-MIT-AND-PSF-2.0`; rows that are already stored change on the artifact's next scan. There is no setting for this.
