- **A hosted protobuf repository answers the `buf` CLI** (#5066). The CLI speaks Connect with the binary protobuf codec, which axum's `Json` extractor refused with a bare `415 Unsupported Media Type` before any handler ran, so `buf push`, `buf dep update` and `buf generate` could not use a hosted repository at all — only the remote and virtual reverse proxy, which passes those bytes through, worked. All hosted endpoints now decode either codec and answer in the one the request arrived in, and the messages the CLI reads carry what it validates rather than the JSON lookalike's values: ids are tuuids, derived from the module name and commit digest the repository already keys on so no id column or migration is needed, and `Digest` is the b5 digest — SHAKE-256 over the module's file manifest composed with its dependencies' own b5 digests — rather than the SHA-256 the bundle is stored under. A commit's b5 is computed and recorded at push time; a dependency whose b5 this repository does not hold is named in a `failed_precondition` error instead of yielding a digest computed from an incomplete dependency set. Decoding the body turned out to be necessary but not sufficient, and driving a built binary with buf 1.72 found the rest: a single-registry push and a b5 pull go to `buf.registry.module.v1`'s `UploadService` and `DownloadService`, where only the v1beta1 pair (the CLI's federated-push and b4-pull path) was routed; `buf push --create` decides to create a module from a `not_found` on `GetModules`, where an empty list was returned; a reference carrying a derived commit or module id was read as a module name, so `buf dep update` was answered "module not found" for the module it had just pushed; and the `_labels` index row, which shares the module's `name` and is written after the commit, was the row every latest-commit query answered with, which surfaced as a 500 from reading its JSON document as a commit bundle. The JSON request and response shapes are unchanged, except that a reference to a module or commit that does not exist is now the Connect `not_found` the schema calls for rather than a short list. `scripts/native-tests/test-protobuf-buf-cli.sh` pushes and resolves a module with the real CLI and checks the b5 digest it writes into `buf.lock`; it skips when `buf` is not installed.
