- **A hosted protobuf repository answers the `buf` CLI** (#5066). The CLI speaks Connect with the binary protobuf codec, which axum's `Json` extractor refused with a bare `415 Unsupported Media Type` before any handler ran, so `buf push`, `buf dep update` and `buf generate` could not use a hosted repository at all — only the remote and virtual reverse proxy, which passes those bytes through, worked. All ten hosted endpoints now decode either codec and answer in the one the request arrived in, and the messages the CLI reads carry what it validates rather than the JSON lookalike's values: ids are tuuids, derived from the module name and commit digest the repository already keys on so no id column or migration is needed, and `Digest` is the b5 digest — SHAKE-256 over the module's file manifest composed with its dependencies' own b5 digests — rather than the SHA-256 the bundle is stored under. A commit's b5 is computed and recorded at push time; a dependency whose b5 this repository does not hold is named in a `failed_precondition` error instead of yielding a digest computed from an incomplete dependency set. The JSON request and response shapes are unchanged, so existing clients and the curl-driven E2E suite see no difference.
