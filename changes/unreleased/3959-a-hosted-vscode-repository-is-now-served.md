section: Added

- **A hosted `vscode` repository is now served through the VS Code gallery protocol, so a published extension can be found and installed by an editor** (#3956). Every gallery route funnelled through one gate that answered `501` for any repository type except Remote, so an extension published to a hosted repository was reachable only through AK-specific routes no editor speaks — and since an editor has exactly one `extensionsGallery.serviceUrl` (microsoft/vscode#179919), the gallery an operator configures has to serve local extensions too. `gallery_upstream` is split into the gate every route shares (repository type, public-only) and the Remote-specific upstream resolver, and `extensionquery`, the latest-version template, the manifest, the details redirect, `vspackage` and the asset route each answer from the repository's own `artifacts` rows. A version carries the `Microsoft.VisualStudio.Services.VSIXPackage` file entry that installs it, `lastUpdated`, `targetPlatform` where the build is platform-specific, and the engine and pre-release properties. `filterType` 7/4 and 10 select, `pageNumber`/`pageSize` page, `Target` and `ExcludeWithFlags` are accepted as qualifiers, and `flags` decides what each version carries; `TotalCount` counts every match, and an unmatched query is an empty page rather than a 404. Search and paging run in SQL over distinct extension ids and only the page's versions are then read, so a repository with any number of versions lists every extension (one extension's long nightly history cannot push the others off the listing); each extension lists its newest 100 versions, and an older one still installs by its exact coordinates. A version the download gate refuses — quarantined with an unexpired hold, or rejected — is left out of every listing, so an editor is never offered an install that would fail; an expired hold is listed again, as conda's repodata does (#4059).

  **Remote repositories are untouched, and hosted package bytes stay on the route that already served them.** The proxy path — composition, skeleton projection, age gate, metadata budget, URL rewriting — is not reached for a hosted repository. A hosted `vspackage`/asset request redirects to `/vscode/{repo}/extensions/{publisher}/{name}/{version}/download`, so those bytes remain quarantine-checked and download-counted by one code path and no new storage surface appears; any other asset type is a 404. Public-only is unchanged for hosted repositories, for the reason recorded in #3257. Virtual repositories still answer `501`. Two limitations: a hosted repository holds one build per version (the artifact path has no platform component, so a second platform under one version is a `409`), and icon and README assets are not served.
