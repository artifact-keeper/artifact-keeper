- **The scanner adapter can partition trivy's analysis cache per registry host** (#5943). `SCANNER_TRIVY_CACHE_PARTITION_MODE=registry` derives each image scan's cache partition from `SCANNER_TRIVY_CACHE_PARTITION` plus the request's `registry.url` host (scheme, trailing slash and letter case ignored), so one adapter, or one trivy server, can serve several Artifact Keeper instances without one instance's cached layer analysis ever being reused for another instance's scan. The default `static` mode keeps one partition per adapter as before; an unknown mode stops the adapter at startup instead of falling back to a shared partition. Filesystem scans keep the static partition; in registry mode the adapter does not extract a root `.git` from an uploaded workspace, the only case in which trivy reuses a cached filesystem analysis (keyed by the claimed HEAD commit). Nothing changes on upgrade unless the mode is set. The startup log and `GET /api/v1/metadata` report the mode, never a partition value.
