- **Package content analysis: what is actually inside an artifact, and which of it is vulnerable** (#4033, #4037, #4038, #4045, #4047, #4056, #4057). A package's metadata describes what it claims to be; for a compiled package the two barely overlap. A conda package or a Python wheel physically contains C and C++ libraries — libwebp, OpenBLAS, libjpeg-turbo — that its own metadata never names, so a scanner reading metadata alone reports it clean while the vulnerable code sits in the artifact. Ingest now reads the bytes the registry already holds and records what it finds: native libraries recovered from `info/recipe/` (conda) and from `auditwheel`/`delocate` layouts (wheels), and install-time scripts from six formats — conda `post-link`, npm `scripts.postinstall`, RPM `%post`, Debian `postinst`, Alpine hooks, and an sdist's `setup.py`. Those components are then queried against OSV and the GitHub Advisory Database, so a vendored library produces a real finding against a package that declared nothing. Served at `GET /api/v1/artifacts/{id}/package-analysis` and shown in an Analysis tab on the artifact.

  **The distinction the feature is built around is that "we found nothing" and "we never looked" must never render alike.** `completeness` states whether the archive was read at all, and is a required argument rather than an inference from an empty result — a caller that has not decided cannot compile. A script whose declared interpreter the rule engine cannot read (an RPM scriptlet running `<lua>`) is stored with `findings = NULL` and a reason rather than an empty list, and a database CHECK enforces the pairing. Advisories are `null` when no query was possible, `[]` only when the feeds answered and matched nothing. Vendored components carry `soname` and `abi_version` in their own columns and never in `version`: the number in `libwebp.so.7` is an ELF ABI version, and that file ships in libwebp 1.2.4, so promoting it would match the wrong advisories confidently.

  **Install scripts run as the installing user, and on RPM and Debian as root.** The rule engine reads shell text — remote code execution, network egress, credential access, writes outside the install prefix, privilege change, obfuscation, persistence — and recurses into nested interpreters (`node -e`, `python -c`, PowerShell `-EncodedCommand`). Its binding constraint is false positives, not coverage: most install scripts are a `mkdir -p $PREFIX` and a symlink, and a scanner that fires on those gets muted. Two zero-findings assertions guard it, over 16 complete benign scripts and 75 individual lines modelled on real feedstock hooks.
