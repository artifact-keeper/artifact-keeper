- **The builds API returns the VCS fields, metadata and attached artifacts it stores, and honours `sort_by`, without exposing another user's secrets** (#6046, #6240, artifact-keeper/artifact-keeper-web#618). `GET /api/v1/builds` and `GET /api/v1/builds/{id}` answered without `vcs_url`, `vcs_revision`, `vcs_branch`, `vcs_message`, `metadata` and `modules`, although create and attach stored them. Both now return them, with `modules[].artifacts` grouped by module name. `metadata` and the VCS fields (`vcs_url`, `vcs_revision`, `vcs_branch`, `vcs_message`) are returned only to the build's creator and to administrators (the rule that already applies to changing a build). Other signed-in callers get the build without them, as before, and see only the attached artifacts whose path starts with the key of a repository they can read. `vcs_url` never carries credentials. On create, userinfo that is unambiguous (`https://user:token@host/...`, `https://token@host/...`) is removed before the URL is stored. A URL whose userinfo cannot be told apart from its host and path (for example a single-label host with an `@` in the path, such as `https://gitlab/org/repo@v1`) is stored unchanged, so no URL is damaged. Reads apply a stricter rule to every stored URL, including those stored before this release, so a possible credential is never returned. A read returns at most 1000 artifacts per build (50 per build on the list). `artifact_count` still reports the total. `sort_by` takes `created_at`, `started_at`, `finished_at`, `duration` (or `duration_ms`), `name` or `status`. Any other value keeps the build-number order.
