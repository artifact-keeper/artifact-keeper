- **The builds API returns the VCS fields, metadata and attached artifacts it stores, and honours `sort_by`, without exposing another user's secrets** (#6046, #6240, artifact-keeper/artifact-keeper-web#618). `GET /api/v1/builds` and `GET /api/v1/builds/{id}` answered without `vcs_url`, `vcs_revision`, `vcs_branch`, `vcs_message`, `metadata` and `modules`, although create and attach stored them. Both now return them, with `modules[].artifacts` grouped by module name. `metadata` and `vcs_url` are returned only to the build's creator and to administrators (the rule that already applies to changing a build). Other signed-in callers get the build without those two fields, and see only the attached artifacts whose path starts with the key of a repository they can read. `vcs_url` never carries credentials: `https://user:token@host/...` is stored as `https://host/...`, and URLs stored with credentials before this release are returned without them. A read returns at most 1000 artifacts per build (50 per build on the list). `artifact_count` still reports the total. `sort_by` takes `created_at`, `started_at`, `finished_at`, `duration` (or `duration_ms`), `name` or `status`. Any other value keeps the build-number order.
