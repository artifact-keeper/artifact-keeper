- **Repository and project storage quotas now apply to every native format publish, not only the generic upload API, chunked uploads and npm** (#4422). Until now most native publish handlers wrote their artifact rows directly and skipped the check: Alpine, Ansible, Bazel, Cargo, Chef, CocoaPods, Composer, Conan, Conda, CRAN, Git LFS, Go, Helm, Hex, Hugging Face, Incus, JetBrains, Maven, OCI/Docker, Pacman, Protobuf (BSR), Pub, Puppet, RPM, RubyGems, sbt, Swift, Terraform and VS Code. (PyPI, NuGet and Debian already went through the generic upload path.) Their bytes counted toward `quota_bytes` but an upload was never refused, so a repository or project could grow past its cap. Each of these publishes now runs the same two-step admission as the generic route: a preflight before the bytes are written, and the authoritative locked check in the transaction that records the artifact. A refused publish answers `507 QUOTA_EXCEEDED` with `Repository storage quota exceeded` or `Project storage quota exceeded`, and leaves no artifact row.

  Format-specific details: a `docker push` is checked on each blob upload (monolithic and chunked) and on cross-repository blob mounts, and a refusal uses the registry error envelope (`507`, code `DENIED`). A manifest is never refused for quota: its row records the image size, whose bytes were already admitted blob by blob, so it is charged nothing (#4545). A manifest whose descriptors declare a negative or absurd size is now rejected with `400 MANIFEST_INVALID`. A Protobuf (BSR) upload answers a Connect `resource_exhausted` error with status 507. An Incus image upload refuses synchronously when the preflight already fails. When a concurrent upload uses up the remaining space after that preflight, the background finalize marks the upload session `failed` with the quota message. Every other format, including Cargo, Git LFS and Swift, answers the generic JSON body `{"code":"QUOTA_EXCEEDED","message":...}` rather than a format-native error shape. A publish that adds no bytes is always admitted, for example a re-push of a blob the repository already holds or an overwrite with identical or smaller content. Unlimited repositories and projects behave as before. Promotions, migration imports, peer replication and proxy-cache fills are still not checked against the target's quota.

  **Upgrade note.** Before this release only the generic upload API, chunked uploads and npm enforced quotas, so a repository or project could already have grown past its `quota_bytes` through any other format. After upgrading, every publish that adds bytes to such a repository or project is refused with `507` until usage drops below the cap or the quota is raised. Check repository and project usage against their quotas before upgrading. Docker usage counts each manifest's image size on top of the blobs that hold those bytes, and counts it again for every additional tag of the same image (#4545). A capped Docker repository therefore refuses new blobs well before its real bytes reach the cap. Size Docker quotas with that in mind until #4545 lands.
