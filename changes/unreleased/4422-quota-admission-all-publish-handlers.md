- **Repository and project storage quotas now apply to every native format publish, not only the generic upload API, chunked uploads and npm** (#4422). Until now most native publish handlers wrote their artifact rows directly and skipped the check: Alpine, Ansible, Bazel, Cargo, Chef, CocoaPods, Composer, Conan, Conda, CRAN, Git LFS, Go, Helm, Hex, Hugging Face, Incus, JetBrains, Maven, OCI/Docker, Pacman, Protobuf (BSR), Pub, Puppet, RPM, RubyGems, sbt, Swift, Terraform and VS Code. (PyPI, NuGet and Debian already went through the generic upload path.) Their bytes counted toward `quota_bytes` but an upload was never refused, so a repository or project could grow past its cap. Each of these publishes now runs the same two-step admission as the generic route: a preflight before the bytes are written, and the authoritative locked check in the transaction that records the artifact. A refused publish answers `507 QUOTA_EXCEEDED` with `Repository storage quota exceeded` or `Project storage quota exceeded`, and leaves no artifact row.

  Format-specific details: a `docker push` is checked on each blob upload, on cross-repository blob mounts and on the manifest, and a refusal uses the registry error envelope (`507`, code `DENIED`), so no tag is created. A Protobuf (BSR) upload answers a Connect `resource_exhausted` error. An Incus image upload refuses synchronously when the preflight already fails. When a concurrent upload uses up the remaining space after that preflight, the background finalize marks the upload session `failed` with the quota message. Unlimited repositories and projects behave as before. Promotions and proxy-cache fills are still not checked against the target's quota.
