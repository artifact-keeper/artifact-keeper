- **Lowering a remote repository's cache TTL now applies to entries that are already cached** (#3832). The proxy stamped an absolute `expires_at` into each cache entry when it was written and trusted that stamp on every read, so after an operator lowered a remote's TTL (for example from 30 days to 4 hours) every mutable index cached under the old value (PyPI simple indexes, npm packuments, OCI tag manifests) kept being served without contacting upstream until its original expiry, up to 30 days later. Every freshness gate (buffered and streaming reads, the presigned-redirect probe, the key-only cache reads and the APT dists check) now uses one shared rule: a mutable entry expires at the earlier of its stamped expiry and the moment the *current* TTL has passed since it was cached or last revalidated. Immutable artifacts are unaffected. Raising a TTL takes effect from each entry's next revalidation. A `304 Not Modified` revalidation now also updates the entry's `cached_at`. The TTL override is now read through a 30-second in-process cache instead of a database query per read. A TTL change takes effect immediately on the replica that handled the request and within 30 seconds on the others.
