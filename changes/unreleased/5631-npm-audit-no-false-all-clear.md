- **`npm audit` through a Virtual repository is now answered by its npm Remote member instead of reporting "found 0 vulnerabilities"** ([#5631]). A Virtual answered both audit endpoints (`/-/npm/v1/security/advisories/bulk` and `/-/npm/v1/security/audits/quick`) with an empty advisory set, so the usual setup (npm pointed at a Virtual) silently disabled `npm audit` and the audit summary of `npm install`. A Virtual now forwards the audit to the first Remote member, in resolution order and among the members the caller may read, whose upstream answers the audit API, using that member's upstream credentials, egress proxy, upstream filter and scope policy. Nothing is cached, and each upstream call is bounded to 30 seconds. A Remote's own audit uses the same path, so its configured credentials and egress proxy now apply too. When no repository can answer, the audit is an error and npm reports it as one: `501` ("npm audit is not available through repository '<key>'") for a hosted repository, a Virtual with no capable Remote member, or a Remote whose upstream filter or cache-only mode refuses the audit path or whose upstream lacks the audit API; `503` when an upstream was contacted and failed (unreachable, timed out, `5xx`, or an unparseable answer). An empty advisory set is now returned only when a Remote's scope policy leaves none of the requested packages in scope.
