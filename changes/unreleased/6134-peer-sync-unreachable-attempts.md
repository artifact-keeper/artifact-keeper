- **A peer sync push made as the peer drops off the network is no longer lost after its retries run out during the partition** (#6134). Each failed transfer counted toward the task's `SYNC_TASK_MAX_RETRIES` (default 3), and the peer keeps looking online until it is marked down: when its heartbeat goes stale (5 minutes by default), or, with heartbeat probes on, after three consecutive failures. With a short retry backoff, a longer stale threshold or heartbeat probes off, every attempt could fail inside that window. The task was then terminal, and nothing re-queued it when the peer came back, so the peer silently missed the write until the artifact changed or an administrator re-evaluated a policy. A transfer that never connected (connection refused, connect timeout, name resolution failure) no longer uses up one of the task's attempts. It is still charged to the peer: it backs the peer off, counts toward its consecutive failures and can demote it to `degraded`. The task is retried once the peer is online and out of backoff again, so it is delivered after the heal. A peer that answers with an error, and a request that times out or is reset after it was sent, still use up an attempt as before. Unreachable attempts are bounded in time: a task that has not reached its peer for more than `SYNC_TASK_UNREACHABLE_MAX_SECS` (default `86400`, 24 hours) is failed for good on its next attempt. Its error then starts with `peer unreachable for more than`. This covers a peer that looks online but never accepts a connection from this instance. The new counter `ak_sync_task_unreachable_failures_total{outcome="retrying"|"exhausted"}` counts these failures. A send error on a chunked upload's session request is now charged like any other, instead of leaving the task claimed until its claim lapses. Migration `419` adds the nullable column `sync_tasks.unreachable_since`. To restore the old rule of three attempts for any failure, there is no switch; set `SYNC_TASK_UNREACHABLE_MAX_SECS=60` for the shortest bound. See [docs/operations/peer-sync-retries.md](docs/operations/peer-sync-retries.md).
