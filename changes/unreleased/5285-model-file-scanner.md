- **Model files uploaded to `huggingface` and `mlmodel` repositories are now scanned for executable pickle payloads and malformed headers** (#5285, #3013). A new in-process `model` scanner, which needs no sidecar or network access, walks the pickle opcode stream of `.bin`, `.pt`, `.pth`, `.ckpt`, `.pkl`, `.pickle` and `.joblib` files (and the `data.pkl` of a zip-wrapped PyTorch archive) without executing it, and classifies every `GLOBAL` / `STACK_GLOBAL` / `INST` import: a code-execution primitive such as `os.system`, `subprocess.*` or `builtins.eval` is a critical `malicious` finding, and any import outside the weights-only allowlist is a `policy` finding naming it. It also reports malformed, truncated or overlapping safetensors headers and malformed GGUF headers, implausible counts and oversized chat templates. Every finding carries a stable rule id (for example `model.pickle.dangerous-global`) in `affected_component`. Parsing is bounded throughout and never reads tensor data. A `.safetensors` file stored in a `huggingface` repository through the generic or chunked upload API now also records its header summary in `artifact_metadata`, as `mlmodel` uploads already did. Proxied files are not judged yet. See `docs/security/model-file-scanning.md`.
