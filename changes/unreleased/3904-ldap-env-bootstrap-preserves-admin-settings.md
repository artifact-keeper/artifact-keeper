- **The `LDAP_*` environment bootstrap no longer undoes admin-API changes to the env-managed LDAP provider on every restart** (#3904). The per-boot reconcile used to write every field it derived and force `is_enabled`, `priority` and (with `LDAP_USE_STARTTLS` unset) `use_starttls` back to hard-coded values, so disabling the provider, raising its priority or enabling STARTTLS through the admin API silently reverted on the next boot. It now follows the same ownership rule as the OIDC bootstrap (#3507): a field an `LDAP_*` variable sets is written, a field the environment set on the previous boot and no longer sets is reset to its default, and every other field keeps its stored value. `is_enabled`, `priority` and the per-provider TLS options are never touched after the provider is created. `LDAP_ADMIN_GROUP_DN` stays env-definitive, like `OIDC_ADMIN_GROUP`: unsetting it clears the admin group. A field changed through the admin API stops being env-owned, so removing its variable later keeps the admin's value. Every stored value a boot overwrites or removes is logged at WARN, with a dedicated warning when STARTTLS is being turned off. Clearing the admin group does not demote users already granted admin. Ownership is recorded in the new `ldap_configs.env_owned_fields` column (migration 255).
