- **Optional FIPS 140-3 mode for regulated deployments** (#5578, #5579, #5580, #5582, #5583, #5584, #5585; epic #5577). The backend now links a single cryptographic provider, AWS-LC via `aws-lc-rs`, for every TLS client (HTTP, Postgres, Redis, LDAP, SMTP, OpenSearch) and every security function; ring, OpenSSL and native-tls are gone from the dependency graph and CI refuses their return (#5578). All security cryptography goes through one facade (`backend/src/crypto/`) that clippy confines the rest of the code to (#5579). A new `FIPS_MODE` setting (`off` by default, `warn`, `strict`) gates startup: `warn` reports what `strict` would refuse in `/health` and the log, `strict` requires a `-fips` build and refuses non-approved configuration (#5580). The `-fips` image and binary variants are built against the AWS-LC FIPS module (#5581). In strict mode, passwords are hashed with PBKDF2-HMAC-SHA512 and API tokens stored as keyed HMACs, with legacy bcrypt rows verified and migrated on use (#5582); stored secrets are encrypted under a dedicated data key with per-purpose subkeys (#5583); SAML responses signed with SHA-1 are refused (#5584); webhook, plugin, storage and digest primitives run on the module (#5585); repository signing keys are generated and used inside it (#5586). With `FIPS_MODE` unset nothing changes: the existing test suite passes unchanged and no new storage format is written, so an upgrade followed by a downgrade is safe. Operator guide: `docs/fips.md` (#5587).
