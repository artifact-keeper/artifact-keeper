- **CHANGELOG entries are now one fragment file per PR under `changes/unreleased/`, assembled into `CHANGELOG.md` only when a release is cut** (#4016). Every PR used to add its bullet at the top of the same `## [Unreleased]` subsection, so two open PRs always conflicted on `CHANGELOG.md` even though both entries were wanted: 76 % of merges to `main` touched the file, every currently conflicting PR conflicted on it, and 69 % of force-pushes landed within an hour of a merge, each one re-running the full CI pipeline for a rebase that changed nothing. A PR now adds `changes/unreleased/<issue>-<slug>.md` — `section:` and `issues:` front matter over the bullet exactly as it reads in the changelog — and no two PRs touch the same file. `scripts/release/assemble-changelog.sh` renders the fragments into the new `## [X.Y.Z] - <date>` section at the release prep, in Keep a Changelog section order and a deterministic entry order, and deletes them; `--check` previews the section. `check-changelog-unreleased.sh` validates every fragment (name, section, a non-empty `issues:` list the body cites, exactly one bullet), `check-changelog-placement.sh` validates the fragments a PR adds and no longer fails a release prep for the bullets it assembles, release preflight check 5 reconciles unassembled fragments alongside `## [Unreleased]`, and the release-hygiene exemptions and the Release-Bump Gate accept the fragment directory. The 37 entries pending under `## [Unreleased]` were moved into fragments byte for byte.

  **Transition.** A PR that still adds a bullet under `## [Unreleased]` passes CI (with a notice), and the assembler merges those bullets with the fragments at the cut, so PRs opened before this change do not need rewriting — though they will conflict once more against the emptied section.
