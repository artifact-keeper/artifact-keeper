- **A releases repository took a SNAPSHOT deploy and a snapshots repository took a release: Maven and Gradle hosted repositories now have a version policy** (#5872). A misrouted deploy made a releases repository mutable for that coordinate or put a release under snapshot cleanup. `version_policy` (`mixed`, `release` or `snapshot`) is set on create and update of a local or staging Maven or Gradle repository and returned on its GET. Under `release` a path in a `-SNAPSHOT` version directory is refused with 400 `Repository '<key>' accepts release versions only`, under `snapshot` a release version is refused the same way, artifacts, POMs, checksums and version-level metadata alike. Group and artifact level `maven-metadata.xml` is accepted under every policy. The policy holds on the Maven deploy route, the generic artifact upload, chunked upload sessions (so peer replication too, below and above its chunked threshold), promotion, approval and the migration import. Setting a policy other than `mixed` on a Remote, a Virtual or another format is a 400 that leaves the rest of the update unwritten. Upgrade note: migration 408 adds the column with `mixed` for every existing repository, so nothing changes until a policy is set. The Nexus and Artifactory importers don't map the source repository's policy yet and the web form has no field for it. Contributed by @nicola-preda.
