- **An artifact that no scanner could inventory is reported as not cataloged even when grype is absent, including archives in generic repositories** (#4154). The "cataloged nothing" signal came only from grype, so on a deployment without it, or for an archive in a generic repository, a scan that assessed nothing completed as clean. The decision is now made over the whole set of scanners: when none of them found a finding, a package or a component, the scan is `not_cataloged` with a reason and the repository reports `has_uncataloged_scan`. The repository grade letter is floored to F only for packages, as before: every package in a typed repository and package-shaped archives (`.whl`, `.jar`, `.war`, `.ear`, `.gem`, `.crate`, `.nupkg`, `.egg`, `.conda`) in a generic one. A plain `.zip`, `.tar.gz`, `.tgz` or `.tar.bz2` in a generic repository (documentation bundles, build outputs, installers) is flagged without changing the grade. A not-cataloged result is never reused for another upload of the same bytes, and a reused scan now carries its source's completeness. Scan results in the API now include `scan_completeness` and `scan_completeness_reason`, so a flagged or floored repository shows why.
