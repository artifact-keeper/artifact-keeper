- **The MCP registry, air-gapped, Hugging Face and disconnected-operation pages now match the code on main** (#5369). `docs/mcp-registry.md` said an anonymous read of a private registry gets the plain `404`. It actually gets `401 mcp_unauthorized` with the `WWW-Authenticate` challenge from the repository visibility middleware; only an authenticated caller with no grant gets the `404`. The page also said a pinned OCI digest is freed by trashing the server version's artifact through the artifact API, which the generic artifact `DELETE` has refused on MCP repositories since #5257. It now says plainly that a digest stays pinned unless the whole MCP repository is deleted, and links #5368, which proposes an admin path. `docs/air-gapped.md` now describes the merged cache-only Remote mode (`PUT /api/v1/repositories/{key}/upstream-mode`, `PROXY_UPSTREAM_MODE`), cache seeding (`POST /api/v1/repositories/{key}/cache/seed`, `paths` only), the scanner-adapter's `SCANNER_OFFLINE` and `PUT`/`GET /api/v1/vulndb` (with `SCANNER_ADAPTER_TOKEN`), the `UPSTREAM_JOBS_PAUSED` switch and its runtime setting, `UPSTREAM_FETCHED` with `AUDIT_UPSTREAM_FETCHES=all` in the verification checklist, config export and plan/apply for the high side, and the MCP Remote sync, instead of calling them planned. `docs/huggingface.md` drops the limitation that a Remote tree listing loses its query (fixed by #5321) and notes that commit-pinned paths are immutable cache entries (#5283). Documentation only; no behaviour change.
