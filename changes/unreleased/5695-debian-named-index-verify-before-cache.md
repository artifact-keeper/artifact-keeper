- **A Debian Remote under `fail_closed` scan-on-proxy no longer serves a package graded on a `Packages` index its `Release` does not name** ([#5695]). Since 1.12.0's suite-scoped grading ([#5170], [#5228]) the gate fetches the index a cached `Release` names when no client has, but it committed the fetched bytes to the proxy cache before comparing their SHA-256 with the `Release` entry, and on later pulls it read any cached plain (non-`by-hash`) index without checking it against the `Release` at all. A tampered or mismatching upstream index was therefore refused on the first pull (423) and trusted on every pull after it, so the package was graded on that suite's release and served 200, while a client fetching the same index got 502 from the existing integrity check. The gate now caches a named index only once it hashes to the digest the `Release` names (a cached copy that does not is evicted and fetched again), and reads a cached index only when the suite's currently cached `Release`/`InRelease` names its digest, taking the release it grades on from that same document, so an index a newer `Release` no longer names decides nothing either. A cached `Release` with no SHA256 table (which every Debian and Ubuntu `Release` carries) now vouches for no index, so it names no release for a pool file. Every pull in that case stays 423 under `fail_closed` (pending under `fail_open`).
