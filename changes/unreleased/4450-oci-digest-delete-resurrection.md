- **An OCI image deleted by digest no longer comes back after a restart** (#4450). `DELETE /v2/<name>/manifests/<digest>` removed every tag and index row for the digest but soft-deleted only the `artifacts` row at the digest path, so the tag's own row (`v2/<image>/manifests/<tag>`) stayed live. On the next start, the OCI migration reindex took that row for a never-indexed migrated manifest and re-registered the tag, its child refs and its `oci_manifests` record: an image an operator had deleted, for example a compromised one, was pullable again after any restart or rollout. A delete by digest now soft-deletes every manifest row in the repository whose bytes are that digest, tag rows included, in the same transaction as the index unwind (a failure rolls both back; the soft-delete error used to be dropped). The startup reindex also skips a live manifest row when the same manifest was deleted by digest after that row was last written, so a row left behind by an older replica during a rolling upgrade is not revived either. Deleting by tag name is unchanged, and a child manifest still listed by another tagged index stays. An image deleted by digest on an earlier release that was pushed only by tag leaves nothing to tell it apart from a migrated manifest, so a restart (including the upgrade itself) may still revive it; check images deleted by digest before upgrading and delete them again afterwards.
