- **Virtual repositories answer `404` for a member's permanent upstream `4xx` and `503` only when a member is temporarily unavailable, on artifacts and checksums alike** (#5504). The Maven virtual checksum walk counted every non-`404` member answer as a failure, so a Remote member whose upstream answers `403` for a missing key (S3-hosted Maven buckets do) or `401` for stale credentials turned every `.sha1`/`.md5` no member has into a `503` that clients retried forever. A permanent upstream `4xx` or a rejected path is now a miss. A member counts as unavailable for an upstream `5xx`, for the retryable `408`, `425` and `429` (rate limiting), for a timeout or transport failure, or for a fault on the server's own side. On the checksum walk only, a hosted member that has the artifact row but whose storage read fails also counts as unavailable, where it read as a miss; hosted members on the artifact walk are left to a follow-up issue. The shared artifact walk behind most formats' virtual downloads (Maven, sbt, npm, Cargo, Conda, Debian, Go, Composer, Hex, Alpine, Chef, Git LFS, JetBrains, Protobuf, Terraform, VS Code, the generic `/download/` and `/general/` routes, and the scan-aware walks of Cargo, Conda, VS Code, Conan, CocoaPods, Pub, Swift and RubyGems, including members that scan on proxy) used to read a member's upstream `5xx` as a miss, so `lib-1.0.jar` answered the `404` Gradle caches while `lib-1.0.jar.sha1` answered `503`. It now passes over an unavailable member exactly as over a missing one, still serves from a lower-priority member that has the file, and answers `503` instead of `404` only when nothing served and a member was unavailable. A member's quarantine or policy block, and a Maven or Go member's age refusal, still take precedence.
