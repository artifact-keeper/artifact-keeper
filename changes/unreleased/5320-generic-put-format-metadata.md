---
section: Fixed
issues: [#5320, #5254]
---
- **A package uploaded through the generic `PUT /api/v1/repositories/{repo}/artifacts/{path}` endpoint is now named, described and indexed exactly as its format's own upload route records it** (#5320, #5254). The endpoint used to take the artifact's name and version from the first two path segments and record no format metadata (except an RPM's header), so an Alpine package at `v3.24/main/x86_64/nginx-1.30.6-r0.apk` was listed in `APKINDEX` as `P:v3.24` / `V:main`, a Maven jar was missing from `maven-metadata.xml`, and npm and Debian packages lost their dependencies. A package at its format's native layout path now gets the same parse its native route runs, before anything is stored: Alpine (`APKINDEX`, identity from the package's `.PKGINFO`), Debian (`Packages`), Maven (`maven-metadata.xml`), npm (the packument), PyPI (the simple index), RPM and Incus (`images.json`). A package the native route refuses (a control file, `package.json` or wheel `METADATA` that names another package or version than the path) is refused with 400 and nothing is stored; an unreadable `.apk` is stored unindexed, as the native route stores it. Any other file, and any package of another format, uploads exactly as before. Packages uploaded before this change keep their rows; upload them again (or through the native route) to re-index them.
