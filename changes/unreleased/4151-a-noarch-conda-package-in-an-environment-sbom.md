section: Fixed
issues: [#4151]
---
- **A `noarch` conda package in an environment SBOM now carries `subdir=noarch`, the identity its own artifact has, instead of the platform of the scope it was resolved into** (#4151). `environment_sbom::package_purl` built every conda member's #4041 qualified purl with `CondaPurl::from_index(name, version, build, scope.platform)` — the fourth argument is the package's *subdir*, and `LockedPackage` carried no subdir at all, so the scope's platform was the only thing available to pass. A `noarch` build resolved into a `linux-64` environment was therefore emitted as `…?subdir=linux-64` while the same build ingested as an artifact gets `subdir=noarch` from its `info/index.json`, so the environment membership and the artifact it names never joined, and one `noarch` build appearing in N platform scopes became N distinct bom-refs. `LockedPackage` now carries the package's own `subdir`, recorded by both conda lockfile parsers: `pixi.lock` from its `subdir`/`platform` field or, for the v6 schema that has neither, from the channel URL; `conda-lock.yml` from the channel URL, deliberately *not* from its per-entry `platform`, which names the graph the entry belongs to rather than the subdir it was built for. A subdir inferred from a URL is accepted only when it is a recognised conda subdir, so a package installed from a local directory contributes none. The scope platform remains the fallback for a lockfile that records no subdir — and for one that records a subdir `CondaPurl` rejects, so a malformed field costs a component no identity it had before. The identity rules in `conda_identity` are unchanged; the two derivations now agree by construction.
