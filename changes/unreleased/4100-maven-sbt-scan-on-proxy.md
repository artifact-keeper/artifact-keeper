- **Scan-on-proxy now gates every proxied Maven, Gradle and sbt download except a short allowlist of metadata files** (#4100, part of #4097). With scan-on-proxy enabled on a Remote `maven`/`gradle` repository (or an `sbt` repository on the `/ivy` route), every proxied file except POMs, `.xml` metadata, Gradle `.module`, checksums, signatures and `-sources`/`-javadoc` jars now goes through the shared inline gate. This covers `.jar`/`.war`/`.ear`, and also `.zip`, `.tar.gz`, `.aar`, `.klib`, `.so` and other native or distribution bundles, which were previously served unscanned. Under `fail_closed`, any of these files returns `423` when no scanner is available or when it is larger than the 200 MiB scan cap (large distributions included); under `fail_open` it is served with `X-AK-Scan: pending`. For gated files: a vulnerable archive is refused with `403 scan_blocked`, a clean one is served with `X-AK-Scan: clean` and its verdict reused on the next pull, and fail-open (`X-AK-Scan: pending`), fail-closed (`423`) and the severity threshold behave as they do for npm and PyPI. Virtual repositories apply the stricter of the virtual's and the member's policy per Remote member, and a member's `403`/`409`/`423` ends the walk instead of falling through to the next member. If the scan configuration cannot be read, the virtual walk fails closed with `503`. The allowlist is matched case-insensitively on the same normalised path the proxy cache uses (`-sources`/`-javadoc` jars are skipped based on the classifier in their name), and unknown extensions and odd suffixes are scanned. A `.jar`/`.war`/`.ear` that names a Maven coordinate gets an identity pin; anything else is scanned without one. Known gap: the scan workspace does not unpack `.aar`, `.hpi`/`.jpi`, `.nbm`, `.jmod`, `.rar` or `.zip`, so those are graded only from what the engine reads in the raw file. On Remote and Virtual `maven`/`gradle`/`sbt` repositories (whether or not scan-on-proxy is on), a proxied path containing `?`, `#`, `;`, `%`, a space or a control character after decoding, or ending in `.`, or one that places a metadata file under a segment named like an archive (`.../widget-1.0.jar/x.pom`), is now refused with `400`, because an upstream could read such a path as a different file than the one classified and cached. The archive's identity is taken from the request path and pinned only when the archive's own `META-INF/maven/<groupId>/<artifactId>/pom.properties` agrees; archives without one (typical of Gradle- and sbt-built jars) are scanned without the identity check. `GET /api/v1/formats` now reports `maven` and `sbt` as `scan_on_proxy: "enforced"`. The buffered path keeps the `.sha1` sidecar check: a body that disagrees with its sidecar is evicted from the proxy cache and refused with `502`, the same way Cargo handles a `cksum` mismatch. If the eviction fails twice, the pull is refused with a retryable `503` instead. A `record_only` repository (#3645) is scanned and recorded and serves every pull with `X-AK-Scan: recorded`.
