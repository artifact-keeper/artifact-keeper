section: Fixed
issues: [#5064, #4989, #5004]

- **Download verification now holds a bounded amount of memory: small stored objects checked before their status is sent share one 256 MiB budget, and a download that finds it full is checked while it streams instead** (#5064, #4989, #5004). Verifying stored bytes before the response status (#4323) reads an object of up to 4 MiB whole and keeps it until the client has read it. That covers the generic download route, OCI blob pulls, every virtual-member serve and the hosted routes on the shared fetch. The global concurrency limit does not bound those buffers, because a request's permit is released when its response starts and the body is sent afterwards. The total was therefore set only by how many connections clients kept open. The buffers now draw on one process-wide budget, `AK_SERVE_VERIFY_BUFFER_BUDGET_BYTES` (default 256 MiB), separate from the proxy-metadata budget. A serve reserves its object's size in 4 KiB units and gives it back once its body has been read or dropped. A serve that finds no room never waits: it is verified while it streams, as an object over 4 MiB always is, so a corrupt object is still never delivered complete, but the transfer is aborted instead of answered `502`. `ak_serve_verify_buffer_bytes_reserved` and `ak_serve_verify_buffer_fallback_total` report the budget's use. A `HEAD` that the generic route answers through a virtual repository's hosted member now reads nothing, as a `HEAD` answered from the artifact row already did.
