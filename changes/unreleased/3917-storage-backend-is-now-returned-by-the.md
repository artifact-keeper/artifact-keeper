- **`storage_backend` is now returned by the repository read endpoints** (#3917). The field was accepted on `POST /api/v1/repositories` and immutable from then on, but no read path echoed it back: `RepositoryResponse` had no such member, so it was absent from the `ToSchema`-generated OpenAPI document and from the live JSON of both `GET /api/v1/repositories/{key}` and the `GET /api/v1/repositories` listing. The practical effect was that the one repository property an operator can never change after creation was also the one they could not ask the API about — a deployment mixing `filesystem`, `s3` and `azure` repositories had to infer placement from `STORAGE_BACKEND` and creation-time records. It is read straight off the repositories row (`VARCHAR(50) NOT NULL DEFAULT 'filesystem'`), so like `curation_enabled` it is always concrete and needs no second lookup, and it is a plain non-skipped field, so it is present on every repository in both the single-repository and listing responses. The same argument the `curation_enabled` comment already makes applies here: state that is stored and enforced but cannot be read back is its own class of problem.
