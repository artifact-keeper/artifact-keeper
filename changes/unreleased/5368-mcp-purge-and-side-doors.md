- **MCP registries get an administrator purge for a deleted server version, and the generic and lifecycle side doors are closed** (#5368). A service account sending the client-set `x-artifact-keeper-replication: true` header could write a server.json into an MCP repository through the generic artifact upload routes (claiming a `name@version` in another team's namespace with an unvalidated, unpinned document) or trash another namespace's server.json through the generic `DELETE`, and a lifecycle policy attached to an MCP repository could trash server.json rows, releasing their OCI pins without the MCP delete's audit or `isLatest` recompute. On an MCP repository the replication exemption now needs an instance administrator's token (how peer links are set up; peer replication keeps working), a service account is refused with `400`, and lifecycle policies skip MCP repositories (a preview says so). Releasing a pin is now a supported, audited step: `POST /mcp/{repository}/v0.1/servers/{serverName}/versions/{version}/purge` (instance administrators only, on a version already soft-deleted, `409 mcp_version_not_deleted` otherwise) trashes the version's server.json and bundles, recomputes `isLatest`, keeps the tombstone so the version can never be republished, and audits `MCP_SERVER_PURGED` with the released digests. The OCI `405` for a pinned digest names this route.
