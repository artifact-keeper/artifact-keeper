- **The trace sampler is now configurable via `OTEL_TRACES_SAMPLER` / `OTEL_TRACES_SAMPLER_ARG`** (#4029). The SDK default was hard-wired, so an operator had no way to reduce trace volume short of turning tracing off. All six values from the OpenTelemetry specification are accepted — `always_on`, `always_off`, `traceidratio`, `parentbased_always_on`, `parentbased_always_off`, `parentbased_traceidratio` — parsed case- and whitespace-insensitively. **The default is `parentbased_always_on`, which is both the specification's default and the SDK's previous behaviour, so a deployment that sets neither variable samples exactly as it did before.** An unrecognised sampler name falls back to that default rather than failing startup, and the resolved sampler is logged at boot so a typo is visible rather than silent. `OTEL_TRACES_SAMPLER_ARG` is the ratio for the two `traceidratio` forms; an absent, unparseable, out-of-range or NaN value falls back to `1.0` rather than `0.0`, because a misconfigured ratio behaving like `always_on` is a far better failure than one that silently drops all telemetry. Note the interaction with the trace-context adoption below: under the default sampler a caller's `traceparent` can only suppress its own trace, but under `parentbased_traceidratio` or `parentbased_always_off` an untrusted `sampled=01` can force export of a trace the sampler would otherwise have dropped — an operator choosing either on a publicly reachable deployment should gate trace-context extraction on their trusted-proxy range, which is a follow-up.
