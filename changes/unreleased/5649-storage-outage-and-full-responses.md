---
section: Fixed
issues: [#5649, #5650]
---
- **A storage outage now answers `503` within seconds, and full storage answers `507`, instead of hanging or a `500` that echoed the object store's error** ([#5649], [#5650]). With MinIO stopped, every upload and download blocked until it came back: each attempt to reach the gone host waited out a 5-second connect timeout and the S3 client kept retrying for up to three minutes, so clients gave up on their own timeouts with no answer. Storage requests are now bounded by `STORAGE_CONNECT_TIMEOUT_SECS` (default 3), a 2-second cap on the pause between retries, a control-plane retry budget of `STORAGE_OPERATION_TIMEOUT_SECS` (default 15) and, for uploads and downloads, a fixed retry count under `STORAGE_BULK_RETRY_TIMEOUT_SECS` (default 180, long enough that a long transfer keeps its retries). An unreachable or timed-out store answers `503 STORAGE_UNAVAILABLE` with `Retry-After` (OCI: `503 UNAVAILABLE`) within about 15 to 30 seconds; GCS 5xx and rate/usage-quota answers now give the same code with a fixed message instead of echoing the GCS body. A write refused for lack of space (a MinIO bucket quota, an S3-compatible `QuotaExceeded`, HTTP 507, a full filesystem) answered `500 STORAGE_ERROR`, and `docker push` printed MinIO's XML error with the bucket name and request ids; every route, the OCI `/v2` envelope included, now answers `507 STORAGE_FULL` (OCI: `507 INSUFFICIENT_STORAGE`) with a fixed message (the class comes from the response status and exact error code, never the message text, so an object named after an error code cannot change it), and no object-store error text (an XML error document, the raw S3 error) reaches a client on any `/v2` 5xx. The package routes that answered a storage failure as `500 Storage error: <raw error>` (Bazel, CRAN, Composer, Hex, Pacman, RubyGems, Puppet, RPM, PyPI, Helm, Ansible, the Maven proxy, Hugging Face) now answer `503`/`507`/`500 STORAGE_ERROR` with a fixed message, and their out-of-space `507` is decided by the storage error's class instead of its wording. The storage health probe is bounded to 2 seconds, `/health` reports storage unhealthy for 60 seconds after a write is refused for lack of space, and `/readyz` lists unhealthy non-gating dependencies under a new `degraded` field while staying ready. See `docs/operations/health-probes.md`.
