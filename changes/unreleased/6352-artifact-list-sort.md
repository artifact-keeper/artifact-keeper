- **The artifact list can be sorted by size or creation time on the server** (#6352, #5040). `GET /api/v1/repositories/{key}/artifacts` takes `sort_by` (`path`, the default, `size` or `created_at`) and `sort_order` (`asc` or `desc`) and orders the whole listing before paging, so the largest or newest artifacts of a repository are on the first page, not the largest of the page the browser happened to hold. Ties break on the row id, so the `next_cursor` walk has no gaps or repeats, and a cursor is only accepted with the order that produced it. Hosted repositories and a virtual with one member sort. `group_by` listings, Remote repositories and a virtual with more than one member list by path only and answer 400 to any other order. Migrations 424 and 425 add two partial indexes on `artifacts`, `(repository_id, size_bytes, id)` and `(repository_id, created_at, id)`, so a sorted page does not read the whole repository. Both are built `CONCURRENTLY`, uploads keep going while they build.
