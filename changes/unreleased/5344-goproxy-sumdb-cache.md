- **A Go Remote now caches the checksum database it answers under `sumdb/<host>/...`, so `go` verifies seeded modules with the checksum database out of reach** (#5344). The route used to forward every request to `sum.golang.org` uncached, so a module missing from `go.sum` failed verification offline even when the module itself was cached. Answers now go through the Remote's proxy cache: tiles and `lookup/<module>@<version>` are immutable entries, and the signed tree head `latest` is mutable (revalidated after the cache TTL, served stale within the stale-if-error grace when the checksum database is down, and served as it is in cache-only mode). The upstream filter (matched against the absolute `https://<host>/...` URL) and cache-only mode apply as for other Remote fetches, the fetches are recorded as `UPSTREAM_FETCHED` audit events, and a Virtual repository caches through its Remote members. The host allowlist is unchanged and the Remote's upstream credentials are never sent to the checksum database. On Remote and Virtual repositories a sumdb path containing `?`, `#`, `;`, `\`, a stray `%` or a control character is refused with `400`. A Hosted Go repository keeps the uncached pass-through. See "Format notes" in `docs/air-gapped.md`.
