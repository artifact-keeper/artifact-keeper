- **Download tickets now carry the repository restriction of the credential that minted them, and redeeming a valid ticket works again** (#4588, GHSA-2mfv-xg68-gq4p). `POST /api/v1/auth/ticket` stored only the user, so a redeemed ticket was rebuilt from the user account with access to every repository the user could reach. A token restricted to some repositories could therefore mint a ticket for a repository outside its restriction. This was latent: the user lookup at redemption selected a fixed column list that no longer matched the user model, so it failed and every ticket was treated as anonymous. That also broke the web UI's `?ticket=` downloads and streams and the Terraform provider mirror's ticketed archive URLs (#3588). In addition, a path-bound ticket was compared against the nest-stripped request path on `/api/v1/...` routes, so it could not match there. All three are fixed together. A ticket now records the minting credential's repository restriction (migration 286), and redemption restores it, so a ticket never reads more than its minter could. The user lookup reads the whole row. The bound path is compared with the full request path. Minting a ticket now requires the `read:artifacts` token scope, which interactive sessions always have. Tickets minted before the upgrade carry no recorded restriction and are refused. They expire within minutes, so a client only has to mint a new one.
