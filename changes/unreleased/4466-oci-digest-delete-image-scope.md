- **Deleting an OCI manifest by digest no longer deletes the same manifest under other image names in the repository** (#4466). `DELETE /v2/<repo>/<image>/manifests/<digest>` removed the digest's tags under every image name in the repository, so deleting `xa@<digest>` also removed `xb:v1` when both pointed at the same manifest, and since the #4450 fix the tag rows of the other names were soft-deleted too, so the loss survived a restart. In the distribution spec `<name>` is `<repo>/<image>`, so the delete now removes only `<image>`'s tags and `<image>`'s manifest rows (canonical and migrated source-layout paths); the same digest stays pullable under every other image name. The manifest's shared records (index edges, blob references, the referrers subject edge and its `oci_manifests` row) still go only when no tag of any image name in the repository points at the digest. The startup reindex's "deleted by digest" guard is scoped the same way, so a delete under one image name never stops the repair of another. Because AK resolves a digest across the whole repository, `<image>@<digest>` keeps resolving after the delete while another image name in the repository still tags that digest.
