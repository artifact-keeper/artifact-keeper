- **A `HEAD` on a Maven, npm, PyPI, OCI or other Remote no longer downloads the file from upstream and throws it away** (#5343). The fix for #5322 covered the formats served through the shared Remote download path; the handlers that stream their own Remote downloads still answered a cold `HEAD` by opening an upstream `GET` of the whole file and dropping the body unread, which cached nothing, so the `GET` that followed downloaded the file a second time. Clients that probe before they download (Maven Resolver, Gradle, `docker pull`, containerd, skopeo) paid double egress for every new artifact. A cold `HEAD` is now answered from an upstream `HEAD` with the headers the `GET` would send (`Content-Length`, `Content-Type`, `ETag`, `Content-Encoding`, and the format's own: `Docker-Content-Digest`, Maven's `X-Checksum-SHA1`, the attachment file name), and a cached file is answered from the cache as before. An upstream that refuses `HEAD` gets the `GET` path. Covered: Maven, Gradle, sbt, npm (Remote tarballs and a Virtual's last-known-good substitution), PyPI, Cargo, NuGet, Conda, Debian, Alpine, Helm, Go, Composer, Conan, CocoaPods, Swift, Pub, Chef, JetBrains, VS Code, Git LFS, Terraform providers and mirror archives, RPM packages, Bazel, the generic repository download route, and OCI blobs on a Remote and through a Virtual.
