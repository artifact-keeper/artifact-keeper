section: Security
issues: [#5991]

- **The backend image no longer contains `krb5-libs`, so the 14 HIGH `krb5-libs` CVEs are gone from it rather than suppressed** (#5991). `krb5-libs` was in the image only because the UBI 9 `curl-minimal` RPM pulls in `libcurl`, which links Kerberos (and, through the full `libcurl`, `libssh`, `openldap` and `cyrus-sasl-lib`). The image now ships its own `curl` at `/usr/bin/curl`, built from the signed curl 8.23.0 release with `libcurl` linked in statically, so existing compose healthchecks and `docker exec … curl` probes keep working, and 27 RPMs leave the image. That `curl` still speaks HTTP and HTTPS through OpenSSL, including HTTP/2. It no longer supports Kerberos/Negotiate or NTLM authentication, LDAP, SCP/SFTP, brotli or zstd decoding, IDN hostnames, PSL cookie checks, or the telnet, tftp, gopher, dict, IMAP, POP3, SMTP, MQTT, RTSP and IPFS protocols. The image `HEALTHCHECK` checks the same thing as before, `GET /health`, but now runs it through a new `artifact-keeper healthcheck [URL]` subcommand instead of curl. With no argument the subcommand probes `/health` on the address in `BIND_ADDRESS`, read exactly as the server reads it. It also accepts another path, such as `/livez`, or an `http://` URL. It needs no configuration of its own, finishes within 9 seconds, exits 0 on a 2xx response, and exits 1 otherwise, so a backend whose database is down still reports unhealthy. It needs a 1.12.0 or later image: a compose file pinned to an older tag must keep its curl-based healthcheck.
