- **The backend image no longer contains `krb5-libs`, so the 14 HIGH `krb5-libs` CVEs are gone from it rather than suppressed** (#5991). `krb5-libs` was in the image only because the UBI 9 `curl-minimal` RPM pulls in `libcurl`, which links Kerberos (and, through the full `libcurl`, `libssh`, `openldap` and `cyrus-sasl-lib`). The image now ships its own `curl` at `/usr/bin/curl`, built from the signed curl 8.23.0 release with `libcurl` linked in statically, so existing compose healthchecks and `docker exec … curl` probes keep working, and 28 RPMs leave the image. That `curl` still speaks HTTP and HTTPS through OpenSSL, but it no longer supports Kerberos/Negotiate authentication, LDAP, SCP/SFTP or HTTP/2. The image `HEALTHCHECK` now runs a new `artifact-keeper healthcheck [URL]` subcommand, which sends a plain `GET /livez` to the port in `BIND_ADDRESS` (or `PORT`), or to a given path or `http://` URL. It needs no configuration or database and exits 0 on a 2xx response.
