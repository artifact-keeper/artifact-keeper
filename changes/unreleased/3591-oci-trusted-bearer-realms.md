- **Remote OCI/Docker repositories can trust specific cross-origin Bearer token realms** (#3591). Since GHSA-78h6-3wp8-2542, a remote only sent its configured upstream credentials to a token `realm` on the upstream's own origin. Registries that issue tokens from another host, such as Docker Hub (`registry-1.docker.io` to `auth.docker.io`) and GitLab with a separate registry hostname, could therefore not authenticate: private images failed, and Docker Hub pulls fell back to anonymous rate limits. The new per-repository `oci_trusted_bearer_realms` list, accepted on create and update and returned on the repository API, names the exact `https://host[:port]` origins that may also receive the credentials. Entries are validated when written: https only, an origin with no path or userinfo, no wildcards, and SSRF-checked like upstream URLs. Nothing is trusted by default, including Docker Hub. **A credentialed Docker Hub remote (`upstream_url: https://registry-1.docker.io`) must add `"oci_trusted_bearer_realms": ["https://auth.docker.io"]` to pull private images or use its account rate limits.** An unlisted cross-origin realm still gets an anonymous token request. When the remote has credentials, the security warning now names the setting. Credentials sent to a trusted realm are logged at INFO on the `security` target. See `docs/oci-trusted-bearer-realms.md`.
