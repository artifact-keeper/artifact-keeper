- **A hosted package archive whose contents a scanner could not catalog at all is no longer graded 100 / A** (#4036). `parse_cyclonedx_catalog` deliberately distinguishes `None` ("this scanner reports no catalog") from `Some(vec![])` ("the engine ran and cataloged nothing"), but the hosted scan path discarded the signal: a package archive grype cannot read — a conda `.tar.bz2` is the canonical case — completed with zero findings and was scored as a complete clean, and with zero packages persisted its `inventory_status` stayed at the `'complete'` default. The hosted path now folds an empty catalog from a catalog-reporting scanner into a new `scan_completeness` value, `not_cataloged`, gated by `format_expects_catalog` so it applies only to package-archive artifacts (conda `.tar.bz2`/`.conda`, npm `.tgz`, PyPI sdist/wheel, `.gem`, `.crate`, `.nupkg`, `.jar`, `.deb`, `.rpm`) — a plain file in a generic repository legitimately catalogs nothing and keeps its grade, and a scanner that reports no catalog at all (`None`; the trivy family, OCI registry mode) never triggers it. The scan row still completes normally with its real counts and a persisted `scan_completeness_reason` naming the scanner, but `inventory_status` is marked `partial`, and `recalculate_score` floors the repository grade to F with a new persisted `repo_security_scores.has_uncataloged_scan` flag (mirroring the #2167 `has_failed_scan` gate, also exposed on the score API) until a superseding completed scan clears it. `not_cataloged` is deliberately distinct from `partial`: pin-downgraded and lockfile-unparseable scans still graded real content and remain gradeable.
