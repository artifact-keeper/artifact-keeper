- **MCP Registry repository format: host a private catalog of Model Context Protocol servers** (#5253). A Local or Staging `mcp` repository speaks the MCP registry API v0.1 (and `/v0`) at `/mcp/{repo}/`, so VS Code's MCP gallery (`chat.mcp.gallery.serviceUrl`), GitHub Copilot's private registry policy and `mcp-publisher` can use it in place of the public registry. server.json documents (schema 2025-12-11) are validated strictly, write-once per version, and listed, searched and paged with upstream's envelope; `PATCH .../status` deprecates or deletes a version.

  By default (`mcp_package_policy: own-repos`) every package a server runs must already be in one of this instance's repositories, mapped per `registryType` with `mcp_package_repos`: the publish resolves it in the database (nothing is fetched), pins the exact version or image digest, and every read serves the Artifact Keeper coordinates (`registryBaseUrl` for npm, PyPI, NuGet and Cargo; `host/repo/path:tag@sha256:...` for OCI). A package from anywhere else is refused with `422`, as are `:latest` and tagless images. A pinned OCI tag that later moves keeps serving the pinned digest and is audited as `MCP_PIN_DRIFT_DETECTED`. A server version whose server.json or pinned package is quarantined, refused by scan policy (or by the stored proxy-scan verdict of the Remote it was pulled through), younger than that Remote's age gate, or gone is left out of every listing, and an exact read answers the same `404` as an unknown name (the reason only for callers who hold the repository), because VS Code keeps a server enabled on any other refusal. `open` is an explicit opt-out that stores packages verbatim. Remote and Virtual MCP repositories are refused until a later release. See `docs/mcp-registry.md`.
