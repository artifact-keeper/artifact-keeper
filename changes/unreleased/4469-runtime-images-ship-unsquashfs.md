- **The runtime images now ship `unsquashfs`, which the Incus scanner needs to extract SquashFS rootfs images** (#4469). The scanner runs `unsquashfs` on both its local Trivy path and its scanner-adapter path, but neither `Dockerfile.backend` nor `Dockerfile.backend.alpine` installed it, so every SquashFS Incus image scanned by a published image failed at extraction. The Alpine image installs `squashfs-tools`. The UBI image builds `unsquashfs` from the pinned squashfs-tools 4.7.5 release (sha256-verified and built hardened), because the UBI 9 repositories do not carry squashfs-tools; its GPL-2.0 licence text and the exact source tarball it is built from ship under `/licenses/squashfs-tools/`, and the rootfs gains `libzstd`, which it links. The UBI build reads gzip, xz and zstd SquashFS images; LZO and LZ4 images extract only on the Alpine image, whose distro package has all five codecs (see `docs/incus-image-scanning.md`). Extraction as the image's non-root user can still exit non-zero on images that carry `security.*` xattrs or device nodes; that is tracked separately (#4470).
